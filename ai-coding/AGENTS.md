## 一、文件与目录

```

### 1.2 章节文件命名

```
chapters/<两位章号>-chapter.md
```

- 章号两位数字:`00`、`01` ... `15`
- 当前使用占位名 `NN-chapter.md`,**建议优化**为 `NN-章节标题.md`(参考 fde/workbuddy 风格)
- 标题用中文,长度建议 8-20 字
- 用半角连字符 `-` 连接章号与标题
- 标题末尾不加句号、不加书名号

**示例**:
- ✅ `01-生态四象限与五家垂直对比.md`
- ❌ `1-生态.md`(章号必须两位)
- ❌ `01-生态象限?.md`(不允许问号)

### 1.3 配图命名

```
figures/<原命名>.png
```

- 配图保留**原命名**(不强制重命名,以避免破坏引用)
- 现存两类命名:
  - `ai_coding_book_secXX_figYY.png` — 早期 sec 编号
  - `ai_coding_book_secXX_<主题>.png` — 主题命名
  - `secXX_<主题>.png` — 简化主题命名
- 优先 PNG(无损),允许 JPG、WebP
- 分辨率建议 2x,DPI 144

### 1.4 引用约定

**章节 md → 配图**(相对路径):

```markdown
![图说文字](../figures/ai_coding_book_sec01_fig01.png)
```

- 所有章节内 `![]()` 引用,必须用 `../figures/` 相对路径
- 引用文件名必须存在于 `figures/` 目录
- 引用前先 grep 确认文件存在

## 二、章节结构

每章固定结构(从第 1 章到第 16 章保持一致):

```markdown
# 第 N 章 章节标题

## 本章要点

- 要点 1
- 要点 2
- 要点 3

(开头 1-2 段:本章动机,200-400 字)

## 一级标题(3-5 个)

(正文 5000-8000 字,含 3-5 张配图、提示词示例、操作步骤)

## 小结

- 关键收获 1
- 关键收获 2
- 关键收获 3

## 下一章预告

(50-100 字)

## 完整提示词(本章可直接复制使用)

```text
[完整提示词,可直接复制]
```
```

### 2.1 字数控制

| 部分 | 字数 |
|---|---|
| 本章要点 | 100-200 字 |
| 开篇衔接 | 200-400 字 |
| 正文 | 5000-8000 字 |
| 小结 | 100-200 字 |
| 下一章预告 | 50-100 字 |
| 完整提示词 | 100-500 字 |
| **合计** | **6000-10000 字** |

### 2.2 章节引用

- 引用他人案例:脱敏后引用,标注来源
- 引用价格/版本:正文写"截至 XXXX 年 X 月,XX 版 XX 元/月"
- 引用源(200+ 条):见 `assets/research/` 12 篇 dimension 资料

## 三、文字风格

### 3.1 人称与语气

- **默认第二人称**(你、读者)
- 避免"我们认为"、"小编建议"等集体口吻
- 严肃但不刻板,允许有作者个人观点但要标注

### 3.2 术语处理

- **专业术语首次出现**:中文 + 英文 + 简释
  - 例:"工作目录(workspace,AI 可读取的本地文件夹)"
- 后续使用统一术语,不要混用同义词

### 3.3 段落与节奏

- 单段不超过 6 行
- 关键操作前用引导句
- 列表与正文交替使用

### 3.4 标点与排版

- 中文标点全角,英文标点半角
- 代码、命令、文件名:用反引号包裹

## 四、配图与表格

### 4.1 配图规范

- **类型**:UI 截图占 50%、示意图 30%、流程图 20%
- **图说**:`![图说文字,字数 15-30 字](../figures/xxx.png)`
- **图序**:每章独立编号 1.1, 1.2 ...

### 4.2 表格规范

- 三线表(无竖线,仅顶/底/表头分隔)
- 表头简短,左对齐

## 五、出版级质量基线

### 5.1 三审三校

| 环节 | 责任 | 检查项 |
|---|---|---|
| 一审(作者自查) | 作者 | 内容完整性、事实准确性、配图齐全 |
| 二审(同行评审) | 协作者 | 术语统一、风格一致、章节衔接 |
| 三审(主编终审) | 主编 | 出版级质量、读者预期、立场平衡 |
| 一校/二校/三校 | 编辑 | 错别字、标点、引用规范 |

### 5.2 风险内容

- **避免夸大宣传**:不写"AI 将取代 X"
- **避免绝对化用词**:不写"最好"、"唯一"、"完美"
- **数据须有来源**:用户量、价格、功能,均需注明出处与截至日期

## 六、给 AI 协作者的执行摘要

如果你是一个 AI agent,正在协助本项目:

1. **先读 [README.md](./README.md)** 了解项目当前状态
2. **再读 [chapters/](./chapters/)** 了解章节结构
3. **修改任何文件前** 确认文件路径与本规范一致
4. **创建新文件时** 严格遵循 1.2 / 1.3 的命名规范
5. **写新章节时** 必须包含 2.1 的全部结构
6. **不要直接覆盖已定稿内容**:如需修改,先备份到 `_archive/vN-章号-标题.md`,再改原文件
7. **图片引用** 必须用 `../figures/xxx.png` 相对路径
8. **遇到歧义**:回到本规范第 1-5 章;若仍无答案,向用户提问而不是猜测
