# 模型选型速查表(三问清单)

> 配套《AI Coding:人人都是程序员》第 1 章。可打印贴在墙上。
> 数据截至 2026-07-31,工具生态以 4—8 周为周期迭代,数据本身会过时,框架不会。

## 1. 三问决策树(回答 3 个问题,锁定候选)

```
本项目关键能力是否依赖单一海外模型?
├── 是 → 必须建立降级方案
│        → 智谱(双格式接口、20+ 工具兼容,迁移摩擦最小)
└── 否 → 继续 ↓

本项目的工作量是?
├── 重度长任务(数小时以上,反复读同一批材料) → Kimi(缓存命中不计额度)
├── 高频短任务(单次 < 10 分钟,简单整理) → MiniMax(入门价最低)
└── 介于两者 → 继续 ↓

本项目需要图片/语音等多模态?
├── 是 → MiniMax(全模态额度池) 或 Z Code
└── 否 → 继续 ↓

所用软件在 Kimi 白名单内?
├── 是 → 可放心选 Kimi
└── 否 → 选 MiniMax 或智谱
```

**局限说明**:本清单不含"项目所属行业有特定数据使用要求"等业务侧变量,后者需在选型前单独评估。

## 2. 五家厂商横评(2026-07-31)

| 维度 | Anthropic | OpenAI | 智谱 | Kimi | MiniMax |
|---|---|---|---|---|---|
| 模型档 | Sonnet / Opus 5/5.8 | GPT-5.5 / 5.5 Pro | GLM-5 / 5.2 | K2-Think / K2-Instruct | M3 / M2 |
| 软件形态 | Claude Code | Codex CLI | 兼容 20+ 工具 | 客户端最少,白名单管控最严 | 兼容主流工具 |
| 计费机制 | 积分制(高峰倍率更高) | Token 计量 + 缓存命中不计 | Token 额度池(全模态共享) | 同左 | 同左 |
| 适合场景 | 迁移成本最低的兼容派 | 长任务、成本最优 | 跑量任务、需多模态额度 | 重度长任务 | 短任务为主 |

## 3. 跑分阅读三条铁律

1. **三要素齐备才信**:对比对象 + 所用考题 + 统计口径。任一缺失,结论作废。
2. **厂商自报 ≠ 第三方分**:同一模型自家考场与第三方统一考场的分数可相差悬殊;读战报时确认"harness"是否一致。
3. **排行榜 ≠ 实际能力**:查评测机构、考题集、数据隔离机制;2026 年 4 月 arXiv 审计 Terminal-Bench 2.0 时,榜首 415/429 道题"偷看"了测试数据。

## 4. 选型红线清单

- [ ] 不为"第一名"头衔多付钱 — 跑分波动远大于模型代际
- [ ] 不押注单一海外模型 — 2026-06 Claude 停服 19 天是真实案例
- [ ] 缓存命中不计额的机制 — 优先用于重复读取同一批材料的场景
- [ ] 客户端白名单覆盖 — 必查,否则白名单外软件会被迫更换
- [ ] 选型前问"哪个会失效" — 每个推荐都应附"在什么情况下不适用"
