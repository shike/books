# 四杠杆自检速查表

> 配套《AI Coding:人人都是程序员》第 15 章。可打印贴在墙上。
> **核心论点**:AI 编程的产出 = 模型 + 周围工程结构(脚手架)。脚手架的差异稳定超过模型代际差异(arXiv 2605.23950)。
> 决定产出的不是模型单点能力,而是四根杠杆的组合。

## 1. 四杠杆框架

```
┌─────────────────────────────────────────────┐
│ 输入质量(模型看到什么)                       │
│   检索 ←─────────────────────────────────┐  │
│   上下文管理 ←───────────────────────┐    │  │
│                                      │    │  │
│ 执行结构(模型能做什么、怎么做)       │    │  │
│   工具设计 ←─────────────────────┐   │    │  │
│   子 Agent 架构 ←───────────┐    │   │    │  │
└──────────────────────────────┴────┴───┴────┴──┘
```

- **检索**:喂给模型的信息是否恰好相关(第 2/7/11/14 章)
- **上下文管理**:有限窗口里放什么、不放什么、何时清空(第 4/8 章)
- **工具设计**:工具接口如何定义、失败时如何重试、权限如何收口(第 3/5/6 章)
- **子 Agent 架构**:任务如何拆分、噪声如何隔离、结果如何蒸馏(第 6/9/10 章)

## 2. 20 条自检清单(四杠杆各 5 条)

每月给自己的项目过一次。能勾 15 条以上 = 超过九成配置;勾不到 10 条 = 先暂停研究换模型。

### 【检索】(决定"喂对")
- [ ] 新会话开工前,先告诉 Agent 去哪里找
- [ ] 项目里有机器可读的导航(AGENTS.md / 目录说明 / 索引)
- [ ] 外部数据按三件套分工:常识问内置、时事走搜索、私有走爬虫
- [ ] 检索回来的内容抽查过真实性
- [ ] 大库探索派给了探索子 Agent

### 【上下文管理】(决定"放准")
- [ ] 总章程文件 < 500 行(超出会被自动截断未读)
- [ ] 每个任务开工前清上下文
- [ ] 长任务有检查点/进度文件
- [ ] 跨会话经验有地方沉淀(知识库/Skill)
- [ ] 窗口占用常年飘红时,知道该删什么

### 【工具设计】(决定"能做")
- [ ] 危险操作(写库/发消息/付钱)有白名单或人工批准门
- [ ] 凭据不进对话、不进提示词
- [ ] 工具失败时有明确报错和重试策略
- [ ] 每个自动化流程先手动跑通过一遍
- [ ] 插件按需加载,不用的及时卸载

### 【子 Agent 架构】(决定"做好")
- [ ] 每个子 Agent 职责单一,description 里写清"什么时候用它"
- [ ] 评审/审计类子 Agent 只有读权限
- [ ] 子 Agent 返回的是蒸馏摘要(千字级,不是完整日志)
- [ ] 并行派子 Agent 的活,事先评估过 7× Token 代价值不值
- [ ] 拆子 Agent 是因为有隔离/并行/权限需求,不是因为"显得高级"

## 3. 症状 → 短板 定位

| 症状 | 短板在哪根杠杆 |
|---|---|
| "AI 老答非所问" | 检索 |
| "聊着聊着忘了规矩" | 上下文管理 |
| "不敢让 AI 碰真实系统" | 工具设计 |
| "主会话又乱又贵" | 子 Agent 架构 |

## 4. 改造顺序(三步走)

```
第一步:脚手架健康度自检
   ↓
第二步:看哪一栏勾得最少 → 那就是当前天花板
   ↓
第三步:按序改造
   1) 补规范层与执行习惯(想清楚、干好活)
   2) 上子 Agent(拆活)
   3) 调成本路由(省钱)
   4) 仍有差距 → 才是换模型的时候
```

**倒序警告**:路由优化省的是钱,规范层救的是方向,方向错了,省钱没有意义。

## 5. 总章程文件字数铁律

- AGENTS.md **不超过 500 行** — 超出主会话只读前段,后段成"装饰性存在"
- 超过部分拆到 `docs/*.md`,在 AGENTS.md 加链接,按需加载
- 现场案例:某项目 AGENTS.md 写到 2,000 行,AI 在 PR 中违反"commit 必须含 issue 编号"的规矩 — 加载 0%
