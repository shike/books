# 四类工程问题诊断速查表

> 配套《AI Coding:人人都是程序员》第 13 章。可打印贴在墙上。
> 关键信息没落在 AI 能读到的文件里 → 同一根因在不同侧面的表现 → 四类问题。

## 1. 四类问题总表

| # | 问题 | 早期信号 | 根本原因 | 解法 | 配套工具 |
|---|---|---|---|---|---|
| 1 | **代码质量下滑** | 同功能多版本、异常被吞、克隆量增 4 倍 | AI 优化目标"让程序跑起来" → 静默容错 > 显式失败 | 质量左移(测试先行 + CI 拦截 + 评审留痕) | 触发器:改完代码自动跑测试 |
| 2 | **上下文失效** | 长任务跑一半忘规矩、重复提示、窗口溢出 | 窗口有限 + 关键信息没入库 | 四类对策(截断/检索/隔离/蒸馏) | 探索子 Agent、AGENTS.md 章程 |
| 3 | **文档与代码不一致** | README 命令跑不通、SDK 升级未通知 | 文档与代码不在同一版本控制 | 文档即代码(从代码生成/同源校验) | docs/ 与 src/ 同 PR,CI 校验链接 |
| 4 | **架构渐进腐化** | 业务层 import 三方内部、循环依赖增 | 局部最优 ≠ 全局最优 | 架构约束强制化(依赖规则/CI 拦截) | 架构守护测试、依赖图检查 |

## 2. 症状 → 根因 决策树

```
最近一次"AI 干得不对"是?
├── "代码能跑但不敢改" / "对账丢单两周才发现"
│   → 问题 1 代码质量下滑
│   → 检查:异常处理是否"返回默认值"?函数是否有多个版本?
│
├── "聊着聊着就忘了前面的规矩" / "长任务跑一半答非所问"
│   → 问题 2 上下文失效
│   → 检查:AGENTS.md 存在?总章程 < 500 行?长任务有检查点?
│
├── "README 写的命令跑不通" / "文档说一套代码做一套"
│   → 问题 3 文档与代码不一致
│   → 检查:文档是否在仓库?是否与代码同 PR?CI 是否校验?
│
└── "业务层直接调三方 SDK 内部" / "改一处要动五处"
    → 问题 4 架构渐进腐化
    → 检查:是否有依赖规则?CI 是否拦截?
```

## 3. 20 条仓库健康自检清单

每月勾一次;15 条以上健康,10 条以下先暂停研究换模型。

### 【代码质量】
- [ ] 所有新代码提交前有测试覆盖
- [ ] CI 失败时禁止合入
- [ ] AI 提交附"修改→任务→验收标准"映射
- [ ] 异常处理不"返回空数组" / "容错吞掉"
- [ ] 重复代码增长率 < 5%/月(GitClear 类工具可监测)

### 【上下文】
- [ ] 仓库根有 AGENTS.md,内容 < 500 行
- [ ] 每个新会话开工前先读 AGENTS.md
- [ ] 长任务有进度文件 / 检查点
- [ ] 跨会话经验有地方沉淀(知识库/Skill)
- [ ] 窗口占用 > 80% 时知道该删什么

### 【文档】
- [ ] 文档与代码同仓库、同 PR
- [ ] 代码示例在 CI 中跑通
- [ ] SDK 升级有变更日志
- [ ] 外部链接季度巡检一次
- [ ] docs/ 目录结构与 src/ 一一对应

### 【架构】
- [ ] 依赖规则写在 lint/ci 中(单向依赖、禁止跨层)
- [ ] 第三方 SDK 封装在 adapter 层
- [ ] 循环依赖检测自动化
- [ ] 业务模块对外 API 有版本号
- [ ] 架构图与代码同步更新(每月)

## 4. 治理三层次序

1. **测试先行**:先写必失败的测试,再写最少代码让它通过
2. **质量左移**:测试与静态检查提前到保存/提交瞬时执行
3. **评审留痕**:每处修改映射回任务与验收标准,无法映射的禁止合入

**判断标准**:治理手段配完后,必须故意触发一次失败来证明它真的拦得住。不能只读配置。
