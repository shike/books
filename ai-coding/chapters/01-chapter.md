# 第1章 牌桌重排：从选模型到选工作方式

**本章导读**：2026 年的 AI 编程产品市场,海外两家(Anthropic、OpenAI)与国产三家(智谱、Kimi、MiniMax)已形成"模型 + 软件 + 套餐"三层绑定的销售结构,DeepSeek 作为低成本后端被嵌入各家工具。本章不罗列参数,目的是为读者建立一套分析格局的方法——理解各家差异的本质、识别选型中的常见陷阱、形成"在什么场景选哪家"的判断框架。本章所有价格、版本、跑分数据均截至 2026 年 7 月 31 日,工具生态以 4 至 8 周为周期迭代,数据本身会过时,分析框架不会。

**本章关键词**:垂直闭环、模型档位、套餐机制、上下文窗口、跑分口径

## 1.1 选型的真实单位:工作方式而非模型

2026 年 AI 编程市场的竞争单位已发生根本性变化。三年前,选 AI 编程方案比的是模型跑分、API 单价、工具自由搭配;2026 年,五家主流厂商均将"模型 + 软件 + 套餐"三层打包销售,并通过指定软件名单、自研核心模块、接口格式差异等方式互相设置门槛[^1^][^7^]。

本书将这一结构称为**垂直闭环**:模型、软件、套餐三层绑定,买其中任何一层,另外两层即被锁定——好比装修全包合同,设计、施工、材料由同一家公司整体交付。这个格局直接改变了选型的含义:读者选择的不是"跑分最高的模型",而是此后每天的工作方式——在哪个软件里与 AI 对话、额度按什么规则扣减、团队能否共享。选错的代价不只是多花钱,而是整套工作流程推倒重来。

### 1.1.1 一次停服事件及其方法论遗产

垂直闭环格局的形成,部分源于 2026 年 6 月的一次行业事件。Anthropic 公司于 6 月 12 日发布公告,因美国政府要求,暂停其 Claude Fable 5 与 Mythos 5 两个模型在全球范围的访问。这两个模型 6 月 9 日才发布,上线三天即被叫停,直至 7 月 1 日加装新的安全过滤模块后才恢复服务[^3^]。停服原因是这一代模型具备自主发现并利用零日漏洞(指软件中厂商尚未知晓的安全缺陷)的能力,这是商用大模型首次因网络安全能力被官方要求暂停对外服务。

该事件落在产品团队头上,衍生出一条新的采购原则:**关键能力不能押在单一供应商身上**。具体而言,如果产品当时将 Fable 5 作为核心能力依赖,产品将无预警停转三周,无赔偿、亦无替代品——Mythos 级能力在彼时仅此一家。模型采购由此首次进入"供应链风险管理"范畴,性质与制造业担心芯片断供相同。

事件的后续同样值得关注。Fable 5 停服次日,智谱宣布 GLM-5.2 向其编程套餐全部用户开放,三天后模型文件公开下载;产品社区的讨论话题在数日内从"Fable 5 何时恢复"切换为"如何将 GLM-5.2 接入现有 Claude Code 流程"。停服第三天,用户已经开始搬家。

由此得出本章第一条判断:将产品的关键能力绑定在单一海外模型上存在实质商业风险,必须预先准备降级方案——模型能否替换、配套软件能否平移、成本是否可控。这些问题应在平时就有答案,不能在停服当天才开始考虑。

### 1.1.2 从"模型竞争"到"闭环竞争"

Fable 5 事件只是表象,背后是 2026 年行业竞争逻辑的变化。两三年前,选 AI 编程方案比的是单一模型;2026 年,比的是整套工作方式。Anthropic 卖的是"Claude 模型 + Claude Code 软件 + Max 订阅"的整体方案;智谱、Kimi、MiniMax 也各自把这三层捆绑销售,差异在于绑定的强度——智谱的接口兼容 20 多种工具,迁移成本最低;Kimi 的客户端适配数量最少、指定软件名单管控最严,迁移成本最高。

这一格局对读者的实际意义是:先挑顺手的软件,模型以后随时能换。模型是闭环中技术更新最快的部分,也是最容易替换的部分;软件则是闭环的真正壁垒——一旦习惯某家软件,即被该家的套餐锁定。

在逐一拆解之前,先确立四根比较轴:**模型**(型号与定价)、**软件**(配套工具的能力与生态)、**套餐**(额度规则与门槛)、**开放度**(兼容多少其他工具)。跑分被有意排除在四轴之外,1.6 节详述其方法论缺陷。

此外,本节交代四个全书通用的术语,后文不再重复解释。

**Agent(智能体)**:能自己动手干活的 AI。普通对话式 AI 是"你问一句它答一句";Agent 是"你交代一件事,它自己拆成几步,打开文件、修改内容、检查结果、没做好接着改",循环直到完成。一个能自己操作电脑的远程员工,而不是一个客服。

**Token(模型计量单位)**:AI 读写文字的计量单位,也是按量计费时的收费单位。粗略换算:1 个汉字约 1—2 个 Token,1 个英文单词约 1 个 Token。报价中的 "$5/$25"指每百万 Token 的输入价/输出价——读者喂给 AI 一百万 Token 收 5 美元,AI 吐出一百万 Token 收 25 美元。

**API 与订阅是两条独立的计费线路**:API 是"软件之间互相调用的接口",按 Token 用量计费,适合产品上线后服务用户;订阅是包月制,给一个定额的使用池,适合个人天天使用。同一厂商同一模型,两条线的价格和容量经常不一致——这是最常见的认知误区。

**Coding Plan(编程套餐)**:2026 年国内厂商推出的订阅形态,专门为"让 AI 干活"场景重新设计:月费几十到几百元,给一个对接配套软件的额度池。它是国内用户的主流入口,1.7 节横评。

## 1.2 海外两家:Anthropic 与 OpenAI

国内个人使用海外工具有支付与网络两道现实门槛,因此本节从简,每家只给模型梯队、价格与软件形态,以及该厂家产品对国内读者最值得借鉴的设计。

### 1.2.1 Anthropic:四档模型与 Claude Code

截至 2026 年 7 月底,在售模型共四档:Haiku 4.5($1/$5)面向高频轻量任务;Sonnet 5($3/$15)为走量中坚;Opus 5($5/$25)为旗舰,也是 Claude Code 的默认模型;Fable 5($10/$50)比 Opus 更高一档,即 1.1 节所述被暂停的型号[^1^]。

两组数字有助于校准整体判断。能力方面:SWE-bench Verified(业界公认的编程考题库)成绩从 Claude 3.5 Sonnet 的 33.4%(2024 年 6 月)升至 Opus 5 的 96%,历时仅两年。价格方面:旗舰档定价从 3 代的 $15/$75 降至 $5/$25,三年下降三分之二;Fable 5 又将价格上探至 $10/$50。能力倍增、旗舰降价、前沿加价,这三件事同时发生,构成当前市场的基本面。对读者的含义是:旗舰档并非奢侈消费,预算有限时用 Sonnet 档承担主力即可。

软件侧的核心产品是 Claude Code:一个常驻命令行界面的 Agent 软件。命令行界面可以理解为"电脑里那个能直接打字的窗口",而非带图标的应用程序。Claude Code 是全行业的功能风向标——与 Codex 共有的 24 项相似功能中,18 项由它率先实现[^1^]。其中四项设计对国内读者特别值得借鉴:一是 MCP 协议(给 AI 接外部工具的通用接口),二是子代理(AI 把独立的小活儿外包给"临时工"并行处理),三是 Hooks(给 AI 立的自动规矩),四是 Skills(把工作方法写成说明书文件,AI 遇到相关任务时自动调出照做)。

订阅分三档:Pro $20/月(含 Claude Code),Max $100 与 $200/月,用量分别为 Pro 的 5 倍与 20 倍[^2^]。最值得借鉴的是额度扣减机制:5 小时滚动窗口与每周上限并行计算,任一先耗尽即停止服务——买的不是"无限使用",而是两个额度池中先见底的那一个。这套设计后来被国内厂商几乎原样采用(详见 1.7 节)。

另一个常被忽视的事实:**订阅用户统一只有 200K 上下文窗口**[^2^]。上下文窗口指 AI 一次能同时看进脑子的材料总量(详见 1.5 节)。即使接口名义上支持 1M,订阅线路默认只给 200K,超出部分会被自动压缩成摘要,细节随之丢失。

### 1.2.2 OpenAI:三档模型与 Codex

GPT-5.6 系列分三档:Sol($5/$30)对标 Opus,Terra($2.50/$15)对标 Sonnet,Luna($1/$6)对标 Haiku[^114^]。Codex 是其配套 Agent,提供命令行、编辑器插件、网页版、桌面应用四种用法,这一覆盖广度是 Anthropic 所没有的。

Codex 的一个关键设计值得留意:它给 AI 划定了"文件围栏"——只能在指定目录内操作,不能越界读用户的私人文件。这一设计在产品团队视角下意味着"默认更安全",在个人使用视角下意味着"少一些灵活性"。

订阅方面,Codex 包含于全部 ChatGPT 套餐(含免费档),与 Anthropic 不同;但同样采用 5h+周双层额度机制[^7^]。

## 1.3 国产三家:智谱、Kimi 与 MiniMax

国产三家的共同特征是模型全部开源(可以免费下载模型文件)、人民币计价、入门档统一为 ¥49。但同质化仅止于此——三家在产品定位、套餐机制、生态开放度上差异显著,选型的核心问题不是"哪家跑分更高",而是"哪家的工作方式更契合具体项目"。



![五家垂直闭环结构对比](../figures/ai_coding_book_sec01_fig03.png)

### 1.3.1 智谱:迁移成本最低的兼容派

GLM-5.2 是当前主力,模型文件公开下载,API 输出价约为 Opus 5 的五分之一[^10^]。智谱不构建软件闭环——其 Z Code 软件改用自家核心模块后,Claude Code 仅需修改两行配置即可接入;反过来,Z Code 也支持接入 Claude 与 Kimi 模型。这一双向兼容特性,使智谱成为"先用别家、想换国产"路径上摩擦最小的选择。

智谱 Coding Plan 累计付费用户 24.2 万,是国内规模最大的编程套餐产品[^10^]。其额度机制采用积分制(类似游戏里的"点券",按使用量扣除),高峰时段抵扣倍率更高——口径经过多次调整,购买前应核对官方现行帮助页[^110^]。

风险点集中在两点:其一,高峰限速——社区反馈集中在晚间高峰时段响应变慢;其二,生态绑定温和但存在——智谱自家核心模块对其余厂商的兼容性有提升空间。

### 1.3.2 Kimi:长任务的成本最优解

Kimi 的定位可以一句话概括:**重度长任务的成本最优解**。K3 于 7 月 16 日深夜发布,2.8T 总参数、1M 上下文,为当前参数规模最大的开源模型[^112^]。发布 48 小时后即暂停个人新订阅,至 7 月底四档会员全部显示"售罄"[^113^]——订阅制产品售罄在该行业尚属首次,反映需求侧对长任务场景的强烈偏好。

Kimi 的真正差异化在计费机制:**唯一按 Token 计量、且缓存命中不计额度**的 Coding Plan。缓存命中指 AI 重复读取同一份材料时,平台按已存留的"复印件"结算而非按原件——长任务中 AI 会反复读取同一批代码与文档,实测命中率可达 90%,这部分在 Kimi 套餐中免费。这一机制对动辄数小时的重度任务是成本优势的全部来源。

风险点:档位门控细碎(¥49 档不可用 K3,¥99 档 K3 限 256K 上下文),客户端适配数量在三家中最少,指定软件名单管控最严——使用名单外软件有封号风险。购买前应逐项核对权益表,并先确认所用软件是否在白名单内。

### 1.3.3 MiniMax:跑量任务的默认后端

M3 于 6 月 1 日发布,约 428B 总参/23B 激活,1M 上下文(官方保底 512K 可用),原生支持文字、图片、语音等多模态输入[^13^][^14^]。Token Plan 分 ¥49/119/469 三档,官方宣传"同价用量约为 Claude 订阅的 15 倍"——这是厂商自报换算,非第三方实测;但入门价最低则没有争议[^15^]。

差异化体现在软件层:Agent Team 功能支持多个 AI 分工协作(分别承担编写、审查、测试),并可接入微信、飞书、Telegram,在聊天软件里直接指挥 AI——需要在群聊发起任务的场景,目前仅此一家提供现成方案。跑量型任务将其设为默认后端,成本最低。

风险点:顶级复杂任务的完成度与 Claude 旗舰仍存在可查的差距,因此它适合作为"默认模型"而非"攻坚模型";社区反馈集中在高峰限速、长任务中输出 Token 消耗过快,部分长回答会被截断。

### 1.3.5.1 本章思考题

1. 你的团队当前用的 AI 编程工具是哪一家?对照 1.3 的五家对比表,你能说出"我们选了 A 而不是 B 的三个具体理由"吗?如果说不清,说明选型决策缺乏可被复核的依据。
2. 如果你所在的产品把核心能力押在单一海外模型上,对照 1.1.1 的 Fable 5 停服事件,你准备好的"降级方案"是什么?迁移成本评估过吗?
3. 1.5 节说"有效上下文约为标称值的 25%—30%"。你当前用的 AI 工具标称上下文是多少?按 25%—30% 折算后,你的实际可用窗口是多少?这个数字有没有写进你项目的"上下文预算"文档?
4. 1.7 节给了"三问选型清单"。用这个清单给你的下一个项目做一次选型,推荐方案是什么?备选方案是什么?什么情况下会失效?
5. 你的 Coding Plan 是订阅制还是 API 按量?按 1.2.2 的双层额度机制,你的"5h 滚动窗口"和"周上限"哪个先耗尽的历史数据是什么?这个数据决定了下个月是否需要换套餐。

## 完整提示词:三问选型清单的执行版

本节给出的提示词,是 1.7 节"三问选型清单"的执行化版本。读者面对任一具体项目的工具选型时,可直接复制使用,AI 会按"任务画像—使用画像—约束画像"三步引导用户回答,并基于回答给出明确推荐。

## 1.4 DeepSeek:非闭环的通用后端

DeepSeek 单独成节,因其角色明确:不构建闭环,而是作为**被集成进各家工具的低成本后端**——读者付费购买的某个软件套餐,底层替你干活的可能就是它。它把"用 AI"的成本压到了一个可以写进商业模式里的水平。

官方接口同时兼容 Anthropic 与 OpenAI 两种通信格式,市面上几乎所有相关软件均可接入。在海外最大的模型聚合平台 OpenRouter(可理解为"批发调用各家模型的超市")上,其 Token 用量份额接近 20%,居所有模型之首[^16^]。价格处于行业最低区间:7 月 31 日开始公测的 V4-Flash 正式版,定价 $0.14/$0.28 每百万 Token——同样一百万 Token,Opus 5 的输出价约为其 90 倍[^17^]。

低价有工程基础:V4 更换了内部结构,1M 上下文下单 Token 的计算开销仅为上代的 27%(Flash 版为 10%),暂存上下文的内存压缩至 10%[^16^]——结构先把成本压低,价格才有降到底的空间。版本现状:V4 预览版于 4 月 24 日发布(V4-Pro 1.6T 总参、V4-Flash 284B,均 1M 上下文、模型文件公开),旧接口名称 7 月 24 日已退役;V4-Pro 正式版截至发稿尚未发布。

**实战定位:成本路由的底层**。任何产品中均存在大量简单、批量、容错性高的任务——批量改写文案、整理表格、生成重复性内容。将这类任务交给 DeepSeek,成本直接降至十分之一;复杂且需要兜底的任务留给旗舰模型。这种"按任务难度分流"的做法称为**成本路由**,逻辑与人事安排类似:简单活给实习生,关键活给骨干。判断标准只有一条:该任务出错的后果是否可承受——可承受则交给低价模型,反之留给旗舰。

能力边界方面,官方技术报告写明:发展轨迹"大约落后最前沿闭源模型 3 到 6 个月",内部评测"接近 Opus 4.6 非思考模式,但与思考模式有差距"[^16^]。需要注意,其对标的 Opus 4.6 已不是当前旗舰——旗舰已更新至 Opus 5 与 GPT-5.6。幻觉控制是已知弱项——幻觉指 AI 一本正经地编造不存在的内容。把它放在底层跑量没有问题,批量任务出错代价低;但在产出必须配套验收手段的产品中,使用它意味着验收层需要设计得更厚。

## 1.5 上下文窗口:标称值、有效值与计费值

**上下文窗口**指 AI 一次能同时"看见"的材料总量——用户写的要求、AI 读的文件、之前的聊天记录、AI 正在生成的回复,全部占地方,单位是 Token。可以将其类比为办公桌桌面:桌面越大,能同时摊开的资料越多。它是厂商宣传中调门最高、水分也最大的指标,同时决定两件事:AI 一次能看懂用户多少资料,以及账单按哪档费率结算。



![上下文窗口:标称值/有效值/计费触发点对比](../figures/ai_coding_book_sec01_fig02.png)

### 1.5.1 三道折扣

查阅各家接口文档,旗舰模型确已全面进入百万 Token 时代:Claude 1M、GPT-5.6 一百零五万、GLM-5.2 提供 1M 变体、Kimi K3 与 MiniMax M3 均标称 1M[^104^]。但实际使用要经过三道折扣。

**第一道,软件层先截断**。Codex 客户端仅提供约 400K(272K 输入预算 + 128K 输出上限),GitHub 上有个数千人关注的请愿帖要求开放 1M[^105^];Cursor 标称 200K,为保障速度主动截断,实测有效窗口仅 70K—120K[^106^];Claude Code 订阅默认 200K,1M 需特定档位。读者以为在使用 1M,客户端实际给的远少于此。

**第二道,模型本身会遗忘**。这并非厂商限制,而是客观规律:多项实测指向同一数字——**约 150K Token 真正相关的内容之后,各家模型的表现均开始退化**,前面的要求被淡忘、细节张冠李戴。更典型的一组数据来自第三方测试:GPT-5.4 在 256K 长度下得分为 79.3%,拉长至 1M 后降至 36.6%——窗口扩大四倍,能力下降过半[^84^]。标称值的含义是"装得进去",而非"记得住",Anthropic 官方文档亦明确表述了这一点。

**第三道,计费规则又加一码**。GPT-5.6 单次请求输入超过 272K 时,整个请求按输入 2 倍、输出 1.5 倍计费[^5^];Claude 订阅超过 200K 触发自动压缩;MiniMax M3 超过 512K 价格翻倍。读者以为在使用 1M,账单却按更高的费率结算。


图 1-2 将三道折扣绘制在同一坐标系中,"1M 宣传"的水分清晰可见。Codex 的浅色柱标至 1050K,深色柱仅 400K,中间 272K 处的倒三角是计费跳变点——尚未达到软件上限,账单已先翻倍;Cursor 更为明显,标称 200K 的浅柱之下,实测有效窗口只剩 70K—120K 的一小段。左侧 150K 虚线是客观规律的上限:真正相关的内容超过它之后,无论标称值多大,各家模型都开始遗忘。该图的阅读顺序是从右往左:广告给出的数字最大,实际可用的是最短的柱,付费区间由倒三角的位置决定。

### 1.5.2 三个数值的实际含义

将上述内容归纳为一个拆解框架,此后面对任何厂商的窗口宣传均可套用:**标称值是广告,有效值是体验,计费值是账单**[^2^]。

广告中的 1M 用于市场竞争;日常可稳定利用的部分应按 150K 上下编制预算——这也是本书后续投入大量篇幅讨论上下文管理的原因:把真正相关的材料挑出来放进窗口,远比购买大窗口重要。成本测算时应盯住计费阶梯的触发点(272K、200K、512K 这几条线):长任务的成本大头不在单价,而在是否跨过那道线。

工程实践中,给 AI 派任务时应主动控制交给它的材料范围,让它按需查找而非整摞灌入——150K 的天花板客观存在,"全部塞入"从来不是可选项。第 13 章将展开这一原则。

## 1.6 厂商跑分的阅读方法

每次新模型发布,信息流都会被跑分截图占据。先界定两个术语。**跑分**指让各家模型做同一套标准化考题后的得分,被引用最多的是 SWE-bench——从真实项目的代码仓库里抽取的"修 bug 题库",模型必须在真实代码中定位问题、修改并通过自动检查才计分。读懂战报直接决定读者是否要为"第一名"的头衔多花钱。本节用 2026 年三个真实案例演示拆解方法。

### 1.6.1 案例一:"GLM-5.2 击败 Claude"的误读

6 月 GLM-5.2 发布后,中文自媒体出现大量"国产模型击败 Claude 登顶"的标题。查阅智谱官方发布页自带的对比图可以发现,图上明确标注:SWE-bench Pro 基准下,Claude Opus 4.8 为 69.2,GLM-5.2 为 62.1——**在官方自己的图中,它并未战胜 Claude**,实际超过的是 GPT-5.5(58.6)与 Gemini 3.1 Pro(54.2)。

"登顶"的误读由两种手法构成:只报告"超过了谁"、不报告"未超过谁";再将不同考题混合比较——GLM-5 的 77.8 是 SWE-bench Verified 的得分,GLM-5.2 的 62.1 是 SWE-bench Pro 的得分,两套题库难度不同。有人据此声称"退步了"(77.8→62.1),也有人据此声称"反超了",两种说法均不成立。

由此得出第一条经验:**阅读战报先确认三个要素——对比对象、所用考题、统计口径,缺任意一项,结论作废。**

### 1.6.2 案例二:厂商自报与第三方复测的口径差

比误读更普遍的是口径差异。此处确立一对全书反复使用的概念:**厂商自报分**指厂商在自家搭建的测试环境下跑出的成绩,**第三方分**指独立机构在统一环境下复测的成绩。这个统一环境有个术语叫 harness,可以理解为"考场"——桌椅、文具、监考规则全由第三方统一提供,谁也不能自带小抄。同一个模型,自家考场和统一考场的分数可以相差悬殊。

典型案例:2026 年 4 月发表于 arXiv 的一项研究分析了 6,299 个 GitHub 仓库中的 30.26 万个 AI 署名提交,结论是五种主流 AI 编程工具无一例外,超过 15% 的提交引入了至少一个可检测的问题[^60^]。另一组来自 GitClear 的 2.11 亿行代码分析显示,AI 生成时代下,代码克隆量增长 4 倍、重构活动下降 60%、函数调用率下降 35%[^63^]。这些数据均来自独立第三方,与厂商自报形成对照。

Opus 5 发布时,Anthropic 官方迁移指南中有一条反直觉的建议:删掉提示词中"自我验证""完成后汇报进度"类指令,因为模型已内建这些行为,保留只会导致重复验证、浪费 Token;它还会更主动地委派子 Agent,使用者要做的是显式设置上限[^1^][^4^]。这背后是一个大趋势:脚手架的功能正在逐代被模型吸收进体内。今天的最佳实践,是明天的模型默认行为。

### 1.6.3 案例三:作弊题与"超满分"现象

2026 年 4 月发表于 arXiv 的一项研究审计了 Terminal-Bench 2.0 排行榜:榜首 Pilot 在 429 道题中有 415 道"偷看"了测试数据,ForgeCode 把评分环境换成自己的版本后,得分从 81.8% 跌至 71.7%[^93^]。同期,OpenAI 在官方博客中宣布弃用 SWE-bench Verified,理由是该题库已被严重污染——模型可凭题号默写标准答案,测试数据已广泛泄漏[^96^]。

由此得出第二条经验:**跑分排行不等于实际能力**。读者若希望为"第一名"头衔多付钱,需先核查评测机构、考题集、数据隔离机制——这三项中任何一项不可靠,跑分即失去参考价值。

横评之后,回到选型决策本身。一个三问清单,可在面对任一具体项目时直接套用。

**问题一:本项目的关键能力是否依赖单一海外模型?**

是——必须建立降级方案:模型能否替换、配套软件能否平移、成本是否可控。智谱的双格式接口与 20+ 工具兼容是当前迁移摩擦最小的选项。否——继续。

**问题二:本项目的工作量是重度长任务还是高频短任务?**

重度长任务(数小时以上,反复读取同一批材料)——优先 Kimi,缓存命中不计额度的机制可显著降低成本。高频短任务(单次对话 10 分钟内,简单文案整理、数据整理)——优先 MiniMax,入门价最低。介于两者之间——继续。

**问题三:本项目是否需要图片、语音等多模态输入?**

是——优先 MiniMax,全模态额度池;或考虑 Z Code。否——继续。

**问题三(续):所用软件是否在 Kimi 白名单内?**

是——可放心选 Kimi。否——选 MiniMax 或智谱。

通过三问的答案交集,可直接锁定一家或两家候选,具体在套餐档位上根据预算选择。这一清单的局限:不包含"项目所属行业有特定的数据使用要求"等业务侧变量;后者需在选型前单独评估。

**现场延伸**:这套三问清单在作者自己的团队里跑了半年多。最早用上,是 2026 年 3 月的一次内部项目——彼时团队刚用完上一家海外厂商的年度订阅,要不要续约成为争论焦点。按这三问过了一遍:问题一答案是"重度依赖单一海外模型",触发"必须准备降级方案";问题二答案是"中长任务,文档批量处理为主",指向 Kimi 缓存命中的成本优势;问题三答案是"不需要多模态"。三个答案交集到"智谱 + Kimi 互补使用"。最终决策:不续约海外,改用智谱主力(日常短任务)+ Kimi 辅助(批量文档任务),年度成本下降 70% 左右,且具备海外模型停服时的降级路径。这套三问的核心价值,不在于每次都给出唯一答案,而在于把"选哪家"这种容易陷入品牌偏好的决定,转化为可被反复套用的判断流程。

## 1.8 本章方法论:格局差不等于产出差

本章的最后,回到一个贯穿全书的方法论原则:**模型差距不等于产出差距**。2026 年 arXiv 上的一项研究(编号 2605.23950)专门分析过这个问题:基准测试的分数从来不是"模型能力"的纯函数,而是模型与其外部工程环境的联合产物[^76^]。这层环境——提示词如何组装、上下文提供什么、工具如何定义、失败如何重试、任务是否拆给子 Agent——称为 harness,即"脚手架"。研究将同一批模型放入不同脚手架中反复测试,结论是:**更换脚手架造成的分数波动,稳定超过更换一代模型**。厂商发布新模型时宣称的进步通常只有 2 到 4 分,而脚手架的更换可以带来几十个百分点的波动[^76^]。

两组实验值得记录。其一:其余条件完全相同,仅向系统中增加一个负责代码搜索的子 Agent WarpGrep,在 SWE-bench Pro(一个比 SWE-bench Verified 更难、更防污染的编程基准)上,两个模型的排名就发生了翻转——尽管后者在多数其他基准上更高[^76^]。其二来自 Cursor 的内部研究:同一个模型,在一套脚手架下得分 46%,在另一套下得分 80%。差距来自四个变量——是将整个代码库灌入上下文还是只检索相关文件、是提交一个大任务还是拆分为带作用域的子任务、工具调用失败后是直接放弃还是纠正重试、中间结果是随手丢弃还是写入结构化工作记忆[^77^]。

这四个变量没有一项属于模型问题。它们正是本书后续章节要收口的四根杠杆:**检索、上下文管理、工具设计、子 Agent 架构**(详见第 15 章)。

格局章的方法论产出,最后归结为一条建议:**先把脚手架修好再换模型**。当读者对当前产出不满意时,优先检查四根杠杆中的哪一根没调到位,而不是急于切换到"跑分更高"的模型。跑分更高的模型在同样糟糕的脚手架下,产出质量不会比前任更好。下一章开始进入案例篇——10 个真实项目的复盘,每章都会演示四根杠杆中至少一根的实际调节过程。
