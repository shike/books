# 反馈入口 / Feedback

> 电子书与印刷书最大的不同:**作者能在几天内收到反馈并修正**。
> 本文档是本书**唯一权威反馈入口说明**,所有渠道在此集中登记,避免读者到处找。

---

## 首选:GitHub Issues(最推荐)

**仓库**:`https://github.com/shike/books`(顶层仓库,`fde/` 子目录)

**适合**:
- 🐛 错字、引用失效、案例描述不准等具体问题
- 💡 章节补充建议、新增行业案例(法律 / 教育 / 政务等)
- 🤔 对方法论结论的质疑或反对(欢迎,我可能在错)
- 📦 配套数字仓库(`assets/`)中的资源缺失 / 失效

**为什么首选**:
- 公开透明,所有读者都能看到问题与修复
- 自动追踪进度(Open / Closed),不会丢
- 修复后会自动出现在 PR 中,易于追溯
- GitHub Issues 关闭时会触发邮件通知

**Issue 模板**(4 种,提交时会自动选择):
1. **🐛 Bug Report** — 错字 / 引用失效 / 事实错误
2. **💡 Feature Request** — 章节补充 / 新案例 / 新方法
3. **🤔 Question / Discussion** — 方法论讨论 / 不同意结论 / FDE 一线经验分享
4. **📖 Doc Improvement** — 文档 / 注释 / 配套资源

## 次选:电子邮件(紧急 / 私密)

**邮箱**:`shike@dropleap.cn`

- 不希望公开的反馈(比如发现某段引用涉及具体客户)
- 媒体 / 出版社 / 平台对接 / 行业培训合作

**响应时间**:工作日 48 小时内,周末顺延。

## 反馈处理流程

```
读者提交反馈
  ↓
作者分类(PATCH / MINOR / MAJOR)
  ↓
记录到 promotion/corrections.md(可公开的错误与未决项)
  ↓
PATCH:72 小时内修复 → 立即推 GitHub + 24 小时内推 KDP / 微信 / 豆瓣
MINOR:本月内修复 → 进入下个 MINOR 版本
MAJOR:进入 backlog → 在下个 MAJOR 版本讨论
  ↓
CHANGELOG.md 记录本次更新
  ↓
通知订阅者(Watch 仓库 / 公众号"电子书架"栏目)
```

## 行业案例共建(特别征集)

本书的 7 大行业案例(医疗 / 金融 / 制造 / 政务 / 教育 / 法律 / 特殊)反向受限于"作者拿到的真实项目"。

如果你在某一行业深耕,愿意分享你的 FDE 实战故事(脱敏后),欢迎提 Issue 标注 `case-contribution`。

**共建方式**:
- 📝 提供行业背景 + 你踩过的坑(不署名,仅行业 + 角色)
- 📝 提供 1 套判断框架(你总结出来的)
- 📝 提供 1 份脱敏后的现场还原(2000-5000 字)

**回报**:
- 在书中"读者贡献案例"专章署你笔名(或匿名)
- 获赠全套电子版(含 KDP / Apple Books 任选)
- 受邀加入 FDE 同行闭门交流群

## 不要做这些事

❌ **不要在豆瓣 / 微信读书评论区反馈技术问题** — 平台侧通知链路太慢
❌ **不要在 Twitter / X 私信反馈** — 我不一定看得到,且容易丢
❌ **不要在豆瓣短评写勘误** — 短评不是反馈渠道
❌ **不要在公众号文章留言** — 留言 48 小时后无法回复

## 贡献与共建

欢迎以下类型的 PR(在 GitHub 仓库发起):
- 📝 直接修改错字 / 引用(简单 PR,无需讨论)
- 📝 补充行业案例(放在 `assets/cases/` 下,需脱敏处理)
- 📝 补充 FDE 实战框架(放在 `assets/frameworks/` 下)
- 📝 翻译英文版(放在 `assets/translations/`,目前英文版未启动)

**版权说明**:所有贡献默认以 CC BY-NC-SA 4.0 发布,与本书主体一致。
