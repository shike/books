# 附录

## A. 工具速查表

### 按场景决策

| 你在做什么 | 需要什么 | 建议方向 | 不用这个方向的条件 |
|------------|----------|----------|-------------------|
| 调用大模型 API | 生成/理解文本 | 按数据合规和延迟需求选厂商 | 数据不能出内网 → 排除 |
| 自部署模型 | 数据不出内网 | vLLM + 开源模型（Llama、Qwen、DeepSeek） | 团队无 GPU 运维能力 → 排除 |
| 搭 RAG | 知识检索增强 | 先选分块策略，再选向量库。轻量 pgvector，规模大 Pinecone/Milvus | 文档不适合 RAG → 先做文档治理 |
| 语义搜索 | Embedding | text-embedding-3-large（API）或 bge-large（开源），先测 precision@5 | — |
| 重排序 | Reranker | Cohere Rerank（API）或 bge-reranker（开源） | 候选集很小（<10 条）→ 可跳过 |
| Agent 框架 | 多步推理+工具调用 | 验证概念用 LangChain/LlamaIndex，生产考虑自建轻量编排 | 不需要 Agent → 用流程式方案 |
| 结构化抽取 | 从文本提取字段 | Instructor（基于 Pydantic 的约束生成） | 字段定义不清晰 → 先理清定义 |
| Prompt 管理 | 版本/测试/评估 | Git + 手写测试脚本。不需要专门工具除非 50+ Prompt | — |
| LLM 评估 | LLM-as-Judge | 用不同家族模型评估，人工抽评校准 | 自评 → 永远不要 |
| 监控 | 延迟+成本+质量 | 延迟/成本/错误率用常规 APM，输出质量需单独评估管线 | — |
| 数据标注 | 训练/评估数据 | 小规模内部+标注规范，大规模专业平台 | — |

### 选型不取决于"哪个最好"

取决于：
- 数据能出内网吗？不能 → 排除所有外部 API
- 团队有 GPU 运维能力吗？没有 → 排除自部署
- 调用量多大？日均百万+ → API 成本可能超自部署
- 延迟要求？毫秒级 → 排除大模型 API，考虑轻量模型或规则

## B. 故障排查决策树

### 标准排查路径

```
用户报告 / 监控发现异常
        │
        ▼
┌──────────────────┐
│ 1. 症状界定       │
│ 什么时间开始？     │
│ 影响范围？         │
│ 什么场景？         │
│ 有没有对应变更？   │
└──────┬───────────┘
       │
       ▼
┌──────────────────┐
│ 2. 看输出          │
│ 抽 20 条出问题的   │
│ 输出，人工读       │
│ 具体哪里不对？     │
│ 从何时开始不对？   │
└──────┬───────────┘
       │
       ▼
┌──────────────────┐
│ 3. 看输入和上下文  │
│ 模型收到了什么？   │
│ RAG 检索对不对？   │
│ Prompt 被改过吗？  │
│ 上游数据变了吗？   │
└──────┬───────────┘
       │
       ▼
┌──────────────────┐
│ 4. 看外部依赖      │
│ API 版本升级了？   │
│ 数据库变更了？     │
│ 第三方服务变了？   │
└──────┬───────────┘
       │
       ▼
┌──────────────────┐
│ 5. 最后看模型      │
│ 模型版本换了？     │
│ 参数被改了？       │
│ 温度/采样策略？    │
└──────────────────┘
```

大多数问题在步骤 3 或 4 找到根因。如果每一步都排除了才到步骤 5。不要跳步——跳过第三层直接调模型参数是行业里最普遍的排障错误。

### 常见症状 → 优先排查方向

| 症状 | 第一反应排查 |
|------|-------------|
| 回复变长/变啰嗦 | Prompt 约束、模型版本升级、温度参数 |
| 正确率突然下降 | 数据源变更、知识库过期、上游字段变化 |
| 特定场景表现差 | 该场景训练/测试数据覆盖不足、分块策略不适配 |
| 回复格式不对 | Prompt 输出格式约束不够具体、模型版本行为变化 |
| 延迟飙升 | API 限流、网络变更、调用链新增步骤 |
| 幻觉增多 | RAG 检索质量下降、知识库有矛盾信息、模型温度过高 |
| 用户反馈恶化但离线正常 | 评估集过时、评估维度缺失、用户分布和生产分布偏差 |
| 回复风格不稳定 | 温度参数过高、模型版本交替、Prompt 中风格约束被其他指令覆盖 |

## D. 推荐阅读

### FDE 思维基础

- *The Field Guide to Understanding Human Error* — Sidney Dekker。教你从"谁犯错了"转向"系统为什么允许这个错误发生"。不是 AI 书。是所有工程领域关于"如何理解失败"的经典。
- *Thinking in Systems* — Donella Meadows。系统思维入门。帮助你看到"问题不是孤立的"和"今天的方案可能制造明天的问题"。

### AI 工程实践

- Anthropic 的 Prompt Engineering Guide 和 Cookbook。不是理论——是写 Prompt 的实际方法论，包含大量对比案例。
- OpenAI 的 Evals 开源框架。看评估框架在工程上怎么实现——把你的评估集变成可运行的测试。
- Lilian Weng 的博客。Agent 系统设计和 RAG 模式的深度技术分析。每一篇都值得精读。

### 工程判断力

- *The Pragmatic Programmer* — David Thomas, Andrew Hunt。二十年前经典，讲的不是 AI，但"够好就行"、"不要过度设计"、"简单优于复杂"全在里头。FDE 的工程圣经。
- *Staff Engineer* — Will Larson。从高级工程师到"影响组织"的角色转变。FDE 的职业出口之一。

### 组织与沟通

- *An Elegant Puzzle* — Will Larson。工程管理中的系统思维。FDE 需要的"理解组织运作方式"的框架。
- 事后复盘报告。网上找几份真实的事后复盘报告（postmortem）读。Uber、GitHub、Cloudflare、GitLab 都公开过。比管理书更真实。

## E. FDE 全流程自测清单

### 接手新项目时
- [ ] 需求洋葱剥到第几层了？起码到第三层
- [ ] 五个 AI 适格性问题全部回答了吗？
- [ ] 有人评估过"不用 AI 的方案"吗？
- [ ] 三根轴分别打分了没有？有红的吗？
- [ ] 数据到手了吗——不是"有人答应给"，是数据样本在硬盘上？
- [ ] 找到至少一个 champion 了吗？
- [ ] 利益相关者地图画了吗？
- [ ] 项目有明确的成功标准吗——是数字不是形容词？

### 方案设计时
- [ ] 从用户出发倒推还是从模型出发正推？
- [ ] AI 冰山——水面下部分列出清单了吗？每部分估了时间吗？
- [ ] 方案决策树——从最便宜方案开始试了吗？
- [ ] 有没有可以先手动验证的？能不写代码吗？
- [ ] 如果核心 LLM 挂了系统还能部分工作吗？
- [ ] 方案里每个 AI 组件——能说清楚"为什么必须用 AI"吗？

### 开发过程中
- [ ] Prompt 有版本号吗？在 git 里吗？
- [ ] 评估集来源是真实数据还是自己编的？
- [ ] 评估维度是多维还是只有综合分数？
- [ ] LLM-as-Judge 校准过偏差吗？
- [ ] 评估每天都在做吗？
- [ ] Agent 方案的话——停止条件定义了吗？

### 上线前
- [ ] 20 个上线检查清单问题全有答案？
- [ ] 渐进式上线阶段和通过标准定了吗？
- [ ] 回滚预案写好了吗——技术操作 + 用户沟通？
- [ ] On-Call 安排好了吗？
- [ ] 不是周五上线吧？

### 上线后
- [ ] 输出质量监控就位了吗——不只是延迟和错误率？
- [ ] 数据漂移检测做了吗？
- [ ] 反馈搜集低摩擦吗？
- [ ] 反馈闭环节奏定了吗？
- [ ] 多久抽生产日志亲眼看一次？
- [ ] 竞品对比多久做一次？

### 每次复盘时
- [ ] 时间线精确到分钟吗？
- [ ] 根因是系统层面吗——不是停在"人为失误"？
- [ ] 有没有叫"下次注意"的行动项？删了重写
- [ ] 行动项都有负责人和 DDL 吗？
- [ ] 复盘结论更新了检查清单/模板/Runbook 吗？
