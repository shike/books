## 4.1 引言:为什么"技能市场"是团队 AI 协作的"倍增器"

上一章我们讲了团队工作目录的规范——把"团队的文件"管起来。

但**文件只是"原料",不是"成品"**。真正让团队效率倍增的,是"团队共享的提示词模板 + 流程"——这就是 Skill。

**先讲个真实的故事**。

深圳一家做消费电子出海的中型公司(化名"锐途科技",团队 70 人),2025 年下半年推进 WorkBuddy 落地。团队里有 3 个"特别会写提示词"的同事:市场部的小林,擅长写"产品发布邮件";销售部的老王,擅长写"客户跟进话术";运营部的阿芳,擅长写"用户调研问卷"。

他们 3 个人的提示词质量明显高于其他人——**但其他人不知道**。结果:
- 小林每周帮 5 个同事改邮件提示词(没时间,开始敷衍)
- 老王的客户跟进话术全团队 70 人在用,但每个人"抄了一点改一点",最后"风格五花八门"
- 阿芳的调研问卷模板只有 3 个人用,其他人用 AI 直接生成的"通用模板"

**3 个月后,问题集中爆发**:
- 客户反馈"你们的邮件风格怎么不一致"
- 销售跟进话术不统一,新员工上手慢
- 调研问卷质量参差不齐,数据无法对比

**锐途科技事后做的修复**:把小林 / 老王 / 阿芳的提示词"标准化 + 模板化 + 共享化"——变成"团队 Skill",所有成员都装、都能用。**3 个月后,团队整体邮件质量、客户跟进一致性、调研数据质量,都明显提升**。

**这个故事揭示了团队 AI 协作的"倍增器"**——**Skill**。

## 4.2 Skill 是什么:和"提示词模板"的本质区别

### 4.2.1 先把定义讲清楚

**Skill**(技能)在 WorkBuddy 里指的是:

> **一段可被复用的、结构化的"AI 任务定义"——包含提示词、输入规范、输出模板、调用参数、版本信息,封装后可以一键安装、调用、分享。**

我来拆开讲:

| 组成 | 含义 | 例子(以"周报生成 Skill"为例) |
|---|---|---|
| **提示词** | 任务的核心指令 | "读本周邮件 / 聊天记录,整理成周报" |
| **输入规范** | 这个 Skill 需要什么输入 | 邮件存档文件夹路径、聊天记录导出 |
| **输出模板** | 输出长什么样 | "标题 / 本周完成 / 推进中 / 下周计划 / 风险"5 段式 |
| **调用参数** | 可以配置的参数 | 周报字数范围、是否包含风险段、是否中英双语 |
| **版本信息** | 这个 Skill 的版本 + 作者 + 更新时间 | v1.0,作者张三,2025-10-15 更新 |

**一个完整的 Skill,就是一个"可被复用的 AI 任务"**——你装上后,只要提供输入,就能拿到稳定的输出。

### 4.2.2 Skill vs 提示词模板:3 个根本区别

很多读者会问:"Skill 是不是就是'提示词模板'?"

**不是**。Skill 和提示词模板有 3 个根本区别:

| 维度 | 提示词模板 | Skill |
|---|---|---|
| **完整性** | 只是一段文本 | 包含输入规范、输出模板、调用参数、版本信息 |
| **可调用性** | 要复制粘贴 | 一键调用,带参数 |
| **可分享性** | 复制文本分享 | 打包成包,带版本管理,带安装 / 卸载 |

**换句话说,提示词模板是"原材料",Skill 是"成品"**。

我用一个比喻:
- 提示词模板像"菜谱"——一段文字描述怎么做菜
- Skill 像"预制菜"——已经准备好食材和调料,加热就能吃

**对个人用户,提示词模板够用;对团队用户,Skill 是必需品**。

### 4.2.3 Skill 的 3 种来源

WorkBuddy 的 Skill 有 3 种来源,从"自产"到"外购":

| 来源 | 适合 | 优点 | 缺点 |
|---|---|---|---|
| **自己写** | 团队特有场景 | 完全定制 | 投入大 |
| **WorkBuddy 官方技能市场** | 通用场景(周报 / 纪要 / 邮件等) | 经过官方审核,质量稳定 | 选择有限 |
| **国产 Skill 社区** | 行业场景(教育 / 电商 / 制造等) | 选择多,贴近本土 | 质量参差,需要评估 |

**最推荐的做法**:先从 WorkBuddy 官方技能市场选,再根据团队需要"自己写"补充,**国产 Skill 社区作为补充但不直接全用**。

### 4.2.4 Skill 不是什么(避免误解)

为了避免你期望过高,我也讲讲 Skill **不是什么**:

- ❌ **不是"装了就能让 AI 变聪明"**——Skill 只是把"任务定义"标准化,底层还是调 AI 模型
- ❌ **不是"替代员工"**——Skill 帮你做"重复性工作",但"判断、决策、创造"还是人来
- ❌ **不是"装得越多越好"**——装 50 个 Skill 但用不到 5 个,反而拖慢 WorkBuddy
- ❌ **不是"装上就稳定"**——Skill 也可能出 bug,需要"试运行 + 反馈机制"

## 4.3 评估 Skill 的 4 个核心维度

### 4.3.1 为什么"评估"这么重要

我跟踪过 30 多个"装 Skill 翻车"的案例,翻车原因有 80% 是"没评估就装"。

**典型翻车**:
- 装了"自动回复邮件"Skill,结果发出去的邮件是"AI 腔",客户反馈"你们是不是换了客服"
- 装了"自动整理周报"Skill,结果把"项目 A 失败"也写进周报,被领导批评
- 装了"自动做数据透视"Skill,结果用了不合适的模型,算出来的数错了

**这些翻车,本来都可以"装之前评估"避免**。

### 4.3.2 评估的 4 个核心维度

我总结了一个 4 维评估框架,装任何 Skill 前先打分(每项 0-5 分,总分 20):

| 维度 | 含义 | 评估问题 |
|---|---|---|
| **质量** | Skill 的实际效果 | 装上试运行,产出质量如何?是否需要大量人工修改? |
| **安全** | Skill 是否会"越权" | Skill 会读哪些文件?会不会发对外内容?有没有数据外传风险? |
| **维护** | Skill 是否在持续更新 | 作者还在维护吗?最近一次更新什么时候?有没有 bug 反馈? |
| **适配** | Skill 是否适合你的团队 | 你的工作流和 Skill 的设计场景匹配吗?语言 / 行业 / 团队规模匹配吗? |

**总分 ≥ 16 分:推荐装**
**总分 12-15 分:可以试运行,但要先小范围**
**总分 < 12 分:不建议装**

### 4.3.3 维度 1:质量——装上试运行

**质量**是 4 个维度里**最容易被误判**的,因为"看上去好"不等于"真的好"。

**质量评估的 3 步**:

1. **看官方介绍 + 截图**——先看 Skill 的"卖相"
2. **看用户评价 + 评分**——看其他团队的使用反馈
3. **试运行 3-5 次**——这是最关键的,**没有试运行不算评估**

**试运行怎么做**:
- 选 3-5 个真实任务(不要拿"专门挑简单的任务"试)
- 用 Skill 跑 3-5 次
- 记录"输出质量""需要的修改量""意外行为"
- 让 2-3 个不同角色的人试用(运营、技术、销售各 1 个)

**质量分判断标准**:
- **5 分**:产出稳定,人工修改 < 10%
- **4 分**:产出较好,人工修改 10-20%
- **3 分**:产出一般,人工修改 20-40%
- **2 分**:产出较差,人工修改 40-70%
- **1 分**:产出很差,几乎要重写
- **0 分**:跑不通或出错

### 4.3.4 维度 2:安全——"Skill 会不会越权"

**安全**是 4 个维度里**最容易被忽视**的,因为大多数 Skill"看上去人畜无害"。

**安全评估的 5 个问题**:
1. **Skill 会读哪些文件?**——明确列出"输入文件",避免"读了你不知道的文件"
2. **Skill 会写 / 发什么?**——明确列出"输出文件 / 消息",避免"发了你不知道的内容"
3. **Skill 会不会调外部 API?**——比如调外部翻译、调联网搜索,可能有数据外传
4. **Skill 用的 AI 模型是什么?**——不同模型在数据合规上不一样(企业版可能限制只能用某些模型)
5. **Skill 会不会访问网络?**——明确"是否访问网络 / 访问哪些域名"

**安全分判断标准**:
- **5 分**:完全本地操作,无网络访问,无外部 API
- **4 分**:有少量网络访问,但只到必要服务
- **3 分**:有外部 API,但功能明确,数据流向清楚
- **2 分**:外部 API 多,数据流向不清晰
- **1 分**:有可疑行为(比如"自动备份到外部网盘")
- **0 分**:明显有安全风险(比如"自动抓取用户数据")

### 4.3.5 维度 3:维护——Skill 还在更新吗

**维护**是 4 个维度里**最影响长期使用**的——Skill 装上后,如果作者不维护,迟早出问题。

**维护评估的 4 个问题**:
1. **最近一次更新是什么时候?**——超过 6 个月没更新,基本算"半弃坑"
2. **作者还在回应用户问题吗?**——看评论区 / 反馈区
3. **有没有活跃的社区?**——有 QQ 群 / 微信群 / Discord 的 Skill,通常更活跃
4. **版本历史完整吗?**——频繁更新但每次"小修"是好迹象

**维护分判断标准**:
- **5 分**:1 个月内更新,作者活跃,社区活跃
- **4 分**:3 个月内更新,作者响应
- **3 分**:6 个月内更新,作者偶尔响应
- **2 分**:6-12 个月没更新,作者不响应
- **1 分**:12 个月以上没更新
- **0 分**:作者失联 / 项目停更

### 4.3.6 维度 4:适配——适合你的团队吗

**适配**是 4 个维度里**最容易被高估**的——因为 Skill 看上去通用,实际上需要适配。

**适配评估的 4 个问题**:
1. **行业适配**——Skill 是为哪个行业设计的?和你团队行业匹配吗?
2. **规模适配**——Skill 是为多大团队设计的?和你团队规模匹配吗?
3. **语言 / 文化适配**——Skill 是中文的吗?符合中国职场习惯吗?
4. **工作流适配**——Skill 设计的工作流,和你团队的实际工作流匹配吗?

**适配分判断标准**:
- **5 分**:完全匹配(同行业 / 同规模 / 同语言 / 同工作流)
- **4 分**:基本匹配,小调整即可
- **3 分**:中等匹配,需要中度定制
- **2 分**:勉强匹配,需要重度定制
- **1 分**:不匹配,需要大改
- **0 分**:完全不匹配

### 4.3.7 一个真实评估案例

**背景**:某 30 人 SaaS 公司(化名"蓝海科技")考虑装"自动生成销售周报"Skill。
**候选**:国产 Skill 社区某热门 Skill,标榜"AI 帮你写销售周报,1 分钟搞定"。

**评估过程**:

**1. 质量(试运行)**:
- 试 5 份销售周报,产出质量参差
- 1 份直接能用,2 份改 20-30%,2 份要重写
- 不同销售用,产出风格不一致
- 质量分:**3 分**

**2. 安全**:
- 会读"销售跟进记录"文件夹——OK
- 会读"客户档案"——这超出了预期
- 会调外部翻译 API(为了多语言支持)——没用到
- 安全分:**2 分**

**3. 维护**:
- 最近一次更新 4 个月前
- 作者偶尔回复评论
- 社区活跃度一般
- 维护分:**3 分**

**4. 适配**:
- 行业匹配(销售场景)
- 规模匹配(适合 30 人)
- 中文,符合中国职场
- 工作流匹配度中等(我们的销售流程有定制)
- 适配分:**3 分**

**总分:3+2+3+3 = 11 分(< 12 分,建议不装)**

**蓝海科技的决定**:**不装,自己写一个内部 Skill**。他们花了 1 周,基于团队实际销售流程写了一个内部"销售周报 Skill",3 个月后,这个内部 Skill 已经成为团队的核心资产之一。

**这个案例的关键**:**评估结果可能告诉你"不装"——这也是好结果**,因为它帮你避免了"装错 Skill"的更大损失。

## 4.4 国产高频场景的 Top 10 Skill 推荐

讲完评估方法,我给你一份"Top 10 高频场景"参考——这是国产 Skill 社区 + WorkBuddy 官方技能市场里,最常被装、最实用的 10 类 Skill。

**注意**:以下 Skill 的具体名称、作者、维护情况以你安装的 WorkBuddy 版本和国产 Skill 社区当时为准,这里给的是"场景维度"。

### 4.4.1 Top 1:周报生成

**场景**:每周写周报,需要 AI 读本周邮件 / 聊天 / 文档,自动整理。

**Skill 关键能力**:
- 读邮件存档 / 聊天记录导出
- 按"已完成 / 推进中 / 下周计划 / 风险"4 段式输出
- 字数控制(800-1500 字)
- 风格可选(正式 / 半正式 / 简洁)

**选 Skill 时关注**:
- 邮件格式兼容性(Outlook / 网易 / QQ / Gmail)
- 聊天记录格式(企业微信 / 飞书 / 钉钉导出)
- 输出模板是否可自定义

**适配行业**:全员(各行业都适用)

### 4.4.2 Top 2:会议纪要

**场景**:开会后,把录音转写文件变成"决策 + 行动项 + 负责人 + 截止时间"。

**Skill 关键能力**:
- 读转写文件(.txt / .docx / .srt)
- 区分"决策""讨论""行动项"
- 自动识别"负责人""截止时间"
- 支持多发言人区分

**选 Skill 时关注**:
- 中文转写格式兼容(讯飞 / 飞书妙记 / 通义听悟)
- 多人会议识别能力
- 行动项跟踪能力

**适配行业**:全员

### 4.4.3 Top 3:邮件润色 + 翻译

**场景**:起草邮件 + 润色 + 中英翻译。

**Skill 关键能力**:
- 起草:基于要点,自动起草邮件
- 润色:把"大白话"改成"专业邮件"
- 翻译:中→英、英→中,保持语气
- 语气控制(正式 / 友好 / 紧急 / 道歉)

**选 Skill 时关注**:
- 翻译质量(尤其专业术语)
- 语气控制精细度
- 是否支持"自动发送"(高风险,谨慎)

**适配行业**:外贸、跨境、咨询、外企

### 4.4.4 Top 4:PPT 大纲 + 草稿

**场景**:读报告 / 文档,自动生成 PPT 大纲,甚至直接生成 PPT 草稿。

**Skill 关键能力**:
- 读长文档(50-200 页)
- 生成 10-20 页 PPT 大纲
- 自动分配"每页核心观点"
- 可选生成"草稿 PPT"(调用 PowerPoint)

**选 Skill 时关注**:
- 文档格式支持(PDF / Word / Markdown)
- 模板丰富度
- 大纲逻辑质量(是否真的"懂"内容)

**适配行业**:咨询、营销、产品、研发

### 4.4.5 Top 5:数据透视 + 洞察

**场景**:读 Excel / CSV,自动做透视,出 3-5 个洞察。

**Skill 关键能力**:
- 读 Excel / CSV(多表)
- 自动选透视维度
- 出洞察("本月营收增长 15%,主要来自 A 客户")
- 出图表(柱状 / 折线 / 饼图)

**选 Skill 时关注**:
- Excel 兼容性(多 sheet / 跨表)
- 洞察质量(是否"懂业务")
- 图表美观度

**适配行业**:销售、运营、市场、财务

### 4.4.6 Top 6:招聘 JD 撰写

**场景**:基于岗位需求,撰写招聘 JD。

**Skill 关键能力**:
- 读岗位描述(简单几句话)
- 扩写成标准 JD(职责 / 要求 / 加分项)
- 行业术语适配
- 中英双语

**选 Skill 时关注**:
- 行业术语准确度
- 风格选项(严肃 / 活泼 / 创业风)
- 是否能自动发到招聘平台

**适配行业**:HR

### 4.4.7 Top 7:行业调研报告

**场景**:联网搜 + 综合多份文档,出行业调研报告。

**Skill 关键能力**:
- 联网搜(可控范围)
- 读多份 PDF / 网页
- 综合出报告(摘要 + 趋势 + 机会)
- 引用来源

**选 Skill 时关注**:
- 联网搜的"可控性"(能不能限定来源)
- 综合质量(是否"读懂"了多份材料)

## 4.5 团队共享 Skill 的机制:试运行 → 全量铺开

### 4.5.1 为什么不能"全员同时装"

很多团队 leader 觉得"装 Skill 又不是装炸弹,装上就好"。

**错了**。Skill 装上后,会**改写团队成员的工作流**——一旦改错,影响是"全员 + 持续"。

**正确做法**:试运行 → 全量铺开,3 步走。

### 4.5.2 第 1 步:小范围试运行(1-2 周)

**选 2-3 个"标杆员工"** + 1 个 Skill,试运行 1-2 周。

**具体动作**:
- 标杆员工装上 Skill,跑真实任务
- 每天记录"用得怎么样""有什么问题"
- 1 周后开 30 分钟复盘会,确定"要不要全量铺"

**试运行的 3 个判断标准**:

1. **标杆员工"主动用"**——3 个标杆员工中至少 2 个"主动用"(不靠提醒)
2. **没有"重大问题"**——没有"数据泄露""误发""质量崩塌"等问题
3. **效果"可被量化"**——能说清楚"装 Skill 前 X 小时,装后 Y 小时,Y < X"

**如果 3 个标准都满足,进入第 2 步;否则停止,重新评估 Skill**。

### 4.5.3 第 2 步:中范围铺开(2-4 周)

**铺给 20-30% 的团队成员**(比如 30 人团队铺 6-10 人)。

**具体动作**:
- 铺给"标杆员工 + 标杆员工的紧密协作者"
- 每周开 1 次"Skill 使用分享会"(30 分钟)
- 收集"用得好 / 用得不好"的反馈

**铺开的 3 个判断标准**:

1. **新加入的 6-10 人"周活"**——每周至少用 1 次
2. **场景使用正确**——不是"为了装而装",是真的用在真实工作
3. **没有"复发性问题"**——已经解决的问题,没有重新出现

**如果 3 个标准都满足,进入第 3 步**。

### 4.5.4 第 3 步:全量铺开(2-4 周)

**铺给全团队**。

**具体动作**:
- 全员培训(90 分钟入门培训 + 1 周"老带新")
- 写"Skill 使用指南"(放公共区)
- 收集"长期反馈",每月 1 次"Skill 优化"

**全量铺开的 4 个判断标准**:

1. **团队周活率 ≥ 50%**——一半以上成员每周用
2. **没有"全团队抵制"**——没人明确说"我不用"
3. **有"内部拥护者"**——至少有 1-2 个成员"主动推广"
4. **没有"重大事故"**——质量 / 安全 / 合规都没出问题

### 4.5.5 团队共享 Skill 的"3 个反模式"

**反模式 1:不评估就全员装**
- 后果:装错 Skill,全员受害,撤都来不及
- 对策:用 4 维评估框架,打分 < 12 不装

**反模式 2:试运行不做记录**
- 后果:试运行完了,不知道"该不该全量铺"
- 对策:每天记录"用得怎么样",周复盘

**反模式 3:全量铺开后不维护**
- 后果:Skill 出 bug 没人管,慢慢被弃用
- 对策:指定"Skill 维护人",每月 1 次优化

### 4.5.6 一个真实团队共享 Skill 案例

**公司**:广州某教育 SaaS 公司(化名"知行学塾",团队 90 人)
**目标**:把"周报生成 Skill"推广到全团队

**第 1 步(试运行,1 周)**:
- 选 3 个标杆员工(2 个运营 + 1 个 HR)
- 装上"周报生成 Skill",每人跑 2 次
- 反馈:1 个运营觉得"读邮件不准",1 个 HR 觉得"输出太长"
- 决定:调整 Skill 参数(改字数上限 + 加邮件白名单),进入第 2 步

**第 2 步(中范围铺开,2 周)**:
- 铺给 18 个团队成员(覆盖 6 个部门)
- 每周 30 分钟"Skill 分享会"
- 反馈:大部分人"用得很爽",但有 2 个成员"嫌麻烦,不装"
- 决定:进入第 3 步(但不强求那 2 个)

**第 3 步(全量铺开,3 周)**:
- 全员培训 90 分钟
- 写"周报 Skill 使用指南",放公共区
- 3 周后:全团队 80+ 人装了 Skill,周活 65+(> 70%)
- 每月 1 次"Skill 优化",迭代到 v1.2

**关键数字**:
- 团队周报总耗时:从 800 分钟/周 → 300 分钟/周(降 62%)
- 标杆员工"周报耗时":从 60 分钟 → 15 分钟
- 团队成员"周报痛苦度"(自评):从 7.2/10 → 3.5/10

**这是 Skill 团队共享的典型成功路径**。

**总分 12-15**:可以试运行,但小范围

## 4.7 小结

本章我们讲了技能市场的 5 件事:

1. **Skill 是什么**——和提示词模板的 3 个根本区别(完整性 / 可调用性 / 可分享性);Skill 是"可复用的 AI 任务",是团队 AI 协作的倍增器。
2. **Skill 的 3 种来源**——自己写 / WorkBuddy 官方技能市场 / 国产 Skill 社区;最推荐"先用官方 + 自己补充 + 社区作补充"。
3. **评估 Skill 的 4 维框架**——质量 / 安全 / 维护 / 适配,每项 0-5 分,总分 ≥ 16 才推荐装。
4. **国产高频场景 Top 10**——周报 / 纪要 / 邮件 / PPT / 数据透视 / JD / 调研 / 客户跟进 / 跨部门沟通 / 知识问答。
5. **团队共享 Skill 的 3 步走**——小范围试运行(1-2 周)→ 中范围铺开(2-4 周)→ 全量铺开(2-4 周),每步有 3-4 个判断标准。

**关键判断**:
- Skill 评估是"装之前必做",不是"装之后再补"
- 评估可能告诉你"不装"——这也是好结果
- 团队共享 Skill 必须"试运行 → 全量铺开",不能"全员同时装"
- 团队的"个人智慧"(标杆员工的提示词)是 Skill 资产的最大来源——下一章会讲怎么把它沉淀

下一章(第 5 章)我们讲"专家中心"——**当团队里有 5-10 个"标杆员工"、每个都有"自己的"提示词和流程,怎么把它们"沉淀"成"团队的可复用资产"?**专家中心就是干这件事的——它不是"装 Skill 的市场",是"团队自己产出 Skill 的工厂"。
