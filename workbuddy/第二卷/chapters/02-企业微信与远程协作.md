## 2.1 引言:为什么远程协作是推广 + 沉淀阶段的"必答题"

上一章我们讲了团队落地的三阶段(试点 → 推广 → 沉淀)。在"推广 + 沉淀"阶段,几乎所有团队 leader 都会被问同一个问题——

> "老板不在办公室,事情还能不能继续跑?"

我先把这个问题的真实成本算给你看。

假设你带一个 10 人团队,你不在办公室的频率是:

| 场景 | 频次(每月) | 单次时长 | 月度合计 |
|---|---|---|---|
| 出差 | 2-3 次 | 2-3 天 | 5-9 天 |
| 跨城市会议 | 1-2 次 | 1-2 天 | 2-4 天 |
| 病假 / 私事 | 1-2 次 | 0.5-1 天 | 0.5-2 天 |
| 周末紧急 | 4-5 次 | 0.5-1 小时 | 2-5 小时 |
| 通勤 / 路上 | 22 个工作日 | 1-2 小时 | 22-44 小时 |

**合计:你每月有 15-25 天不在工位上**——但你的团队还在跑,事情还在发生。

这时,以下三类事情会变得**"等你回来处理"**:
- 实习生卡在某个数据处理任务上,等你回来
- 客户半夜发的邮件,等你回来
- 跨部门的方案评审,等你回来

**"等你回来"本身就是成本**——它意味着团队节奏被你"卡住"。我跟踪 20 多个团队,做过一个粗略的统计:**"管理者不在办公室"导致的团队整体效率下降,平均在 15-25%**。

这件事不能"等管理者在办公室再处理"。**远程协作能力,是推广 + 沉淀阶段的"必答题",不是"加分题"**。

本章我讲 5 件事:
1. 移动端协作:出差 / 会议室 / 周末的远程派任务
2. 企业微信集成:把 WorkBuddy 接到企业微信,实现"群内调用"
3. 飞书 + 钉钉集成:另两家国内办公平台的对接逻辑
4. 团队授权的颗粒度:"角色 + 任务"双层模型
5. 安全边界:高风险操作二次确认、SSO、审计日志这"3 道防线"

读完后,你会有一份完整的"远程协作方案",可以直接套用到你团队。

## 2.2 移动端协作:把 WorkBuddy "伸出爪子"

### 2.2.1 移动端协作的本质:"把本机能力联网化"

**先讲清楚一件事**——WorkBuddy 是一款**本机部署的桌面 AI 客户端**,它的"本机"属性是核心差异化(第一卷 1.3 讲过)。**移动端协作不是"取代"本机,而是"延伸"本机**。

打个比方:你的电脑是"主厨",WorkBuddy 是"主厨的智能助手",移动端协作是"主厨的远程耳朵和嘴巴"——你不在厨房(电脑前)时,耳朵和嘴巴接收指令,转给主厨执行,执行结果再回到耳朵和嘴巴。

**这种设计有两个根本好处**:
- **数据不离开本机**——所有"读文件 / 写文件"操作都在你电脑上完成,移动端只收发指令和结果
- **攻击面被控制**——即便移动端权限泄露,攻击者也只拿到"派任务"的能力,拿不到"本机所有文件"

**反过来,也有一件事必须坦白**:**移动端不能做"本机所有事"**。比如:
- 移动端不能直接编辑本机文件(只能查看、批注、回传指令)
- 移动端不能调用本机软件的所有功能(只能调用 WorkBuddy 集成的功能)
- 移动端不能替代"坐在电脑前"——某些需要"看大屏"的任务(PPT 设计、Excel 透视)还是要在电脑上做

**这意味着"移动端协作"是"补位"工具,不是"替代"工具**。

### 2.2.2 远程派任务的三类典型场景

**场景 1:出差中的"派任务 + 看结果"**

你周三去上海出差,周四上午 10 点客户临时要一份竞品对比。你的团队在北京办公室,桌上电脑没带。

**传统做法**:你打电话给团队成员 → 解释需求 → 团队成员做 → 拍照发你 → 你修改 → 再发回去。全程 1-2 小时,中间打 3-5 个电话。

**远程派任务做法**:
1. 你在企业微信里给 WorkBuddy 发一条指令:"做一份竞品对比,聚焦 A、B、C 三家,15 分钟内给我"
2. WorkBuddy 读你授权的工作目录(里面有"竞品资料"文件夹)
3. WorkBuddy 出对比表,推到企业微信群(或者私聊发你)
4. 你在手机上审一遍,标注修改意见,再发回群里让团队成员改
5. 总耗时 20-30 分钟

**这里有几个关键设计**:
- **指令要"具体"**——"做一份竞品对比"太模糊,"聚焦 A、B、C 三家"才具体
- **结果要"可审"**——WorkBuddy 给的结果应该可以直接发,不能"AI 写的不能直接发"
- **修改要"可逆"**——你标注的修改意见要能让团队成员快速定位、改回

**场景 2:会议室外的"秒级决策"**

你和销售在会议室,客户突然问"你们 Q3 的产能数据是多少"。你一时想不起来。

**传统做法**:你掏出手机查邮件 / 翻微信,翻 5-10 分钟。期间客户在等。

**远程派任务做法**:
1. 你在企业微信私聊里给 WorkBuddy 发:"Q3 产能数据是多少?"
2. WorkBuddy 读你授权的"产能报表"文件夹,挑出 Q3 数据
3. WorkBuddy 给你一个一句话回答 + 一个数据来源(Excel 文件名)
4. 你直接说给客户听

**耗时 30 秒**。

**场景 3:周末的"轻量审批"**

你周六在家,实习生发来一份方案,需要你审批。方案 3000 字,你看 1 小时,还要写反馈。

**传统做法**:你周一再说 / 你花 1 小时看。

**远程派任务做法**:
1. 实习生把方案发到企业微信群,@你
2. 你在企业微信私聊给 WorkBuddy 发:"读群里的方案,给我 5 条核心意见 + 3 个潜在风险"
3. WorkBuddy 读方案,出意见
4. 你看 5 分钟,在企业微信里回复实习生
5. 总耗时 10 分钟

### 2.2.3 远程派任务的 4 条"黄金规则"

远程派任务,听起来简单,但**90% 的失败是因为"指令太模糊"**。我归纳 4 条"黄金规则"——

**规则 1:指令必须"具体到能跑"**

| 模糊指令 | 具体指令 |
|---|---|
| "做个竞品分析" | "对比 A、B、C 三家,聚焦功能、定价、客户案例 3 维度,15 分钟内给我表" |
| "写个会议纪要" | "读群里的会议录音转写,出 5 条决策 + 5 个行动项 + 负责人 + 截止时间" |
| "看这份报告" | "读这份 50 页的 PDF,出 3 个核心结论 + 5 个数据支撑" |

**规则 2:必须"先授权,后执行"**

WorkBuddy 只能读"你授权过的目录"。**远程派任务之前,你要先确认 WorkBuddy 已经授权读相关目录**。授权步骤在第一卷第 2 章讲过,这里不重复。

**规则 3:必须"先审,后用"**

**WorkBuddy 出的所有结果,必须人工审过才能用**。这不是"建议",是"原则"。哪怕你赶时间,也要至少"扫一遍"。

**规则 4:必须"留痕,可回溯"**

WorkBuddy 的审计日志会记录"谁在什么时候给 WorkBuddy 派了什么任务,WorkBuddy 读了哪些文件,产出了什么结果"。**所有远程派任务都应该在审计日志里能看到**。

### 2.2.4 移动端不能做什么

**坦白讲清楚,避免你期望过高**:

- ❌ **不能"接管你的整个桌面"**——WorkBuddy 移动端只能调用 WorkBuddy 相关功能,不能操控本机的浏览器、私人文件、整个桌面
- ❌ **不能"代替电脑前的工作"**——大屏设计、复杂数据透视、长篇 PPT 制作,还是在电脑前做
- ❌ **不能"在你完全不知情时执行"**——所有远程任务,审计日志都会推送到你手机上,你可以随时暂停
- ❌ **不能"读取未授权目录"**——这是"最小权限"原则的硬约束

## 2.3 企业微信集成:把 WorkBuddy 接到"团队日常沟通"

### 2.3.1 企业微信集成的 3 种形态

WorkBuddy 与企业微信的集成,有 3 种形态,从轻到重:

| 形态 | 适合 | 配置成本 | 安全等级 |
|---|---|---|---|
| **轻量:群机器人** | 团队 5-20 人,简单"群内调用" | 5 分钟配置 | 中(看群里谁都能看到) |
| **中量:自建应用** | 团队 20-100 人,需要权限控制 | 1-2 小时 | 高(权限可控) |
| **重量:深度集成** | 团队 100+ 人,需要"读聊天记录" | 1-2 天 | 最高(企业 IT 介入) |

**最常用的是前两种**——群机器人适合 5-20 人,自建应用适合 20-100 人。深度集成(读聊天记录)涉及企业数据合规,建议先和 IT 沟通再启用。

### 2.3.2 群机器人的标准配置流程

**群机器人**是最简单的集成方式——把 WorkBuddy 作为一个"群成员"加到企业微信群,它能接收群里的指令、产出结果推到群里。

**配置步骤(5 分钟搞定)**:

1. **WorkBuddy 后台生成机器人 token**:WorkBuddy → 设置 → 第三方集成 → 企业微信 → "创建群机器人" → 系统会生成一个 token(类似一串字符)
2. **企业微信群添加机器人**:打开企业微信群 → 群设置 → 群机器人 → 添加 → 粘贴 WorkBuddy 提供的 token
3. **WorkBuddy 后台绑定群**:把企业微信群的群 ID 填到 WorkBuddy 后台,完成双向绑定
4. **测试**:在群里 @ WorkBuddy 机器人 + 派任务指令 → 看结果

**配置完成后,你可以这样用**:

```
@WorkBuddy 帮我读群里昨天张经理发的方案,出 3 条核心意见
@WorkBuddy 整理本周的周报,基于我授权的工作目录
@WorkBuddy 把这份会议纪要转成 5 条行动项,负责人 + 截止时间
```

**关键配置技巧**:

- **指令前缀**:你可以设置"必须 @ 我"或"必须带特定前缀",避免群里其他人误触发
- **结果回执**:WorkBuddy 出结果后,可以选择"只在私聊发你""发到群里""发到指定人"
- **错误降级**:如果 WorkBuddy 出错,会回"出错原因 + 建议",而不是"出错了就完蛋"

### 2.3.3 自建应用的标准配置流程

**自建应用**比群机器人复杂,但权限更可控。**它适合 20+ 人团队,需要"不同人有不同权限"**。

**配置步骤(1-2 小时)**:

1. **企业微信后台创建自建应用**:企业微信管理后台 → 应用管理 → 自建 → 创建应用"WorkBuddy"
2. **配置可见范围**:设置"哪些部门 / 哪些人"能用这个应用
3. **获取 corp_id 和 secret**:企业微信会给 corp_id 和应用 secret
4. **WorkBuddy 后台配置企业微信集成**:WorkBuddy → 设置 → 第三方集成 → 企业微信 → "配置自建应用" → 填 corp_id 和 secret
5. **配置权限映射**:在 WorkBuddy 后台,设置"企业微信的'部门 / 角色'对应 WorkBuddy 的'角色 / 权限'"
6. **测试 + 灰度**:先让 3-5 个团队成员试 1 周,确认没问题再全量铺开

![企业微信自建应用配置流程:5 步](figures/2.2.2-wecom-self-built-app.png)

**关键配置技巧**:

- **权限映射要"细"**:不要"所有人都能读所有文件",要按"部门 / 角色"细到"具体能读哪些目录"
- **敏感操作要"二次确认"**:比如"用 WorkBuddy 写邮件发出去""删除文件""跨成员读工作目录",这些操作必须二次确认
- **审计日志要"全"**:所有"读 / 写"操作都留日志,180 天可查

### 2.3.4 企业微信集成的"3 个常见坑"

**坑 1:把企业微信当成"备份"**

有些团队觉得"WorkBuddy 出的结果发到企业微信,我就放心了"。**错了**。企业微信是"沟通工具",不是"备份工具"。**WorkBuddy 出的关键结果,应该在 WorkBuddy 本机也存一份**,企业微信只是"通知渠道"。

**坑 2:把群里所有人都能"派任务"**

如果群机器人没设置指令前缀,群里任何人都可以 @ WorkBuddy 派任务。**这意味着实习生也可能误触发"删除文件"等高危操作**。**必须设指令前缀 + 二次确认**。

**坑 3:把"读聊天记录"当成"默认"**

深度集成(读聊天记录)涉及"员工隐私",**不应该默认开启**。即使企业 IT 同意,也要明确告知所有员工:"WorkBuddy 会读取我们的工作群聊天记录用于 AI 任务"。

## 2.4 飞书与钉钉:另两家国内办公平台的对接逻辑

### 2.4.1 为什么三家都要讲

国内主流的办公 IM 平台有三家:**企业微信、飞书、钉钉**。它们覆盖了不同类型的公司:
- **企业微信**:腾讯系,适合已经用企业微信做客户管理的公司
- **飞书**:字节系,适合互联网、科技、新经济公司
- **钉钉**:阿里系,适合制造业、传统行业、阿里系公司

**这三家的对接逻辑大同小异**,都是"WorkBuddy 作为一个应用 / 机器人接入,接收指令、回传结果"。**理解了企业微信的逻辑,飞书和钉钉只需要"换配置"**。

### 2.4.2 飞书集成要点

飞书的开放能力比企业微信更强,主要体现在:
- **飞书机器人**支持"消息卡片"(更丰富的交互)
- **飞书文档**支持 WorkBuddy 直接"读写"(不只是发消息)
- **飞书多维表格**支持 WorkBuddy 直接"写行"(适合数据处理场景)

**配置流程**(和企业微信类似):
1. 飞书开放平台 → 创建应用 → 获得 app_id 和 app_secret
2. WorkBuddy 后台 → 飞书集成 → 填 app_id / app_secret
3. 配置权限范围(读消息 / 写消息 / 读飞书文档 / 写飞书文档)
4. 测试

**飞书特有的"文档协作"场景**:
- WorkBuddy 读飞书文档 → 写飞书文档(全流程无需下载到本机)
- WorkBuddy 读多维表格 → 自动填多维表格(数据录入自动化)

### 2.4.3 钉钉集成要点

钉钉的强项是"审批流 + 考勤 + OA",WorkBuddy 集成后可以实现:
- **钉钉审批**:WorkBuddy 帮你起草审批单 + 自动跟进审批状态
- **钉钉考勤**:WorkBuddy 读考勤数据 + 出"团队出勤分析"
- **钉钉 OA**:WorkBuddy 读 OA 待办 + 提醒你 + 帮你起草回复

**配置流程**:
1. 钉钉开放平台 → 创建应用 → 获得 app_key 和 app_secret
2. WorkBuddy 后台 → 钉钉集成 → 填 app_key / app_secret
3. 配置权限范围(读考勤 / 写审批 / 读 OA 等)
4. 测试

### 2.4.4 三家平台对比

| 维度 | 企业微信 | 飞书 | 钉钉 |
|---|---|---|---|
| **配置难度** | 中 | 较低(开放能力好) | 中 |
| **权限粒度** | 中(按部门 / 角色) | 高(细到字段) | 中(按角色) |
| **消息回执** | 文本 / 卡片 | 文本 / 卡片 / 表格 | 文本 / 卡片 |
| **文档协作** | 需额外配置 | 原生支持 | 需额外配置 |
| **适用公司** | 腾讯系 / 客户管理重 | 互联网 / 科技 | 制造业 / 传统行业 |

**我的建议**:**你的团队用哪家 IM,就用哪家集成**。**不要"为了 AI 协作"换 IM**——换 IM 的成本远大于 AI 协作的收益。

## 2.5 团队授权:"角色 + 任务"双层模型

### 2.5.1 为什么需要"双层模型"

**先讲个真实事故**。

广州一家做 SaaS 的公司(化名"新云科技",团队 50 人),2025 年下半年在 WorkBuddy 团队版上,管理员为了"方便",给所有 50 个人都开了"管理员"权限。结果,某天一个新来的运营,误操作把"客户成功案例库"整个文件夹删了(他以为是个人的临时文件)。**事故复盘时,管理员痛哭流涕——"我以为大家都懂,没想到"**。

**这是"粗放授权"导致的典型事故**。

正确的做法是"**角色 + 任务"双层模型**:
- **角色**:决定默认能力范围(管理员 / 成员 / 只读)
- **任务**:决定具体能看哪些目录、调起哪些工具

**两层一起管,才能避免"误操作 + 越权访问"**。

### 2.5.2 三种内置角色

WorkBuddy 团队版内置三种角色(具体名称以你安装的版本为准):

| 角色 | 权限范围 | 适合 |
|---|---|---|
| **管理员(Admin)** | 团队配置、成员管理、计费、全部工作目录读取 | 1-3 人(可设主备避免单点) |
| **成员(Member)** | 自己的工作目录 + 公共目录读取、AI 调用 | 大多数团队成员 |
| **只读(Viewer)** | 只能看,不能改、不能派任务 | 实习生 / 外部协作方 |

**为什么是这三种?** 这是从 50+ 团队实践中归纳的"最小必要角色集"。**角色越多,管理成本越高;角色越少,灵活性越差**——三种是平衡点。

### 2.5.3 任务维度的 4 个权限

光有角色不够,因为同一种角色(比如"成员"),在不同任务下需要不同权限。

WorkBuddy 把"任务"拆成 4 个权限维度,每个维度可以独立配置:

| 权限维度 | 含义 | 默认 |
|---|---|---|
| **读工作目录** | 能读哪些目录 | 自己的工作目录 + 公共目录 |
| **写工作目录** | 能写哪些目录 | 仅自己的工作目录 |
| **调起 AI 模型** | 能用哪些 AI 模型 | 所有团队授权的模型 |
| **派任务给其他成员** | 能不能"指派 WorkBuddy 任务给别人" | 不能(只有管理员能) |

**这 4 个维度可以独立配置**。比如:
- 运营小张:可以读"市场部"目录,可以写"市场部"目录,可以调 AI,**不能**指派给别人
- HR 小李:可以读"人事部"目录,**不能**读"市场部"目录,可以调 AI,**不能**指派给别人
- 实习生小王:只能读"实习生共享"目录,不能写、不能调 AI、不能指派

**这种"细颗粒度"配置,适合 30+ 人团队**。**10 人以下团队,默认配置就够,不用细调**。

### 2.5.4 跨成员访问的"4 条原则"

跨成员访问(成员 A 读成员 B 的工作目录)是**最容易出事**的环节,必须严守 4 条原则:

**原则 1:默认不开放**
- 成员 A 默认**不能**读成员 B 的工作目录
- 即便两人"关系好",也要走"申请-审批"流程

**原则 2:读要留痕**
- 一旦开放 A 读 B 的目录,所有读取动作都进审计日志
- 180 天可查

**原则 3:写要二次确认**
- A 写 B 的目录,必须有"二次确认"弹窗(在 B 的 WorkBuddy 上弹)
- B 可以"同意 / 拒绝 / 限时开放"

**原则 4:撤权要彻底**
- 项目结束、成员转岗、成员离职,必须**立即撤权**
- 撤权动作 1 周内做一次,过期自动撤

**新云科技那个事故,如果遵守这 4 条原则,根本不会发生**——因为"删除"是高危操作,会有二次确认;因为新来的运营默认不开放"写市场部目录"。

## 2.6 高风险操作的二次确认机制

### 2.6.1 哪些操作算"高风险"

**先把"高风险操作"列清楚**,避免模糊。

| 类别 | 高风险操作 | 风险等级 |
|---|---|---|
| **写出去** | 邮件发出、企业微信消息发出、对外文档发布 | 高 |
| **跨成员** | 读他人目录、写他人目录、跨成员派任务 | 中-高 |
| **数据修改** | 删除文件、覆盖文件、批量重命名、批量删除 | 高 |
| **对外动作** | 联网搜索、调用外部 API、上传文件到外部服务 | 中-高 |
| **付费动作** | 触发 积分 大额消耗、订阅变更 | 中 |

### 2.6.2 二次确认的 3 种方式

WorkBuddy 提供 3 种二次确认方式,从轻到重:

| 方式 | 适合 | 实现 |
|---|---|---|
| **桌面弹窗** | 操作人在电脑前 | WorkBuddy 主界面弹窗,点"确认 / 取消" |
| **企业微信 / 飞书 / 钉钉推送** | 操作人不在电脑前 | 推送卡片到手机,点"确认 / 取消" |
| **双人复核** | 极高风险操作(比如"全员权限变更""批量删除客户数据") | 管理员 + 1 个复核人,都点确认才执行 |

**最常用的是前两种**——桌面弹窗 + IM 推送。第三种"双人复核"只在极高风险操作时用。

### 2.6.3 二次确认的"4 个关键设计"

**设计 1:不能"无脑确认"**
- 弹窗里必须显示"操作的完整内容"——不是"确认删除 1 个文件",而是"确认删除'客户案例库 2025Q3.xlsx'(2.3 MB)"
- 不能 1 秒内"自动确认"——必须停 3 秒以上

**设计 2:不能"事后撤回"**
- 二次确认按下的瞬间,操作已执行
- 所以**二次确认前必须看清**

**设计 3:必须"留痕"**
- 二次确认的时间、操作人、复核人都进审计日志
- 180 天可查

**设计 4:必须"分级"**
- 风险等级不同,二次确认方式不同
- 低风险(写自己的工作目录)→ 桌面弹窗
- 中风险(跨成员写)→ 桌面弹窗 + IM 推送
- 高风险(对外发布、批量删除)→ 桌面弹窗 + IM 推送 + 5 秒等待

## 2.7 SSO 单点登录

### 2.7.1 为什么团队需要 SSO

**SSO(Single Sign-On,单点登录)**在团队场景下非常关键——它解决三个问题:

1. **账号统一管理**:你不需要在 WorkBuddy 里单独建 50 个账号,直接用企业微信 / 飞书 / 钉钉 / 邮箱账号登录
2. **离职即撤权**:员工离职,关闭企业微信账号,WorkBuddy 权限自动撤销——不需要在 WorkBuddy 后台手动删
3. **合规可审计**:登录日志和企业账号体系对齐,审计时不用"两套账号"

**这三点对 30+ 人团队是"必需",不是"可选"**。

### 2.7.2 SSO 配置流程

WorkBuddy 团队版支持三种 SSO 协议:

| 协议 | 适合 | 配置难度 |
|---|---|---|
| **OAuth 2.0** | 用企业微信 / 飞书 / 钉钉账号登录 | 中(1-2 小时) |
| **SAML 2.0** | 用公司统一身份认证(常见于中大型企业) | 高(需 IT 介入) |
| **LDAP** | 用公司 AD 域账号登录 | 高(需 IT 介入) |

**最常用的是 OAuth 2.0**——直接复用企业微信 / 飞书 / 钉钉账号。中小团队用这个就够;大企业(尤其是有专门 IT 团队的)可以考虑 SAML / LDAP。

### 2.7.3 SSO 配置的 3 个关键点

**关键点 1:不要"全员强制 SSO"**
- 试点期先开 1-2 个 SSO 入口,跑 1-2 周,稳定后全量铺
- 避免"全员同时切 SSO",出问题影响所有人

**关键点 2:保留"本地账号"作为兜底**
- 即使全员 SSO,也保留 1-2 个"管理员本地账号"
- 防止"SSO 服务挂了,所有账号都登不上"

**关键点 3:定期"清理失效账号"**
- 每月 1 次,清理"90 天未登录 + 已离职"账号
- 审计日志里查"长期不活跃"账号

## 2.8 审计日志:远程协作的最后一道防线

### 2.8.1 审计日志记什么

WorkBuddy 的审计日志(默认保留 180 天,企业版可延长)会记录**所有"读 / 写 / 派任务"操作**:

| 字段 | 含义 |
|---|---|
| 时间 | 操作发生的精确时间(到秒) |
| 操作人 | 哪个团队成员 |
| 操作类型 | 读 / 写 / 派任务 / 调 AI / 删 / 改 等 |
| 操作对象 | 哪个文件 / 哪个目录 / 哪个任务 |
| AI 模型 | 调用的哪个 AI 模型(DeepSeek / Kimi / 智谱 / 通义 / 文心 / 豆包) |
| 消耗 积分 | 这次操作消耗的 积分 |
| 操作结果 | 成功 / 失败 / 被拒绝 |

### 2.8.2 审计日志的 3 个核心用途

**用途 1:事故溯源**
- 万一出事故(数据泄露、误删、误发),第一时间拉日志,看"谁在什么时候做了什么"
- 平均溯源时间从"几天"降到"几分钟"

**用途 2:行为分析**
- 看"谁用得最多 / 哪个场景最常用 / 哪个时间段最高频"
- 用作"团队效率报告"的数据源

**用途 3:合规审计**
- 金融、医疗、法律等强合规行业,审计日志是"刚需"
- 客户问"你们怎么处理数据",直接导出日志展示

### 2.8.3 审计日志的"4 条使用规则"

**规则 1:每月抽查 5%**
- 不是"全员审查",是"随机抽 5%"——包括"非工作时间操作""跨成员访问""大额 积分 消耗"等重点项
- 抽查结果记录在案,作为"季度安全报告"

**规则 2:重点关注"非工作时间操作"**
- 半夜、周末、节假日的操作,通常是"远程派任务"——合理
- 但如果某些账号频繁在非工作时间做"跨成员读目录",需要重点关注

**规则 3:重点关注"跨成员访问"**
- 默认不开放跨成员访问——一旦发生,必有审批
- 审计日志里"无审批的跨成员访问"是"红线"

**规则 4:导出 + 归档**
- 每月导出一次审计日志,归档到企业存储
- 180 天后 WorkBuddy 自动清理,但归档的版本长期保存
- 合规审计时,直接调归档

## 2.9 安全边界:3 道防线的整体设计

最后,我用一张图把本章讲的"安全边界"整体串起来——**3 道防线**:

```
         ┌─────────────────────────────┐
第 1 道 │  最小权限(默认不开放)        │
         │  • 角色 + 任务双层模型        │
         │  • 跨成员默认不开放           │
         └──────────────┬──────────────┘
                        ▼
         ┌─────────────────────────────┐
第 2 道 │  全程留痕(审计日志)          │
         │  • 所有读 / 写 / 派任务都记录 │
         │  • 180 天可查                 │
         │  • 每月抽查 5%               │
         └──────────────┬──────────────┘
                        ▼
         ┌─────────────────────────────┐
第 3 道 │  可回滚(二次确认)            │
         │  • 高风险操作必须二次确认     │
         │  • 二次确认前看清内容         │
         │  • 严重操作双人复核           │
         └─────────────────────────────┘
```

**3 道防线的逻辑**:
- **第 1 道防"误操作 + 越权"**——默认不开放,跨成员默认不可见
- **第 2 道防"隐蔽违规"**——即便有人绕过第 1 道,也会被记录
- **第 3 道防"严重后果"**——即便前 2 道被绕过,严重操作还要二次确认

**任何一道防线单独都不够**——必须 3 道同时启用。

## 2.11 小结

本章我们讲了远程协作的 5 件事:

1. **移动端协作**——把 WorkBuddy "伸出爪子",补位"管理者不在办公室"的场景;**不是替代本机,是延伸本机**。
2. **企业微信集成**——3 种形态(群机器人 / 自建应用 / 深度集成),适合不同规模团队;群机器人 5 分钟配置,自建应用 1-2 小时配置。
3. **飞书 / 钉钉集成**——配置逻辑和企业微信类似,选你团队在用的 IM,不要"为了 AI 换 IM"。
4. **团队授权**——"角色 + 任务"双层模型,3 种角色 + 4 个权限维度,跨成员访问默认不开放。
5. **安全边界**——3 道防线(最小权限 + 全程留痕 + 可回滚),SSO 单点登录,审计日志 180 天保留。

**关键判断**:
- 远程派任务"4 条黄金规则"——具体 / 授权 / 审 / 留痕
- 高风险操作"3 种二次确认方式"——桌面弹窗 / IM 推送 / 双人复核
- 团队授权"4 条原则"——默认不开放 / 读要留痕 / 写要二次确认 / 撤权要彻底

下一章(第 3 章)我们讲"团队工作目录与文件规范"——**当你 5-10 个人共用一个工作目录时,文件怎么组织、命名怎么规范、权限怎么分级、冲突怎么解决**。这件事没做好,远程协作的"基础"就不稳。
