## 三、团队工作目录与权限

**团队工作目录**
在 Workspace 基础上按"公共 / 个人 / 项目"三层划分。公共层放团队共享模板与制度文件,所有成员只读;个人层放个人草稿与笔记,他人不可见;项目层按具体项目隔离,跨项目不可见。三层通过权限矩阵统一管理,任何文件移动都需经管理员审批。常见误区:把客户合同直接放到公共层,导致外发风险——应放在项目层并配置"看 + 分享需审批"。

**命名规范**
项目层目录统一格式:`项目编号-日期-负责人`,例 `PRJ-2026-08-zhangsan`。日期取 YYYY-MM,负责人用工号或拼音首字母。便于检索、移交、年度归档。命名一旦确定,中途不得改名,改名会断链;若需变更,走"目录迁移"流程并保留旧名 90 天作为软链。

**权限矩阵**
三档操作:看(只读)、改(可写)、分享(可转发)。每条目录对每个成员独立授权,默认"看"。需要修改或外发时逐级提权,变更需留审计日志。易混点:"改"不含"分享",可写的成员仍需单独申请转发权限;反之"分享"权限的成员通常只读源文件,不会误改原文。

**团队 积分 池**
将成员个人 积分 汇总为团队资源池,统一调度。解决"有人用不完、有人不够用"的失衡,也便于项目级核算。计费仍按个人订阅档从各自账户扣,池内只是"配额转移"。

**总池 / 共享池 / 审批制**
三种管理模式,按团队成熟度递进。总池:全部成员共用一份,按需扣减,适合早期试点(2-10 人)。共享池:按部门或项目分小池,跨池调用需审批,适合中期(10-50 人)。审批制:大额调用需主管审批,适合敏感业务或固化阶段(50+ 人),通常配合明示审计。

## 四、推广方法论

**团队三阶段**
团队引入 WorkBuddy 分三阶段推进,每阶段约 30 天。试点:2-3 人,跑通 1-2 个高频场景,产出可复用模板。推广:覆盖 30%-50% 成员,沉淀模板与培训手册。固化:全员使用,纳入考核与日常流程。三阶段不可跳,试点未通过的团队强行推广会拉高反对声量,反而拖延整体进度。

**评估标准(试用 3 次)**
Skill 上线前,需在真实任务中试用至少 3 次。3 次都给出满意结果方可纳入推荐列表;低于 3 次视为"待验证",只在个人目录使用,不得进入公共层。3 次不必连续,但建议间隔一周以上,覆盖不同上下文,避免"恰好三次都对"的偶然性。

**Top 10 推荐 Skill**
按"使用频次 × 满意度 × 场景覆盖率"打分,从已验证 Skill 中选前十,放入公共层目录,作为新人首选。每季度复评一次,排名末尾 2 名自动降级。易混点:推荐列表不等于"最强大"Skill,只看"高满意度 + 高频次",某些长尾但关键场景的 Skill 反而进不了前十,需另设"必备 Skill"子目录补充。

**30 天培训手册**
按周分四阶段的学习路径。第 1 周:熟悉界面与基础 Skill,完成"3 个必做任务"清单。第 2 周:完成一个真实业务任务,产出工作记录。第 3 周:产出可复用模板,纳入团队目录。第 4 周:带教一位同事,沉淀带教笔记。手册不是 PPT,而是 checklist + 示例对话,新人在第 1 周结束前应能独立复现手册里的所有示例。

**L1 / L2 / L3 培训目标**
三级能力阶梯。L1:能独立完成基础任务,30 天达成,对应"会用人"。L2:能写提示词与配置 Skill,60 天达成,对应"会用工具"。L3:能教别人、做内部布道,90 天达成,对应"会造工具"。L3 才会被推荐为 Champion。

**内部布道师(Champion)**
团队中率先熟练使用、愿意分享经验的成员,通常占 10%-15%。承担答疑、案例收集、新人帮带。WorkBuddy 提供"Champion 徽章"作为系统标识,出现在其 Claw 与管理后台名单中。Champion 不是额外头衔,而是 L3 之后的自然延伸,不享受额外报酬,但可优先获得新功能试用权。

**三指标评估**
衡量推广效果的三个核心指标。日活率(DAU/总成员数)反映粘性,健康线 60%,低于此值说明多数人只是"尝鲜"。任务密度(人均日完成任务数)反映深度,健康线 ≥3,过低意味着只在做最简单操作。场景覆盖率(已用 Skill 数 / 应有 Skill 数)反映广度,健康线 70%,过低说明 Skill 市场未被有效利用。三指标任一低于阈值即触发复盘,先定位"日活低"还是"任务少"或"场景窄",再对症下药。

## 五、技能与专家

**技能市场(Skill Marketplace)**
WorkBuddy 内置的技能分发平台。官方与社区作者均可发布 Skill,带版本号、评分、下载量。团队管理员可一键安装到团队工作目录,也可禁用指定 Skill。安装前需核对权限声明,某些 Skill 会请求网络访问或文件写入,团队场景下建议只在隔离项目层试用。

**专家中心(Expert Hub)**
团队内部的"人才 + 经验"双索引。可按人查(谁擅长什么),也可按问题查(这类事找谁、参考哪份模板),降低重复咨询成本。专家中心的价值不在于"找人",而在于"找经验"——同事的可用时间有限,而他们沉淀的模板、提示词、复盘笔记可以无限复用。

**5 字段法**
专家经验录入模板的最小单元:`场景 → 操作 → 提示词 → 常见坑 → 适用边界`。少一字段视为不完整,不予收录;多则按需扩展为附录。常见误区:把"操作"写成"做什么"而非"怎么做",把"适用边界"漏掉导致被错误套用——5 字段法强制每个字段都有具体内容,本身就是质量过滤。

**专家保鲜**
防止"专家经验录入后失效"的机制。每条记录强制带版本日期、维护人、反馈通道。过期未更新自动降权,鼓励持续迭代。默认保鲜周期 90 天,超过未更新的记录从首页降级到"历史"区,但不删除——历史经验仍有价值,只是优先级降低。

## 七、审计与价值衡量

| 中文 | 英文 / 简释 | 出处 |
|---|---|---|
| 审计日志 | WorkBuddy 对所有任务调用、文件读写、积分 扣减的完整记录,可按成员、时间、Skill 检索,默认保留 180 天,合规场景可延长至 3 年。 | 第二卷 第 8 章 |
| 明示审计 | 成员被告知"操作会被记录"的审计模式,用于日常管理与复盘,起威慑与归因作用,新员工入职时口头+书面双重告知。 | 第二卷 第 8 章 |
| 暗箱审计 | 成员不知情时进行的抽样审计,用于合规检查与敏感岗位监督,需在团队制度中明确启用范围、抽样比例与触发条件,不可无限扩张。 | 第二卷 第 8 章 |

> 明示与暗箱不是"道德高下",而是"用途差异":前者重在预防,后者重在发现。两者并行不悖,但都需事先约定边界,临时启用容易引发信任危机。

**复合 ROI 公式**
第二卷用于衡量 WorkBuddy 投入产出比的统一公式:

```
ROI = (节省工时 × 时薪 + 业务增量收益 − 工具成本 − 培训成本) / (工具成本 + 培训成本)
```

分子覆盖可量化收益(工时、业务)与折算项(培训损耗、试错成本),分母为总投入。>1 即回本,>3 视为优秀。易混点:不要把"业务增量收益"无限放大,本卷建议取保守值——若实际增量难以归因,默认填 0,让工时节省独自支撑 ROI,可避免事后被审计质疑。

## 八、Claw 远程与移动场景

**Claw 远程控制**
在非 WorkBuddy 主机(如客户电脑、家庭笔记本)上,通过已登录的 Claw 实例接管任务。主控端可继续编辑文件、调用 Skill,数据流经云端加密通道,原端只做渲染。延迟通常在 200ms 以内,适合文本类任务;高强度本地操作(如大型文件编译)仍建议回主控端完成。

**Claw 出差场景**
出差或通勤时,手机端 Claw 接管办公室电脑的待办:读邮件、改文档、回消息。回办公室后无缝继续,不丢上下文,适合 1-3 天短差。易混点:这不是"用手机跑模型",而是"用手机当主控端,办公室电脑执行"——模型推理仍在办公室主机,流量与计算压力不转移到手机网络。长差(>3 天)建议改用云端实例,避免办公室电脑长时间开机带来的安全与能耗问题。

## 九、易混淆对照

把第二卷中容易混淆的术语放在一起对比,降低查阅成本。

| 易混项 A | 易混项 B | 关键区分 |
|---|---|---|
| 工作目录(Workspace) | 团队工作目录 | 前者是单人在 WorkBuddy 内配置的文件夹,后者是团队三层(公共/个人/项目)结构,前者可被后者包含。 |
| Claw | Claw 远程控制 | 前者是桌面端浮动工具本身(第一卷),后者是该工具的远程接管能力(第二卷新增),所有 Claw 实例默认具备远程能力,需主动开启。 |
| 技能市场(Skill Marketplace) | 团队工作目录 | 前者是公开分发平台,任何人都能下载;后者是团队内部命名空间,只有团队成员可见,管理员控制进出。 |
| 专家中心(Expert Hub) | Top 10 推荐 Skill | 前者是"人 + 经验"双索引,后者是技能列表;两者可联动——Top 10 中某些 Skill 的维护人就是专家中心里的对应专家。 |
| 审计日志 | 明示审计 | 前者是技术产物(记录),后者是制度(模式);明示审计必然产生审计日志,但审计日志不一定是明示审计下产生(也可能是暗箱)。 |
| 团队 积分 池(总池) | 团队 积分 池(共享池) | 同名不同模式,前者全团队共用一份,后者按部门分小池;切换时需重新做一次配额盘点,不要在切换中保留旧池余额。 |
| 复合 ROI 公式 | 单点节省工时 | 前者分母包含培训与工具成本,后者只算"工时 × 时薪";简单算式会高估 ROI,把培训沉没成本摊进去才能反映真实投入。 |
