# 附录 C 团队场景提示词模板集

> 12 个团队协作场景的提示词模板,延续卷 1 的三件套(背景 Context / 任务 Task / 约束 Constraint),新增"角色 / 敏感信息 / 团队风格"适配多人协作的复杂度。把 `{{}}` 占位符替换为你的真实信息即可使用。
>
> 截至 2026-08-16 · 适用 WorkBuddy v2.3+

---

## 使用约定

三条边界,先说清楚。

**第一,模板是起点,不是终点。** WorkBuddy 生成的初稿需由团队负责人复核后再对外发布,涉外模板(跨部门邮件、客户回访、客户案例)尤其重要。

**第二,敏感信息脱敏后再输入。** 客户身份证号、内部薪酬、未公开财务、员工私人信息粘贴前应做脱敏(把"张三"替换为"员工 A","¥1,250,000"替换为"百万级")。

**第三,团队规模 3-30 人效果最佳。** 模板按中型团队设计,规模差异较大时参考每节末的"改造提示"。

---

## 模板 1:团队周报汇总

### 适用场景

每周五下午,部门负责人把团队成员各自的周报汇总为部门周报,用于向上汇报或跨部门同步。

### 完整提示词

```text
# 背景 Context
你是部门助理。我所在部门是【{{部门名称}}】,本周日期范围是【{{起止日期}}】。
下面是 {{N}} 位团队成员的本周个人周报,每段以"### {{姓名}}"开头:
{{粘贴个人周报原文}}

# 任务 Task
汇总为部门周报,包含:
1. 本周完成(按业务线/项目归类,不逐人罗列)。
2. 下周计划(每个计划项注明负责人)。
3. 风险与求助(需上级或跨部门支持的事项)。
4. 跨部门协作(涉及其他部门的事项单列)。

# 约束 Constraint
- 总字数控制在 {{字数上限}} 字以内。
- 保留每位成员关键贡献,表述上做合并。
- 模糊或冲突的表述标"待确认",不替成员承诺。
- 营收、利润等未公开数据用【需脱敏】占位。
```

### 预期输出示例

```text
# 部门周报 · {{部门名称}} · {{日期}}

## 本周完成
- 产品线 A 完成 v2.1 上线,日活提升 12%
- 客户线 B 签约 3 家,合计合同额【需脱敏】
- 内部优化:周会时长从 90 分钟压缩至 45 分钟

## 下周计划
- 产品线 A:启动 v2.2 需求评审(负责人:{{姓名}})

## 风险与求助
- 研发资源紧张,v2.2 排期可能延后一周,需 CTO 借调

## 跨部门协作
- 与市场部联合筹备秋季发布会(下周三对齐)
```

### 改造提示

5 人以下按人合并,30 人以上按业务线。营收、客户名等敏感字段提前替换为占位符。

## 模板 2:团队周会纪要

### 适用场景

周会或临时会议结束后,把录音转写文本喂给 WorkBuddy,生成结构化会议纪要,自动分发到与会者与缺席者。

### 完整提示词

```text
# 背景 Context
会议主题:【{{会议名称}}】
时间:{{日期与时段}}
参与者:{{列出姓名或角色}}
会议记录来源:{{录音转写 / 速记 / 笔记}}
{{粘贴会议原文}}

# 任务 Task
生成结构化会议纪要,包含:
1. 会议结论(已达成共识的决策,不超过 5 条)。
2. 行动项(每条含负责人、截止时间、可验收标准)。
3. 待议事项(本次未达成共识、需下次继续讨论)。
4. 信息同步(与决策相关但不属于决策的背景信息)。

# 约束 Constraint
- 行动项必须含 owner + due date,缺一不可。
- 争议性结论标"待复核"并说明争议点。
- 不替未参会者承诺任务。
- 全文 Markdown 列表,避免大段散文。
```

### 预期输出示例

```text
# 会议纪要 · {{会议名称}} · {{日期}}

## 会议结论
1. Q3 OKR 维持原定 3 项,不再追加
2. 远程办公制度延续至年底,每周到岗 2 天

## 行动项
- [ ] {{姓名}}:完成客户分级标准文档,due {{日期}}
- [ ] {{姓名}}:远程办公系统权限开通,due {{日期}}

## 待议事项
- 部门年度预算分配,需财务数据,推至下周一。
```

### 改造提示

若转写自 Otter、飞书妙记,需说明时间戳格式。站会类只保留行动项,战略复盘加"管理层共识"小节。"信息同步"段落单独发给未参会者。

## 模板 3:新人 onboarding 文档

### 适用场景

新员工入职前 3 天,由 HR 或部门助理汇总老员工经验贴、过往 FAQ,生成岗位入职第一周指南。

### 完整提示词

```text
# 背景 Context
新员工岗位:{{岗位名称}}
所在团队:{{团队名称}}
入职日期:{{日期}}
{{N}} 份老员工经验贴(已脱敏):
{{粘贴经验贴原文或要点}}

# 任务 Task
生成"入职第一周指南",包含:
1. 第一天:报到流程、账号开通、必装软件。
2. 第 2-3 天:必读文档、必见的人、必参加的会议。
3. 第 4-5 天:第一个小任务(可独立完成、产出可见)。
4. 避坑清单:老员工踩过的 3-5 个坑。
5. 师傅与求助渠道:谁负责带你、紧急情况找谁。

# 约束 Constraint
- 必须包含师傅联系方式(工位、微信/钉钉、工号)。
- 内部链接脱敏或占位,如"内部 wiki:/onboarding/{{部门}}"。
- 专业术语首次出现给一句话解释。
- 语言简洁,鼓励主动提问,不要恐吓式表达。
```

### 预期输出示例

```text
# {{岗位名称}} · 入职第一周指南

## 第一天
- 09:00 到 {{地址}},找 {{HR 姓名}} 报到
- 领取工卡,开通企业邮箱、OA、WorkBuddy
- 必装:Slack/钉钉、企业微信、VPN

## 第 2-3 天
- 必读:《{{部门}} 业务白皮书》《{{系统}} 操作手册》
- 必见:{{师傅姓名}}、{{姓名}}、{{姓名}}

## 第 4-5 天
- 小任务:在沙箱跑通 {{流程名}},产出 demo 截图

## 避坑清单
1. 不要用个人微信传工作文件,改用企业网盘
2. 客户数据下载需走审批,不要直接拷贝到本地

## 师傅与求助
- 师傅:{{姓名}}(微信:workbuddy-{{简拼}})
- 紧急 IT:分机 {{号码}}
```

### 改造提示

无现成经验贴时,先做 30 分钟师傅访谈再喂模板。远程入职把"第一天"改为"第一周线上流程"。校招版加"团建安排",社招版加"前任交接"。

## 模板 4:客户回访提醒

### 适用场景

销售或客户成功岗位,系统提示需要回访客户时,自动生成回访话术、议程和风险点提示。

### 完整提示词

```text
# 背景 Context
客户名称(已脱敏):【{{代号,如"客户 A"}}】
客户行业:{{行业}}
上次接触时间:{{日期}}
当前阶段:{{新签 / 续约 / 增购 / 投诉处理 / 例行回访}}
历史沟通要点:
{{粘贴历史沟通记录或客户档案摘要}}

# 任务 Task
生成回访准备包,包含:
1. 开场白(30 秒内建立信任,不突兀)。
2. 议程(3-5 个讨论点,每个点预计时长)。
3. 关键问题(本阶段最需确认的 2-3 个问题)。
4. 风险点(可能引发客户不满的话题及应对话术)。
5. 后续动作(回访后何时跟进、跟进什么)。

# 约束 Constraint
- 不承诺价格、折扣、工期等敏感信息,只说"内部评估后回复"。
- 话术符合公司合规要求,引用《客户沟通红线手册》对应条款。
- 提示本次通话会被录音,并征得客户同意。
- 客户隐私字段(身份证、银行卡、住址)一律不出现。
```

### 预期输出示例

```text
# 客户 A 回访准备包 · {{日期}}

## 开场白
"{{客户 A}} 老师您好,我是 {{公司}} 的 {{姓名}},上次在 {{时间}} 沟通过 {{主题}}。今天花 10 分钟同步进展。"

## 议程(15 分钟)
1. 上次需求落地(3 分钟) 2. 当前卡点(5 分钟) 3. Q4 是否增购 {{模块}}(5 分钟)

## 关键问题
- {{功能}} 活跃度是否符合预期?是否在评估其他竞品?

## 风险点与应对
- 客户提竞品报价:不直接比价,引导到价值;客户投诉:先共情,再记工单。

## 后续动作
- 当天发纪要,48h 内确认下一步。
```

### 改造提示

B2B 强调决策链,B2C 强调使用体验。投诉处理在开场白后加"情绪安抚"段落。批量回访可一次喂入 N 份档案生成 N 份准备包。

## 模板 5:会议预约协调

### 适用场景

3-8 人参与的会议,各自日程分散,人工比对照常耗时。让 WorkBuddy 读取(或粘贴)各人空闲时段,推荐公共时间。

### 完整提示词

```text
# 背景 Context
会议主题:【{{主题}}】
预计时长:{{分钟数}}
必须到场:{{姓名列表}}A 类必到。
优先到场:{{姓名列表}}B 类优先,缺席需事后同步。
{{N}} 位与会者空闲时段(已转换为我所在时区 {{时区}}):
{{粘贴日历或空闲时段表}}

# 任务 Task
找出 3 个可行时段并给出推荐:
1. 列出每个时段的必到人员出席率。
2. 标注该时段是否有冲突会议相邻(避免赶场)。
3. 给出推荐时段(综合出席率、相邻会议、个人偏好)。
4. 提供预约邮件草稿。

# 约束 Constraint
- 不暴露任何与会者的会议内容,只暴露时段。
- 所有时间标注时区,跨时区同事单独标注其本地时间。
- 提前至少 {{N}} 小时发送,避免临时打扰。
- 24 小时内无解时,提示"需放弃部分必到人员"。
```

### 预期输出示例

```text
# {{主题}} · 可行时段(2026-08-16 至 2026-08-22)

| 时段(本地) | 必到出席 | 优先 | 备注 |
|---|---|---|---|
| 周二 14:00-15:00 | 5/5 | 2/3 | 推荐 |
| 周三 10:00-11:00 | 4/5 | 3/3 | {{姓名}} 缺席 |
| 周四 16:00-17:00 | 5/5 | 2/3 | 与周会相邻 |

## 推荐:周二 14:00-15:00
全部必到出席,2 位优先人员有空,不与既有会议冲突。

## 预约邮件草稿
主题:{{主题}}会议邀请(周二 14:00)
正文:各位好,本周需就 {{议题}} 对齐,推荐周二 14:00-15:00。如冲突请回复替代时段。
```

### 改造提示

WorkBuddy 默认需日历只读权限,无权限时手动粘贴 3 天空闲时段。跨时区把"我所在时区"改为 UTC,结果中标注每个人本地时间。周例会保存首次推荐结果后不再重复协调。

## 模板 6:团队技能地图盘点

### 适用场景

季度或半年度,部门负责人盘点团队成员的 WorkBuddy 使用习惯与产出质量,作为培训计划、岗位调整依据。

### 完整提示词

```text
# 背景 Context
部门:{{部门名称}}
盘点周期:{{起止日期}}
团队花名册(已脱敏):{{姓名、岗位、入职时间}}
本季度 OKR:{{粘贴}}
本周期 WorkBuddy 使用日志(已脱敏,仅含频次、常用功能、典型任务):
{{粘贴日志摘要}}

# 任务 Task
生成团队技能图谱,包含:
1. 整体分布:熟练 / 一般 / 待提升 三档人数比例。
2. 核心能力维度:文档协作、数据分析、提示词工程、流程自动化、客户沟通。
3. 个人亮点与短板(已脱敏,只标 {{代号}})。
4. 培训建议:本季度优先开展的 2-3 个内训主题。
5. 风险预警:关键技能集中于 1-2 人时的断点风险。

# 约束 Constraint
- 评估基于工作产出,而非聊天频率。
- 涉及个人绩效的表述需脱敏,只标能力维度。
- 不公开点名"差",只标"待提升"。
- 结论可对外,原始数据仅限部门负责人。
```

### 预期输出示例

```text
# {{部门名称}} · 技能图谱 · {{季度}}

## 整体分布
- 熟练 30%、一般 50%、待提升 20%

## 核心能力维度

| 能力 | 熟练 | 一般 | 待提升 |
|---|---|---|---|
| 文档协作 | 7 | 2 | 1 |
| 数据分析 | 3 | 4 | 3 |
| 提示词工程 | 4 | 4 | 2 |
| 流程自动化 | 2 | 3 | 5 |

## 培训建议
- 提示词工程实战(2h);数据分析 × WorkBuddy 集成(3h,跨部门合办);流程自动化进阶(0.5d)

## 风险预警
- 流程自动化仅 {{代号 A}}{{代号 B}} 两人熟练,存在断点。
```

### 改造提示

3-5 人时直接按人列表;30 人以上按小组拆分,先做小组图谱再合并。对外时把"代号"替换为"团队成员"。

## 模板 7:跨部门协作邮件

### 适用场景

给非本部门同事(尤其高管或平级部门负责人)发正式邮件,讨论资源协调、问题反馈、项目合作时,降低沟通摩擦。

### 完整提示词

```text
# 背景 Context
本部门:【{{我方部门}}】
对方部门:【{{对方部门}}】,收件人 {{姓名 / 职务}}
沟通主题:{{一句话主题}}
过去 6 个月沟通记录摘要:{{粘贴过往沟通要点}}
本次诉求:{{我方希望对方做什么}}

# 任务 Task
写一封正式协作邮件,包含:
1. 主题行(15 字以内,清晰传达意图)。
2. 开头(1-2 句共情或肯定,避免直接进入诉求)。
3. 背景(为什么重要,目前状态)。
4. 诉求(具体要对方做什么,给出可选项)。
5. 价值(对对方部门的收益,双赢视角)。
6. 时间窗口(希望何时回复、落地)。
7. 落款(礼貌但平等,不卑不亢)。

# 约束 Constraint
- 避免"应该"、"必须"、"请务必"等命令式语气。
- 全文不超过 300 字,高管邮件不超过 150 字。
- CC 双方部门负责人,信息对称。
- 不公开指责对方过去失误,只描述当前事实。
```

### 预期输出示例

```text
主题:关于 {{项目}} 资源协调的沟通(本周三前回复)

{{对方姓名}} 你好,

注意到 {{项目}} 当前在 {{节点}} 遇到资源紧张,过去几周两部门配合顺畅(感谢 {{对方同事}} 的支持)。

为不影响 {{日期}} 发布,希望 {{具体诉求}} 获得 {{对方部门}} 支持。方案两个:
A. 借调 {{资源类型}},为期 2 周。
B. 联合评审,优先保障 {{关键模块}}。

两种方案对 {{对方部门}} 都有价值:前者分担 {{对方痛点}},后者提前介入降低返工。

如能在周三前回复,我们即可启动下一步;时间紧张也可电话 15 分钟。

{{我方姓名}}
{{我方部门}} · {{联系方式}}
```

### 改造提示

"时间窗口"显式标注(如"本周三 18:00 前")降低拖延概率。历史摩擦场景把"背景"拉长,先共情再提诉求。外部客户语气更正式,去掉内部梗。

## 模板 8:团队 OKR 复盘

### 适用场景

OKR 周期中(年中、季末),把团队周报、产出记录、风险事件汇总,生成 OKR 进度复盘报告。

### 完整提示词

```text
# 背景 Context
团队 OKR:{{粘贴本周期 OKR 原文}}
本周期周报与关键产出:{{粘贴}}
本周期风险事件:{{粘贴}}

# 任务 Task
生成 OKR 复盘报告,包含:
1. 进度评分:每个 KR 给出 0-100% 完成度。
2. 信心指数:年底完成情况 1-5 分(1=几乎不可能,5=非常确定)。
3. 复盘原因:得分低于 70% 的 KR,分析根因(人/流程/资源/外部)。
4. 调整建议:继续 / 修订 / 放弃,以及对应方案。
5. 经验沉淀:本周期最值得复用的 1-2 个做法。

# 约束 Constraint
- 信心指数必须附依据(数据 + 主观判断),不允许空打分。
- 不夸大,允许主动暴露问题。
- 调整建议需说明"调整后 KR 是否可衡量"。
- 报告用于内部 review,可点名但避免人身评价。
```

### 预期输出示例

```text
# 团队 OKR 复盘 · {{周期}}

## KR1:{{原文}}
- 完成度 80%,信心 4/5(Q3 数据已超目标 110%)。

## KR2:{{原文}}
- 完成度 45%,信心 2/5(依赖外部审批,卡 3 周)。
- 根因:外部流程不在我方控制。
- 调整:修订为"通过终审",降低依赖。

## KR3:{{原文}}
- 完成度 30%,信心 1/5,根因:关键人员 9 月离职。
- 调整:放弃,本周期不可控。

## 经验沉淀
- 周节奏 + 月度复盘的双层机制有效;跨部门依赖型 KR 需在 O 阶段锁定对接人。
```

### 改造提示

增长类 KR 用数据,体验类用 NPS/CSAT,产品类用上线节点。公司有固定模板时,在"任务"中追加"对齐 {{模板名}} 输出格式"。跨部门 OKR 在每条 KR 下加"关联方进度"小节。

## 模板 9:部门预算申请

### 适用场景

新财年或新项目立项前,部门负责人从历史数据、业务计划、上级要求,生成可提交给财务或高管的预算申请报告。

### 完整提示词

```text
# 背景 Context
部门:【{{部门名称}}】
申请周期:【{{财年或季度}}】
历史预算与执行(过去 {{N}} 期):{{粘贴}}
本周期业务计划与人员规划:{{粘贴}}
上级或公司对部门定位与要求:{{粘贴}}

# 任务 Task
生成预算申请报告,包含:
1. 申请总金额与同比变化。
2. 分类明细:人力、工具、差旅、培训、外包、其他。
3. 必要性:每类支出对应的业务目标。
4. ROI 估算:对核心项目给出投入产出比或回收周期。
5. 风险预案:若审批砍预算,哪些项目优先保留。
6. 审批路径:节点与责任人。

# 约束 Constraint
- 数据来源标注(如"来自财务系统 2025-12 报表")。
- 单项支出超 {{阈值}} 需附独立方案。
- 薪酬、股权等敏感字段脱敏。
- 不用"必须批"、"否则影响"等威胁式表述。
```

### 预期输出示例

```text
# {{部门名称}} · {{财年}} 预算申请

## 总览
- 申请总额【{{金额}}】(同比 +15%),主因:业务扩张 + 工具升级。

## 分类明细

| 类别 | 金额 | 同比 | 业务目标 |
|---|---|---|---|
| 人力 | 【需脱敏】 | +20% | 团队 10 扩至 12 |
| 工具 | ¥120,000 | +50% | 团队版 + BI |
| 培训 | ¥80,000 | 0% | 内训 4 次 |
| 差旅 | ¥200,000 | -10% | 控制非必要出差 |

## ROI
- 工具 ¥120,000,节省 0.5 人/年,回收 6 个月;培训 ¥80,000,人效 +8%,年增收约 ¥400,000。

## 风险预案
- 砍 30%:保留人力,延后工具;砍 50%:保留核心人力,其余冻结。

## 审批路径
- 部门负责人 → CFO → CEO(> ¥500,000 需董事会)
```

### 改造提示

创业公司可省"审批路径"段落,集团企业细化到子部门。ZBB 预算把"分类明细"改为"项目 - 投入 - 必要性 - 替代方案"。"风险预案"作为与上级单独沟通的材料。

## 模板 10:团队公告草稿

### 适用场景

部门或团队内部需要发布正式公告(制度更新、人事变动、流程上线、活动通知)时,用公司口吻起草,确保语气统一。

### 完整提示词

```text
# 背景 Context
公告主题:【{{主题}}】
发布范围:{{部门 / 全公司 / 特定小组}}
公司或部门口径要求:{{例如"严谨、克制、不夸张"}}
目标读者:{{员工类型}}
背景信息:{{粘贴}}

# 任务 Task
撰写一则正式公告,包含:
1. 标题(不超过 20 字,清晰无歧义)。
2. 正文要点(不超过 5 条,每条不超过 50 字)。
3. 生效时间(具体到日期)。
4. 适用范围(谁适用、有无例外)。
5. 答疑渠道(有疑问找谁)。
6. 版本号与日期(便于追溯)。

# 约束 Constraint
- 符合企业正式语气,不用网络用语、不用感叹号。
- 不夹带个人观点,不写"小编认为"。
- 人事变动需脱敏(候选人代号、岗位代号)。
- 涉密内容标"内部公开",不向群外扩散。
```

### 预期输出示例

```text
# 公告:远程办公制度更新(2026 年 9 月 1 日起生效)

各位同事:

经公司管理层研究决定,自 2026 年 9 月 1 日起,远程办公制度调整如下:

1. 每周到岗 2 天(原 3 天),周二、周四为推荐到岗日
2. 跨部门会议如需线下,优先安排在周二、周四
3. 国际差旅不受本制度约束,另行审批
4. 试用期员工首月到岗 5 天,后续按本制度执行
5. 因特殊原因需长期远程,需直属上级与 HR 双签

如有疑问,联系 HRBP {{姓名}}。

公告版本:v2.1 · 发布日期:2026-08-16
适用范围:全体员工(子公司另行通知)
```

### 改造提示

制度类强调"生效 + 例外",活动类"时间 + 报名",人事类"过渡期 + 答疑"。跨境团队需英文版时,让 WorkBuddy 同提示词下输出中英双语。每次修改后追加 v1.1、v1.2 便于追溯。

## 模板 11:客户案例整理

### 适用场景

销售或市场部门,把多个销售/服务记录中的真实案例整理为可对外分享的标准化案例,用于官网、招商材料、行业演讲。

### 完整提示词

```text
# 背景 Context
行业:{{行业}}
客户类型:{{SMB / 中型 / 大型}}
{{N}} 份销售或服务记录(已脱敏,客户名替换为 {{代号}}):
{{粘贴}}

# 任务 Task
整理为 1 个可对外分享的客户案例,结构如下:
1. 客户背景(行业、规模、核心痛点)。
2. 挑战(引入前的具体问题)。
3. 方案(提供了什么、实施周期、关键里程碑)。
4. 效果(2-3 个可量化指标)。
5. 客户证言(1-2 句可直接引用,无原话标注"示意")。
6. 适配建议(最适配哪类潜在客户)。

# 约束 Constraint
- 客户信息全部脱敏,真实数据需书面授权。
- 量化数据来源可溯源,如"客户季度复盘会披露"。
- 客户证言无原话时标"示意文案"或留空。
- 不夸大、不绝对化,不用"完美解决"、"彻底改变"。
- 引用前再次确认授权状态,标注"已授权 / 待授权"。
```

### 预期输出示例

```text
# 客户案例 · {{行业代号 A}}

## 客户背景
- 行业:跨境电商;规模:中型(50-200 人);痛点:多平台协同成本高,客服响应慢。

## 挑战
- 4 个平台运营,日均工单 800+,平均响应 45 分钟。

## 方案
- 部署 WorkBuddy 团队版,接入统一工单中心;2 周上线、4 周全员培训。

## 效果
- 平均响应:45 → 12 分钟(↓ 73%);客服人均处理量 +40%;NPS:32 → 58。

## 客户证言(示意,待授权)
"用了 WorkBuddy 之后,客服终于不用再手动切 4 个后台了。" — 客户 A 客服总监

## 适配建议
最适配:多平台运营、客服 ≥ 20 人、追求提效的电商与新零售。
```

### 改造提示

所有"证言"公开发布前必须拿到客户书面授权。一次喂入 5-10 份记录可生成 3-5 个案例矩阵。B2B 重 ROI 与流程,B2C 重体验,政企重合规。

## 模板 12:培训反馈调研

### 适用场景

内训或外训结束后,自动生成调研问卷,评估培训效果、收集改进建议、规划后续主题。

### 完整提示词

```text
# 背景 Context
培训主题:【{{主题}}】
培训日期:{{日期}}
参训人员:{{人数、岗位类型}}
培训内容大纲:{{粘贴}}
讲师:{{讲师姓名 / 简介}}

# 任务 Task
生成培训反馈调研问卷,包含:
1. 基本信息(可匿名):岗位、参训年限、是否首次参加。
2. 培训内容评价(5 题):清晰度、深度、实用性、案例、节奏。
3. 讲师评价(3 题):专业度、表达、互动。
4. 收获与建议(开放式,不超过 2 题)。
5. 后续需求(可选):希望的下一次主题。

# 约束 Constraint
- 总题数不超过 10 题。
- 开放式问题不超过 3 题,每题预留 100 字以内。
- 评分题统一使用 5 级量表(1-5 分)。
- 默认匿名,统计时去除可识别字段。
- 问卷末尾留 1 个"其他建议"开放式题作为兜底。
```

### 预期输出示例

```text
# 培训反馈调研 · {{主题}} · {{日期}}
(本问卷匿名,预计耗时 3 分钟)

## 基本信息
1. 岗位类型:[ ] 研发 [ ] 产品 [ ] 运营 [ ] 市场 [ ] 销售 [ ] 其他 ____
2. 参训年限:[ ] < 1 年 [ ] 1-3 年 [ ] 3-5 年 [ ] > 5 年

## 培训内容(1=非常不满意,5=非常满意)
3. 内容清晰度:1 2 3 4 5
4. 内容深度:1 2 3 4 5
5. 实用性:1 2 3 4 5
6. 案例丰富度:1 2 3 4 5
7. 节奏控制:1 2 3 4 5

## 讲师评价
8. 专业度 / 表达清晰 / 互动充分:分别 1-5 分

## 收获与建议
11. 本次培训最大的收获?(100 字内)
12. 希望下一次培训的主题?(选填)

## 其他
13. 任何其他建议(选填)
```

### 改造提示

外训增加"对工作应用的迁移度"题,内训增加"与本部门业务的结合度"题。问卷收集后自动汇总到部门周会。培训结束 30 分钟内发出,附"完成即领资料包"激励,回收率通常可超 80%。

## 模板的共性改造思路

把这 12 个模板放在一起看,有三条共性改造线索。

**第一,占位符的颗粒度。** 所有 `{{}}` 按"团队级"颗粒度设计。若团队内部口径不一致(如"客户分级"各人有自己的叫法),先在团队内统一术语再喂模板,效果最好。

**第二,提示词的版本管理。** 模板应与公司制度同步更新;制度或流程调整后,先改模板再发公告,避免"先通知后改工具"。

**第三,人工复核不可省。** 模板是节省时间的起点,不是终点。任何对外发布的产物(邮件、公告、案例)必须由负责人复核,涉外交付物尤其重要。

持续用、持续改,团队沟通的摩擦在一两个季度内会明显下降。
