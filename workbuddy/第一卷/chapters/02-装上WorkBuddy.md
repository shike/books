# 第 2 章 装上 WorkBuddy

## 本章要点

- WorkBuddy 的安装并不复杂,但有 3 个关键决策会决定你后续使用的安全边界和效率
- 下载:从官方渠道 codebuddy.cn/work 获取安装包,Windows 版在线安装器约 8 MB、离线完整包约 480 MB,macOS 版类似。第三方下载站可能捆绑木马或植入后门
- 登录:微信扫码适合个人,企业微信适合团队,手机号作为兜底。三种方式影响后续的 Claw(WorkBuddy 远程控制功能,详见第二卷第 2 章)、技能市场等能力
- 文件夹授权:这是最关键的一步。建议建立独立工作目录(如 `D:\WorkBuddy_workspace`),只授权这一个目录,不要授权"桌面/文档/下载"
- 首次启动的四个常见问题:macOS 14+ "无法验证开发者"、Windows Defender 弹窗、启动卡顿、安装完成后的握手测试
- 本章是实践章。读完并完成操作,你就有了一个真正"能用"的 WorkBuddy

## 开篇

装一个软件,有什么难的?

对绝大多数桌面应用来说,装上确实不难——双击安装包,几次"下一步",完事。但 WorkBuddy 不一样。它不是装上就完事的"聊天软件",它是要"动手"处理你工作目录的"代理人"。

"代理人"意味着它能读你的文件、改你的文件、生成文件、调用系统工具。这种"权限"是把双刃剑:

- 用得好,WorkBuddy 是你每天节省 2 小时的助理
- 用得不好,WorkBuddy 可能误读你桌面上的文件,把客户合同摘要错发给同事

第 1 章讲了"为什么需要桌面 AI"。这一章,我们讲"怎么装上它,但不被它坑"。

整个安装过程大概 5-10 分钟。其中 90% 的步骤,跟装其他桌面应用没有区别。但其中有 3 个关键决策,会决定你后续 6-12 个月的体验:

- **下载渠道**:官方 vs 第三方
- **登录方式**:个人微信 vs 企业微信 vs 手机号
- **工作目录**:全盘授权 vs 单一目录授权

我会带你按顺序过完每一步,在每个关键决策点停下来,告诉你"为什么这里要小心"。

本章是实践章。建议你边读边操作,装上 WorkBuddy。如果你的电脑不在手边,也建议把整章读一遍,理解三个关键决策的逻辑,等到能装的时候一次性完成。

让我们开始。

## 一、下载与安装

### 1.1 找到官方下载渠道

WorkBuddy 的官方网站是 **codebuddy.cn/work**。打开后,网站会根据你的操作系统自动推送对应版本的安装包。

![WorkBuddy 官网首页,顶部"下载 WorkBuddy"按钮](figures/1.2.1-website-hero.png)

*图 1.2.1 WorkBuddy 官网首页,顶部"下载 WorkBuddy"按钮*

**这是下载的推荐渠道**(也是最安全的渠道)。

为什么不推荐第三方下载站(比如某些下载工具捆绑的"高速下载")?三个原因:

**第一,版本不可控**。WorkBuddy 迭代较快(目前 5 个月一版),第三方下载站常常滞后,可能给你装的是 3 个月前的旧版,缺失最新功能和安全补丁。

**第二,安全风险**。第三方下载站的"高速下载器"经常捆绑其他软件——你本来想装 WorkBuddy,结果装了一堆"看图王"、"压缩软件"、"浏览器插件"。这些捆绑软件不一定有害,但会拖慢系统、占用资源,有些还会收集你的浏览数据。

**第三,签名问题**。WorkBuddy 安装包经过官方数字签名,确保"这个文件确实是 WorkBuddy 团队发布的"。第三方下载站的安装包可能没有签名,或者签名被篡改,你装的东西是不是官方版本,无法验证。

所以,无论别人怎么推荐,无论下载站怎么宣传"官方正版",**只从 codebuddy.cn/work 下载**。

### 1.2 Windows 版安装

下载完成后,根据你选择的是在线安装器还是离线完整包,会得到一个 `WorkBuddy-Setup-x.x.x.exe`(约 8 MB)或 `WorkBuddy-x.x.x-full.exe`(约 480 MB)的文件。

![下载完成后的 WorkBuddySetup.exe 文件,Windows 资源管理器中显示](figures/1.2.2-windows-installer.png)

*图 1.2.2 下载完成后的 WorkBuddySetup.exe 文件,Windows 资源管理器中显示*

双击 exe 文件,按引导完成安装。整个过程通常包括:

1. **选择安装位置**:默认是 `C:\Program Files\WorkBuddy\`。**这里有一个选择**——
   - 默认(C 盘):省事,但占用系统盘空间
   - 自定义(改 D 盘):给系统盘减负,但要注意权限问题(下文会讲)
   
   建议保持默认。除非你的 C 盘空间紧张(小于 50 GB 剩余),否则没必要改路径。

2. **同意用户协议**:阅读并同意。注意第 3 条通常会说明"AI 处理数据的方式",建议你读一下。

3. **等待安装完成**:通常 30-90 秒。

4. **选择"立即启动"或"稍后启动"**:建议选"立即启动",直接进入首次配置流程。

### 1.3 macOS 版安装

macOS 版的下载文件是 `.dmg` 格式(约 480 MB 的完整包)。双击挂载 dmg,会出现一个窗口,里面有 WorkBuddy 图标和 Applications 文件夹的快捷方式。

![macOS 拖拽安装界面,左侧 Applications 目标文件夹](figures/1.2.3-macos-drag-install.png)

*图 1.2.3 macOS 拖拽安装界面,左侧 Applications 目标文件夹*

把 WorkBuddy 图标拖到 Applications 文件夹,等待几秒,安装完成。

macOS 安装的"拖拽"动作背后,实际是把 WorkBuddy 复制到 `/Applications/` 目录。这与 Windows 的"安装程序"逻辑不同——macOS 应用通常是"自包含"的文件夹,不需要复杂的注册表写入。

**一个常见误区**:不要试图在 dmg 挂载状态下直接运行 WorkBuddy。有些用户会双击 dmg 里的 WorkBuddy 图标直接运行,这在 macOS 上是允许的,但**只在挂载状态下工作**——一旦你弹出 dmg,WorkBuddy 就会"消失"。正确做法是拖到 Applications 后,在 Applications 里运行。

### 1.4 Linux 版安装(简版)

WorkBuddy 同样提供 Linux 桌面版,适合开发、科研、企业内网等场景。Linux 版的安装流程与 Windows / macOS 有差异(发行版较多、命令行为主),详细说明放在附录 A.4。这里只给一个"够用"的指引:

- **Debian / Ubuntu 系**:下载 `.deb` 包,执行 `sudo dpkg -i workbuddy_x.x.x_amd64.deb`,如缺依赖再 `sudo apt-get install -f` 自动补齐。
- **Red Hat / Fedora 系**:下载 `.rpm` 包,执行 `sudo rpm -ivh workbuddy-x.x.x.x86_64.rpm`。
- **通用便携**:下载 `.AppImage` 文件,`chmod +x` 后直接运行,无需安装。

Linux 版的图形界面、Skills、Credits 等核心功能与 Windows / macOS 一致,只是安装方式不同。如果你是 Linux 用户,装好后可直接跳到第二节(登录方式)继续。Linux 版的"首次启动卡点"基本被发行版的包管理机制吸收,Windows / macOS 常见的 5.x 几个问题在 Linux 上极少出现。

### 1.5 安装过程的常见卡点

大多数情况下,WorkBuddy 的安装会顺利完成。但有几个常见的卡点值得提前知道:

**卡点 1:杀毒软件拦截**
部分 Windows 杀软(包括 Windows Defender、360、腾讯管家)会拦截未知来源的安装包,弹出警告。处理方法:
- Windows Defender:弹窗"是否允许此应用对设备进行更改",点"是"
- 360:在"信任列表"中添加 WorkBuddy
- 腾讯管家:同 360

**卡点 2:旧版本残留**
如果你之前装过 WorkBuddy 的测试版或老版本,新版本可能装不上。处理方法:先卸载旧版本(Windows 控制面板,macOS 拖入废纸篓),再装新版本。

**卡点 3:磁盘空间不足**
基础安装至少需要 5 GB 可用空间,Windows 推荐预留 10 GB(系统盘)。如果不够,清理一些文件后再装。

**卡点 4:权限不足**
在企业环境下,你的 Windows 账户可能没有管理员权限,导致安装失败。处理方法:联系 IT 部门获取临时管理员权限,或者请 IT 部门在企业应用商店中预装 WorkBuddy。

## 二、登录方式选择

安装完成后,首次启动 WorkBuddy,会引导你完成登录。

WorkBuddy 支持三种登录方式:

![WorkBuddy 登录界面,三个登录选项并排](figures/1.2.4-login-page.png)

*图 1.2.4 WorkBuddy 登录界面,三个登录选项并排*

### 2.1 微信扫码

**适用场景**:个人使用。

**优点**:
- 登录最快,扫码 1 秒完成
- 不用记密码
- 自动同步微信个人资料(头像、昵称)

**缺点**:
- 不能用于团队场景(没有"组织"概念)
- 不能启用 Claw 远程控制(详见第二卷第 2 章)
- 离职时账号归属有问题(微信是个人资产)

**适合谁**:个人探索、试用、临时使用。

### 2.2 企业微信

**适用场景**:团队使用。

**优点**:
- 自动绑定到你的企业组织
- 可以启用 Claw 远程控制(企业微信 → WorkBuddy 派任务)
- 团队管理员可以统一管理账号
- 离职时账号自动回收

**缺点**:
- 登录稍慢(需要在企业微信中确认)
- 需要企业先注册 WorkBuddy 团队版
- 部分企业 IT 政策可能限制第三方应用

**适合谁**:在企业微信里办公的团队成员。

### 2.3 手机号

**适用场景**:兜底方案。

**优点**:
- 不依赖微信/企业微信
- 适合海外用户或没有微信的用户
- 隐私相对独立(不与微信账号关联)

**缺点**:
- 每次登录需要短信验证码(略繁琐)
- 同样不能用于团队场景

**适合谁**:没有微信、企业微信、或者想保持账号独立的用户。

### 2.4 选择建议

**管理者视角的建议**:
- 如果你主要想自己先探索,**微信扫码**最方便
- 如果你已经计划把 WorkBuddy 推给团队,**先注册企业微信登录**——这样你试用时,顺便就熟悉了团队版的界面
- 不推荐手机号登录,除非你有特殊原因(海外、不用微信)

**一个隐藏的注意点**:登录方式一旦选定,后续更换会比较麻烦。比如你先用微信登录,后来想转到企业微信,可能需要重新注册账号、数据迁移。所以,登录方式要在第一次就选对。

## 三、文件夹授权:最关键的一步

登录完成后,WorkBuddy 会立即弹出一个对话框——**文件夹访问授权**。

![文件夹授权对话框,提示"请选择 WorkBuddy 可以访问的文件夹"](figures/1.2.5-folder-permission.png)

*图 1.2.5 文件夹授权对话框,提示"请选择 WorkBuddy 可以访问的文件夹"*

这个对话框是 WorkBuddy 与一般桌面应用最大的区别之一。

### 3.1 为什么要授权

WorkBuddy 要"动手"处理你的文件,必须先知道**可以访问哪些文件夹**。这个授权机制,和 iOS、Android 移动应用的"权限申请"逻辑类似——应用要访问你的相册、通讯录,需要先得到你的同意。

WorkBuddy 默认会请求以下三个文件夹的访问权限:
- **桌面**(Desktop)
- **文档**(Documents)
- **下载**(Downloads)

这是基于"大多数用户的文件在这里"的假设。但对管理者来说,**这可能不是最优选择**。

### 3.2 不推荐默认全盘授权

很多用户在第一次看到这个对话框时,会下意识地"全选"——既然 WorkBuddy 要用,就让它访问所有文件夹吧。

**这是不推荐的**。原因有二:

**第一,文件结构不清晰**。如果你的"桌面"上有 50 个散落的文件——PDF 报告、Excel 表格、下载的安装包、截图——WorkBuddy 在"派活"时,可能会读到无关的文件。这会导致两个问题:
- AI 误解上下文(它看到了不该看的东西,可能误用)
- 输出结果混入无关信息(它把无关文件的内容也整理进你的报告)

**第二,数据安全风险变大**。授权范围越大,WorkBuddy 越可能接触到敏感数据。即使 WorkBuddy 本身没有"偷数据"的意图,授权过大也意味着**潜在风险面变大**——一次误操作、一次漏洞,可能影响更多文件。

更稳健的做法是:**只授权一个"工作目录"**。

### 3.3 推荐做法:建立独立工作目录

在正式授权之前,先在电脑上建一个独立的"工作目录"。这个目录是 WorkBuddy 主要访问的地方,也是你建议它唯一能访问的地方(配合 3.5 的"该文件夹及其子文件夹"范围)。

**Windows 用户的建议路径**:
- `D:\WorkBuddy_workspace\`(推荐,D 盘,避开系统盘)
- `C:\WorkBuddy_workspace\`(可接受,但 C 盘容易满)

**macOS 用户的建议路径**:
- `~/Documents/WorkBuddy_workspace/`(文档目录下)
- `~/WorkBuddy/`(用户主目录下)

**为什么不推荐"桌面"**?因为桌面是你"工作现场"的快照,文件多而杂。WorkBuddy 看到你的桌面,就等于看到了你当前的"工作上下文"——这对它来说信息量太大,对你来说风险也大。

**为什么不推荐"文档"或"下载"**?因为这两个目录里通常堆着大量历史文件,有用的、没用的、临时的、长期的混在一起。WorkBuddy 难以判断哪些是相关的。

**独立工作目录的好处**:
- 文件结构清晰,WorkBuddy 不会读到无关文件
- 授权范围最小,数据安全风险最低
- 团队推广时,每个成员都有同样的"工作目录结构",培训更容易

### 3.4 工作目录的内部结构

建立一个好的工作目录,不是只建一个空文件夹就完事。建议的内部结构是:

```
D:\WorkBuddy_workspace\
├── inbox\           # AI 处理前的素材入口
├── drafts\          # AI 生成的草稿
├── final\           # 经过你审核的最终输出
├── templates\       # 模板文件
├── weekly\          # 周报类工作
├── reports\         # 报告类工作
└── archive\         # 归档(处理完的旧文件)
```

**这个结构解决三个问题**:

- **inbox**:把"待处理"和"已处理"分开。你把素材放进 inbox,告诉 WorkBuddy 处理,生成的草稿在 drafts。你审阅后,移到 final。这个"流入-处理-流出"的过程,让工作流可见、可管理。
- **分类目录**(weekly / reports):按"工作类型"分,而不是按"日期"分。这样 WorkBuddy 找你过去同类工作的输出,更容易。
- **archive**:不删除文件,而是归档。这与"数据可审计"的原则一致——WorkBuddy 处理过的每份文件,你都能找到。

**你不需要从第一天就建好这个结构**。可以从最简单的开始:`D:\WorkBuddy_workspace\`,只用一个文件夹。等你用熟 WorkBuddy 后,再慢慢扩展。

### 3.5 授权过程的细节

当你按"添加文件夹"按钮,选择 `D:\WorkBuddy_workspace` 后,WorkBuddy 会确认授权范围:

- **仅该文件夹**(推荐):WorkBuddy 只能访问 `D:\WorkBuddy_workspace\` 下的内容
- **该文件夹及其子文件夹**:WorkBuddy 能访问该文件夹及其所有子目录
- **该文件夹及其所有子文件夹、所有文件**:WorkBuddy 能访问全部内容(危险)

**选"该文件夹及其子文件夹"**——这是最常见的设置。如果你的工作目录将来要建子目录(比如上面建议的 `inbox`、`drafts` 等),WorkBuddy 都能访问到。

**不要选第三项**(全盘访问)。即使它写着"所有文件",WorkBuddy 也没必要访问你电脑上的所有东西。最小授权原则,既保护你,也保护 WorkBuddy(避免它被你的无关文件"误导")。

### 3.6 授权后可以改吗?

可以。如果将来你发现:
- 某些工作目录没授权,导致 WorkBuddy 读不到
- 某些目录授权太大,想缩窄

都可以在 **设置 → 文件夹授权** 中调整。但每次调整,WorkBuddy 都会要求重新确认。这是一个安全机制,防止"AI 偷偷扩大权限"。

## 四、工作目录的设置

授权完文件夹后,WorkBuddy 会进入主界面。但在你正式使用之前,还有几个关于"工作目录"的细节值得了解。

### 4.1 C 盘 vs D 盘:为什么推荐 D 盘

如果你的电脑有多个硬盘(比如 SSD + HDD),**建议把工作目录放在非系统盘**(D 盘或 E 盘)。

**理由有三**:

**第一,避免系统盘空间紧张**。WorkBuddy 在运行过程中会产生临时文件、日志文件、缓存文件。这些文件默认存放在系统盘用户目录下。如果你的 C 盘(系统盘)空间不大,这些文件可能很快占满空间,导致系统卡顿。

**第二,数据备份更容易**。非系统盘往往对应"数据盘"的概念——你重要的文件都在这里。备份软件通常默认备份非系统盘。把工作目录放在非系统盘,意味着你的 AI 工作文件**默认会被备份**。

**第三,未来迁移方便**。如果有一天你要换电脑,把整个 D 盘拷过去,工作目录就完整保留了。如果工作目录在 C 盘,要单独挑出来迁移,容易遗漏。

**没有 D 盘怎么办?**
- 大多数台式机有多个硬盘位,可以加
- 笔记本只有一个盘的话,把工作目录放在 C 盘也可以接受,但建议定期清理 WorkBuddy 的临时文件
- 也可以用外接 SSD 或 NAS(更复杂的方案,先不展开)

### 4.2 工作目录的临时文件

WorkBuddy 在处理任务时,会在工作目录下生成临时文件。这些临时文件包括:

- **中间结果**:任务执行过程中,WorkBuddy 可能会保存中间步骤的结果
- **日志文件**:详细的任务执行日志(不同于"操作日志",更技术)
- **缓存**:AI 模型加载、Skill 加载的临时缓存

**这些临时文件可以清理**,WorkBuddy 不会因为清理临时文件而"丢失"你的工作。但清理前最好确认没有正在执行的任务。

清理方式:在 WorkBuddy 的 **设置 → 存储** 中,有"清理临时文件"按钮。

**建议**:每月清理一次临时文件,避免它们无限增长。

### 4.3 工作目录的命名

工作目录的命名,虽然不影响功能,但有讲究。

**不推荐**:
- 中文路径(如 `我的工作\桌面文件\`):在某些工具链中,中文路径可能导致编码问题
- 路径中有空格(如 `My Documents\WorkBuddy workspace\`):空格在命令行中有时需要转义
- 路径过深(如 `D:\A\B\C\D\E\WorkBuddy\workspace\`):路径超过 260 字符(Windows 旧限制)可能报错

**推荐**:
- 英文或拼音:`WorkBuddy_workspace`、`wb_workspace`
- 路径简短:`D:\WorkBuddy_workspace\`(3 级,清晰)
- 无空格、无特殊字符

**如果你已经有"我的文档"等中文路径,WorkBuddy 也能正常工作**——但遇到问题时,排查起来更麻烦。建议从一开始就养成"英文路径"的好习惯。

### 4.4 多工作目录的设置

有些管理者会建多个工作目录,比如:
- `D:\WorkBuddy_personal\`(个人)
- `D:\WorkBuddy_team\`(团队项目)

WorkBuddy 允许授权多个工作目录。**但我不推荐这样做**,原因:

- 多工作目录会让"派活"变得复杂——你要告诉 WorkBuddy "处理 team 目录下的报告",它要在多个目录间切换,容易出错
- 多工作目录让"数据治理"变得困难——不同目录的命名规范、清理策略可能不一致

**建议:一个 WorkBuddy 实例,一个工作目录**。如果你确实需要"个人"和"团队"分开,可以考虑:
- 用两个不同的账号(个人微信 + 企业微信)登录不同的 WorkBuddy 实例
- 或者用同一个账号,但严格区分文件夹用途(虽然可能造成混乱)

具体怎么做,取决于你的实际场景。先从最简单开始,等遇到问题再调整。

### 4.5 工作目录的命名规范

工作目录内,你自己的文件命名,WorkBuddy 不会管。但**建议你建立自己的命名规范**,这对 AI 协作和组织级推广都有帮助。

一个简单的命名规范示例:

```
[类型]_[日期]_[主题]_[状态].扩展名

示例:
report_2026-08-16_q2-review_draft.docx
email_2026-08-15_client-followup_final.docx
meeting_2026-08-10_weekly-summary_notes.md
```

**这种命名的优点**:
- 类型明确(报告/邮件/会议)
- 日期明确(便于排序)
- 主题明确(便于检索)
- 状态明确(draft / final / notes)

WorkBuddy 在"派活"时,可以基于这种命名规范,更准确地理解你的文件上下文。

**但命名规范是"软建议"**——你不需要从一开始就严格执行。可以从最重要的几类文件开始,慢慢扩展。

## 五、首次启动的常见问题

按以上步骤操作,大多数用户可以顺利装上 WorkBuddy。但有 4 个常见问题值得提前知道,免得你卡住。

### 5.1 macOS 14+: "无法验证开发者"

首次启动 WorkBuddy 时,macOS 14+(Sonoma 及更新版本)可能会弹出一个提示:"WorkBuddy 无法验证开发者,是否仍要打开"。

这个提示是 macOS 的安全机制,**所有未通过 Mac App Store 分发的应用都会触发**,与 WorkBuddy 本身无关。

![macOS"系统设置 → 隐私与安全性"页面,WorkBuddy 被阻止的提示和"仍要打开"按钮位置](figures/1.2.6-macos-blocked.png)

*图 1.2.6 macOS"系统设置 → 隐私与安全性"页面,WorkBuddy 被阻止的提示和"仍要打开"按钮位置*

**处理方法**:

1. 在 macOS 桌面上,点左上角苹果图标 → **系统设置**
2. 在左侧菜单中找到 **隐私与安全性**
3. 向下滚动,找到 WorkBuddy 被阻止的提示
4. 点击提示旁边的 **仍要打开** 按钮
5. 系统会要求你输入管理员密码或使用 Touch ID
6. 之后再次打开 WorkBuddy,即可正常启动

**为什么不直接"允许所有第三方应用"**?macOS 14+ 默认不显示这个选项,主要是为了安全考虑。但你也可以在终端用 `sudo spctl --master-disable` 命令关闭 Gatekeeper——**这不推荐**,会降低系统安全性。按上面的方法,点一次"仍要打开"就够了。

### 5.2 Windows Defender 弹窗

Windows 11 上,首次启动 WorkBuddy 时,Windows Defender(或第三方杀软)可能会弹窗询问:"是否允许此应用对设备进行更改?"

![Windows Defender 弹窗,询问是否允许 WorkBuddy 对设备进行更改](figures/1.2.7-defender-prompt.png)

*图 1.2.7 Windows Defender 弹窗,询问是否允许 WorkBuddy 对设备进行更改*

**处理方法**:

- 点 **是** —— 这是正常的 UAC(User Account Control)提示,WorkBuddy 需要管理员权限才能正常运行
- 如果你用的是第三方杀软(如 360、腾讯管家),杀软可能会先一步弹窗,要求你"信任此应用"。在信任列表中添加 WorkBuddy 即可。

**为什么 Defender 会问**:WorkBuddy 启动后需要读取文件夹、调用系统工具,这些操作需要较高的权限。Defender 的弹窗是在确认"你知道这个应用要做这些事"。点"是"等于你授权了。

**不建议**:不要在杀软里"永久信任所有 WorkBuddy 文件"——这会让其他伪装成 WorkBuddy 的恶意软件也通过信任。**只信任 WorkBuddy 本身**,不扩展到其他文件。

### 5.3 启动卡顿的排查

极少数情况下,WorkBuddy 启动后会卡在加载界面,无法进入主界面。

![WorkBuddy 主界面全景,展示三栏布局](figures/1.2.8-main-interface.png)

*图 1.2.8 WorkBuddy 主界面全景,展示三栏布局*

**常见原因与处理方法**:

**原因 1:网络问题**
WorkBuddy 启动时需要连接服务器验证登录、加载配置。如果网络不通或太慢,会卡在加载界面。
- 检查网络:打开浏览器,看能否正常访问
- 重启 WorkBuddy:关闭后重新打开
- 重启网络:如果是 WiFi,试着切换或重启路由器

**原因 2:工作目录文件过多**
如果你的工作目录下有几十万个小文件,WorkBuddy 首次扫描会非常慢。
- 处理:把工作目录里的文件"分门别类",先移走不需要的;或者用更小的目录测试
- 长期:建立"工作目录维护"习惯,定期清理

**原因 3:旧版本残留**
如果之前装过老版本,新版本可能因为配置冲突而卡住。
- 处理:彻底卸载老版本(Windows 用控制面板,macOS 用清理工具),删除残留配置(Windows: `C:\Users\<用户名>\AppData\Roaming\WorkBuddy\`;macOS: `~/Library/Application Support/WorkBuddy/`),重新安装

**原因 4:硬件资源不足**
如果电脑内存小于 8 GB,或者 CPU 较旧,WorkBuddy 可能启动缓慢。
- 处理:关闭其他占用资源的应用;或者升级硬件

**如果以上方法都试过仍然卡住**:
- 提交问题报告:WorkBuddy 主界面 → 设置 → 反馈
- 加入用户社区:WorkBuddy 官方社区(见官网),搜索类似问题
- 联系 IT 部门:如果你在企业环境,IT 可能有更详细的诊断工具

### 5.4 安装完成后的第一件事

装好 WorkBuddy 后,建议你做的第一件事是:

> **打开 WorkBuddy,点击"新建任务",输入:"你好,WorkBuddy。请做一个自我介绍,告诉我你能做什么。"**

这是一个简单的"握手测试"——确认 WorkBuddy 已经能正常响应。如果它能给出符合预期的回答,说明安装、登录、授权、模型调用都正常。

如果这一步都不工作,后续任何操作都无从谈起。

**这一步是必要的**,不要跳过。即使你已经在另一个电脑上用过 WorkBuddy,在新电脑上也要做一次握手测试——不同电脑的运行环境可能有差异。

## 六、装好之后:第一周使用路线图

装上 WorkBuddy 不等于"会用"。从"装好"到"用起来",中间有一段适应期。这段适应期如果走得好,你会在 1-2 周内形成基本使用习惯;走得不好,你可能装了等于没装。

这里给一个**7 天入门路线图**,帮你平稳过渡。

### 6.1 Day 1:握手 + 简单对话

**目标**:确认 WorkBuddy 能用,你也能"开口"。

具体动作:
- 完成 5.4 的握手测试
- 再提 2-3 个简单问题:"今天天气怎么样?"(测试它会不会回避)、"把'你好'翻译成英文"、 "1+1 等于几"(测试基础能力)
- 观察 WorkBuddy 的回答速度、语气、格式

**预期感受**:WorkBuddy 跟你用过的 ChatGPT 看起来差不多。但你会开始注意到:它能直接读到你工作目录的文件(在下一章会更明显)。

### 6.2 Day 2:处理一份真实文档

**目标**:用 WorkBuddy 处理一份你电脑里的真实文件,体验"桌面 AI"的核心差异。

具体动作:
- 找一份你电脑里的 Word 或 Excel 文档(不要用太重要的,先用一份不太敏感的)
- 放到工作目录的 `inbox\` 下
- 打开 WorkBuddy,说:"处理 `inbox\` 下的 [文件名],告诉我里面讲了什么"
- 观察 WorkBuddy 是否能直接读取文件

**预期感受**:"原来真的能直接读"——这是大多数用户第一次体验 WorkBuddy 时的惊讶时刻。ChatGPT 需要你手动上传,WorkBuddy 直接读,这个差异在第一次体感时最明显。

### 6.3 Day 3:体验 Skill

**目标**:理解 Skill 是什么,以及它能怎么帮你。

具体动作:
- 打开左栏的"技能市场",浏览可用的 Skill
- 选 2-3 个看起来有用的,试用、加载
- 用加载的 Skill 跑一个任务,看输出有什么不同

**预期感受**:你会发现,有些 Skill 能让"派活"更精准。比如"周报助手" Skill,会引导你按"已完成/进行中/下周计划"的结构输出。

### 6.4 Day 4:写第一个"标准提示词"

**目标**:开始积累自己的"派活模板"。

具体动作:
- 想想你这周做过的一个任务(比如"整理会议纪要")
- 把你的"派活指令"写下来——目标、约束、输出格式
- 用这个提示词跑一次任务,看输出
- 微调提示词,直到输出符合预期
- 把这个提示词保存下来,作为你的"标准提示词 v1"

**预期感受**:你会发现,清晰的提示词能让输出质量大幅提升。但写好提示词需要几次迭代——这是正常的。

### 6.5 Day 5:尝试跨工具任务

**目标**:体验 WorkBuddy 的"代理人"能力。

具体动作:
- 让 WorkBuddy 跨两个工具完成任务:比如"读 `inbox\` 下的销售数据 Excel,生成一份 200 字的摘要,保存到 `drafts\`"
- 或者"读 `inbox\` 下的客户邮件原文,起草一封回复草稿,保存到 `drafts\`"
- 检查生成的文件是否在指定路径

**预期感受**:WorkBuddy 不只是"对话",它真的在"动手"。这与 ChatGPT 的差异开始明显——ChatGPT 给你文字回复,WorkBuddy 直接给你一个文件。

### 6.6 Day 6:查看操作日志

**目标**:理解"可审计"这件事怎么落地。

具体动作:
- 打开右栏,找到"操作日志"或"任务历史"
- 看 WorkBuddy 在过去一周做了哪些操作:读了哪些文件、改了哪些文件、调了哪些模型、消耗了多少 Credits
- 想想:如果你的上级问"AI 在你这周做了什么",你能答得清吗?

**预期感受**:你会意识到,"可审计"不是一个抽象概念,而是"我能清楚说出 AI 做了什么"的具体能力。这是云端 AI 给不了的。

### 6.7 Day 7:复盘 + 规划

**目标**:把一周的经验沉淀下来。

具体动作:
- 复盘:这周用了 WorkBuddy 几次?哪些场景好用?哪些场景效果不好?
- 沉淀:把这周用得最稳定、效果最顺手的提示词,固定下来;把反复使用的任务,封装为 Skill
- 规划:下周想多试哪些场景?要不要把同事拉进来一起用?

**预期感受**:一周下来,你应该能用 WorkBuddy 完成 1-2 个真实工作场景了。这是个好的起点——你已经在"用 AI"了,不是"看 AI 演示"。

### 6.8 路线图的灵活性

这个 7 天路线图是**参考**,不是**规定**。你可以:

- **跳步**:如果你是有经验的 AI 用户,Day 1-3 可以快速过,直接到 Day 4
- **慢走**:如果你是新手,每个 Day 可以做 2-3 天,不急
- **重复**:如果某一天的任务没完成,可以重复后再进入下一天

关键是:**不要在没装上 WorkBuddy 的情况下,只是"读"这本书**。WorkBuddy 是实践工具,只有在用的过程中,你才能体会它的价值。

## 小结

这一章我们完成了 WorkBuddy 的完整安装流程。回看全章,关键决策有三个:

**第一,下载渠道**。只从 codebuddy.cn/work 下载,不要用第三方下载站。这关系到安装包的安全性和版本时效。

**第二,登录方式**。个人用微信扫码,团队用企业微信,手机号作为兜底。选对登录方式,会让后续的团队推广和 Claw 远程控制更容易。

**第三,文件夹授权**。这是最关键的一步。建立独立工作目录(推荐 `D:\WorkBuddy_workspace\`),只授权这一个目录,采用"该文件夹及其子文件夹"的范围。**不要授权桌面、文档、下载这三个默认目录,也不要授权全盘**。

完成这些,你就有了一个"能安全使用"的 WorkBuddy。但"能装上"和"会用"是两回事。

下一章,我们进入 WorkBuddy 的主界面,逐一认识左中右三栏的功能,跑通一次完整的"派活"流程,让你从"装好"到"用起来"。

## 实践练习

1. **完成完整的安装流程**:从下载到登录到文件夹授权,按本章步骤做一遍。如果遇到 macOS 验证或 Defender 弹窗,按 5.1 / 5.2 的方法处理。完成后,在 `D:\WorkBuddy_workspace\`(或你自定义的工作目录)下建一个 `test.txt` 文件,内容写"我的第一个 WorkBuddy 文件"。

2. **做一次"握手测试"**:打开 WorkBuddy,新建任务,输入"你好,WorkBuddy。请做一个自我介绍,告诉我你能做什么。"把它的回答截图保存——这是你的"安装成功"证据。

3. **把工作目录的内部结构搭起来**:按 3.4 的建议,建好 `inbox\`、`drafts\`、`final\`、`templates\`、`archive\` 五个子目录(其他可选)。这一步是"先有结构,后有内容"的好习惯。

4. **记录你安装过程中遇到的每一个问题**:无论是弹窗、卡顿、还是找不到的按钮。把它们记下来,以及你是怎么解决的。这份记录有两重价值:一是自己复盘;二是团队推广时,可以基于这份记录写"安装 FAQ"。

5. **检查你电脑的存储状况**:WorkBuddy 会在工作目录里产生临时文件。看看你电脑的 D 盘(或其他非系统盘)剩余空间,以及未来一年的预期使用量。如果空间不足,提前规划清理或扩容策略。
