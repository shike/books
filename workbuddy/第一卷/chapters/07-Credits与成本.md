# 第 7 章 Credits 与成本

## 本章要点

- Credits 是 WorkBuddy 的资源计量单位:它不是"按次付费",而是"按任务复杂度付费"。同样一个对话框,问"1+1"和"基于 5 份 Excel 写一份复盘报告",消耗的 Credits 差几十倍
- 个人用户的 6 类 Credits 来源:注册赠送 5000(有效期至 2027 年底)、每日签到 100、连续 7 天奖励 1000、平台任务(邀请/反馈/内测)、付费套餐(标准版/旗舰版)、自购 API Key(走自购模型不消耗平台积分)
- 任务消耗按"简单问答(1-5)/中等任务(20-50)/复杂任务(100+)"分三档;模型档位(标准/增强/旗舰)再乘 1x-3x 系数
- 付费方案选择不是"哪个更贵"的问题,而是"我这个月的实际消耗落在哪一档"。三个固定套餐之外,自购 API Key 是高频用户与合规场景的另一种成本模型
- 管理者视角的关键:Credits 消耗 = AI 投入的客观度量。把每个任务折算成"Credits × 时长",就能算清楚"哪些任务用 AI 值、哪些不值"
- 算清个人账后,团队账是简单乘法。但"谁出钱、怎么分摊、怎么审计"是组织问题,不是技术问题——这部分会在第二卷第 8 章展开

## 开篇

第 6 章讲了 Skill:把"派活"沉淀为可复用的工具。装上 Skill 之后,你会发现,自己用 WorkBuddy 的频率开始明显上升——周报、邮件、纪要、PPT 大纲,原本要花半小时的事情,现在一两分钟出草稿。

但用得多了,一个新问题就冒出来了:**这把刀多贵?**

这不是一个小问题。WorkBuddy 与传统软件不同——传统软件是"一次买断"或"按月固定",你能预先知道花多少钱;WorkBuddy 是"按消耗付费",你花多少钱取决于你"用得有多重"。这意味着,没有"用得最划算"这种通用答案,**你必须算清自己的账**。

更复杂的是,WorkBuddy 提供 6 种不同的 Credits 来源,每一种的"性价比"与适用场景都不同。不了解来源,可能付了不该付的钱;不了解消耗,可能把 99 元的标准版用得只剩 5 天。

这一章,我们把 WorkBuddy 的"经济系统"完整算一遍:先讲 Credits 是什么、与"按次付费"有什么根本差异;再把 6 种来源逐一拆解;接着讲消耗——一次"派活"到底花多少,5000 Credits 能用多久;然后给你一张付费方案决策表;最后讲自购 API Key 这种"绕过平台积分"的另一种成本模型,以及从管理者视角如何把 Credits 当成"AI 投入产出数据"。

读完这一章,你要能做三件事:算清自己过去一周的 Credits 消耗;选好下个月的付费方案;用 Credits 数据做一次"AI 投入产出"的粗算。

## 一、Credits 是什么

### 1.1 一个"通用积分"的比喻

Credits(积分)是 WorkBuddy 的资源计量单位。它不是货币(不能提现),也不是订阅费(不是按月收一笔钱),它更接近"话费"——你用多少,扣多少;不用,不扣。与话费不同的是,WorkBuddy 的 Credits 按**任务复杂度**计费,问"1+1 等于几"和"基于 5 份 Excel 写复盘报告",消耗的 Credits 差几十倍。**同样的对话框,做的事不同,价格不同**。

### 1.2 与"按次付费"模式的对比

很多 AI 工具的计费方式是"按次"——你问一次,扣一次钱。这种模式有两个问题:**任务复杂度被忽略**(问"今天天气"和写 1 万字分析报告,可能被算成同一次);**中间过程不可见**(读 50 份文件、调用 5 轮模型,这些都不可见)。

WorkBuddy 的 Credits 模式把这两点都解决了——前者 1-5 Credits,后者 100+ Credits,差距 20 倍以上;右栏能看到每一次模型调用、每一次文件读取的消耗。**这种透明度是 WorkBuddy 成本模型的核心特征,也是管理者做 AI 投入产出分析的基础**。

### 1.3 一次"派活"消耗多少 Credits

具体多少,取决于三个因素:**任务类型、模型档位、上下文长度**。

- **任务类型**:简单问答、文本生成、数据分析、多文件汇总、PPT 生成,消耗依次递增
- **模型档位**:WorkBuddy 提供了标准 / 增强 / 旗舰三档模型(类似 GPT 的 mini / plus / pro),每档的 Credits 单价不同
- **上下文长度**:任务输入的素材越多(读 10 份文件 vs 1 份),消耗越大

一个粗略的实测范围(基于标准模型档位,截至 2026 年 6 月):

| 任务类型 | 典型 Credits 消耗 | 例子 |
|---|---|---|
| 简单问答 | 1-5 | "1+1 等于几"、翻译一句话 |
| 中等文本生成 | 20-35 | 起草一封邮件、写一段 500 字文案 |
| 复杂文本生成 | 50-100 | 写一份周报、整理一份纪要 |
| 多文件汇总 | 50-100 | 基于 3-5 份文档生成报告 |
| 数据分析 | 50-150 | 透视 Excel、生成图表包 |
| 复杂推理/规划 | 100-300 | 写一份方案、生成 PPT 大纲 |

> 本表为 3.1 节四档分类(简单 1-5 / 中等 20-50 / 复杂 50-200 / 超复杂 300+)的细化基准,详细定义见 3.1 节。

![图 1.7.2 不同任务类型的 Credits 消耗对比,简单问答 vs 复杂任务差 20-50 倍](figures/1.7.2-credits-by-task.png)

*图 1.7.2 不同任务类型的 Credits 消耗对比,简单问答 vs 复杂任务差 20-50 倍*

如果你选"增强"或"旗舰"模型,上述数字要乘以 1.5-3 倍的系数(具体系数在第三节展开)。

### 1.4 5000 Credits 能用多久

注册即送 5000 Credits(截至 2027 年底有效),这是新用户最大的"免费额度"。

| 使用强度 | 每天消耗 | 5000 Credits 够用 |
|---|---|---|
| 轻度(3-5 个简单任务) | 20-50 | 100-250 天(3-8 个月) |
| 中度(5-10 个任务,标准/增强混用) | 100-300 | 17-50 天(0.5-2 个月) |
| 重度(10+ 个任务,含旗舰模型) | 300-1000 | 5-17 天(0.2-0.5 个月) |

对新用户来说,5000 Credits 是一个"试水金"——够 1-2 个月轻度使用,够你判断"WorkBuddy 对我有没有用"。但打算长期用,就必须考虑付费方案,详见第四节。

### 1.5 Credits 的"三个不变"

不管来源是什么,所有 Credits 有三个共同特征:**有有效期**(注册赠送至 2027 年底、签到当天有效、付费购买的 Credits 按月清零,不会"永远等你用");**不可提现**(不能兑换现金、不能转赠、不能跨账号合并);**使用顺序有规则**(系统优先消耗免费/签到来源,再消耗付费来源)。

理解这三点,你才能不被"还剩 4500 Credits"这种数字迷惑——那些 Credits 可能已经快过期,也可能下一秒就被某个任务消耗掉。

### 2.1 注册赠送 5000 Credits

**新用户首次注册即可获得 5000 Credits**(有效期至 2027 年 12 月 31 日,截至 2026 年 6 月,官方公告),目的是让你在不付费的情况下完整体验产品 1-2 个月。

**怎么用最划算**:不要在第一周就"测到见底",用 1000 Credits 试不同模型档位(标准 vs 增强 vs 旗舰),剩下 4000 作为"日常工具"持续使用。常见误区:把 5000 Credits 当成"压力测试",用最复杂任务把它耗光——这阶段的目的是判断"WorkBuddy 适不适合我",不是测极限。

### 2.2 每日签到 100 Credits

**每天打开 WorkBuddy 并点击"签到"按钮,可获得 100 Credits**,**当天有效**(不签到则清零,不能"攒 10 天一次用 1000")。

100 Credits 大约能支持 2-5 个简单问答,或 1-2 个中等文本生成。对轻度用户来说,100 Credits 足够一天的"轻量使用";对中度用户来说,只是"零头",主要消耗要靠付费套餐或自购 API Key。

### 2.3 连续签到 7 天额外奖励 1000 Credits

**连续签到 7 天,系统会一次性奖励 1000 Credits**(在第 7 天发放,7 天周期内有效)。1000 Credits 相当于"每天额外 +143 Credits",显著高于普通签到——但**前提是连续 7 天,中断一次就重置**。

**管理技巧**:把"签到"作为每天打开 WorkBuddy 的第一个动作。签到成本几乎为零(1 秒),7 天拿 1000 Credits 相当于"轻度用户一个月的免费额度"。

### 2.4 完成平台任务

WorkBuddy 平台会不定期发布**任务奖励**,完成即可获得 Credits。常见任务包括:

- **邀请好友注册**:邀请一个好友注册并完成首次使用,通常奖励 500-1000 Credits
- **反馈与建议**:提交 Bug 报告或产品建议,被采纳后奖励 200-500 Credits
- **内测新功能**:参与 Beta 测试,完成指定任务后奖励 500-2000 Credits

**含金量分析**:邀请好友适合社交圈广的用户;反馈建议门槛低但有"被采纳"的不确定性;内测奖励最高但需花时间测试。新用户前 1-2 个月可重点做"邀请好友"和"反馈建议",快速积累 3000-5000 Credits;之后若长期用,转向付费方案更划算。

### 2.5 付费套餐:标准版与旗舰版

付费是最稳定的 Credits 来源。截至 2026 年 8 月,WorkBuddy 提供三档付费方案(标准版/高级版/旗舰版,具体价格可能因活动而变,购买前请查官方):

| 套餐 | 月费 | 包含 Credits | 单 Credits 成本 | 适合谁 |
|---|---|---|---|---|
| 标准版 | 99 元/月(年付)/70 元/月(月付) | 额度以官网为准 | 约 0.002 元 | 中度用户 |
| 高级版 | 199 元/月(年付)/140 元/月(月付) | 额度以官网为准 | 约 0.0017 元 | 重度用户 |
| 旗舰版 | 999 元/年付、700 元/月(月付) | 50,000 Credits | 约 0.0015 元 | 超重度用户 |
| 自购 API Key | 按用量计费 | 不限 | 0.0008-0.003 元/千 Tokens | 高频/合规场景 |

**标准版**(99 元/月年付,70 元/月月付):适合每天 5-10 个中等任务,大多数"把 WorkBuddy 嵌入日常工作"的管理者落在这档。具体积分额度以官网最新公告为准。

**旗舰版**(999 元/年付,700 元/月月付):含 50,000 Credits,平均每天 1,667 Credits 等效,适合每天 20+ 个复杂任务,可以放心用旗舰模型,适合"重度使用者"。

**为什么有"单 Credits 成本"这一列**:因为它帮你直观比较——旗舰版的单 Credits 成本是标准版的 75%,**用得越多,单成本越低**。详细的付费方案选择放在第四节。

### 2.6 自购 API Key:另一种成本模型

**自购 API Key 不消耗平台 Credits**。你向大模型厂商(腾讯混元、DeepSeek、Anthropic 等)直接购买 API Key,接入 WorkBuddy,任务走的是你自购的模型服务——你绕过 WorkBuddy 的 Credits 体系,直接按 Token 计量付费给大模型厂商。

**适用场景**:
- **高频使用**:你每天消耗 5,000+ Credits,旗舰版可能不够
- **合规要求**:你的数据不能经过 WorkBuddy 平台,必须走私有通道
- **多模型混用**:你希望不同任务用不同模型(简单任务用便宜模型,复杂任务用旗舰模型)

**自购的成本区间**(截至 2026 年 6 月):国产模型约 1-8 元/百万 Tokens,国际模型约 20-80 元/百万 Tokens。Tokens 与 Credits 不是 1:1 对应,粗略地 1 次中等任务约等于 5,000-20,000 Tokens。

自购的详细测算在第五节展开,这是高级话题,你可以先跳过,等需要时再回来读。

### 2.7 来源对比与组合策略

6 种来源不是互斥的,实际使用中你可以**组合**:

| 来源 | 稳定性 | 单 Credits 成本 | 适合谁 |
|---|---|---|---|
| 注册赠送 | 一次性 | 0(已付) | 所有新用户 |
| 每日签到 | 持续 | 0(零成本) | 所有用户 |
| 连续签到奖励 | 持续(需连续) | 0(零成本) | 轻度用户 |
| 平台任务 | 机会型 | 0(零成本) | 社交/分享型用户 |
| 标准版付费 | 持续 | 0.002 元 | 中度用户 |
| 旗舰版付费 | 持续 | 0.0015 元 | 重度用户 |
| 自购 API Key | 持续 | 0.0008-0.003 元/千 Tokens | 高频/合规用户 |

**中度用户典型组合**:注册赠送 5000(2 个月内用完)+ 每日签到 100 × 30 = 3000 + 平台任务 2000-3000 + 标准版对应额度,**月总量约 60,000 Credits**,够大多数管理者的日常工作。

**重度用户典型组合**:平台任务 + 签到 5,000-8,000 + 旗舰版 50,000 + 部分高频任务走自购 API Key(约 100-200 元/月额外),**月总量约 150,000 Credits 等效 + 自购 + 加量包**,适合"已把 WorkBuddy 用成生产力基础设施"的用户。

## 三、Credits 的消耗

理解了来源,接下来看消耗——一次任务到底花多少,怎么查。这部分比"来源"更复杂,因为它**因任务而异、因模型而异**。

### 3.1 四档任务类型:简单 / 中等 / 复杂 / 超复杂

我们用"三档分类法"来描述 Credits 消耗,这是大多数用户最容易理解的框架。

**简单问答(1-5 Credits)**:单轮对话,无文件读取、无 Skill 加载。例如"1+1 等于几"、"今天周几"。实测消耗 1-3 Credits(标准),2-5 Credits(增强)。

**中等任务(20-50 Credits)**:单轮或 2-3 轮对话,可能读取 1-2 份文件。例如起草邮件、生成 500 字周报。实测消耗 20-35 Credits(标准),30-50 Credits(增强)。

**复杂任务(50-200+ Credits)**:多轮对话,读取多份文件,可能调用 Skill。例如基于 3-5 份文档生成报告、Excel 数据透视。实测消耗 50-100 Credits(标准),80-200 Credits(增强),150-300 Credits(旗舰)。

**超复杂任务(300+ Credits)**:多轮对话,大量文件读取,可能多次调用 Skill。例如完整季度复盘、跨 10+ 份文件的归因分析。实测消耗 300-800 Credits(增强),500-1500 Credits(旗舰)。

**一个易被忽略的事实**:即使是"同一句话",在不同上下文下消耗差异巨大。比如"把这段话翻译成英文"(无文件)3-5 Credits;"把这份 50 页报告翻译成英文"(读 1 个 PDF)200-500 Credits;"把这 5 份 50 页报告都翻译"(读 5 个 PDF)1000-3000 Credits。**关键变量是"上下文长度"**——这与"按次"模式的根本差异:在 WorkBuddy 里,**"读 10 份文件"不是 1 次任务,而是 10 倍的任务**。

### 3.2 模型档位:标准 / 增强 / 旗舰

WorkBuddy 提供三档模型(具体名称以官方为准,这里用"标准 / 增强 / 旗舰"统称三档):

| 档位 | 性能 | 单 Credits 消耗系数 | 适合场景 |
|---|---|---|---|
| 标准档 | 基础能力 | 1x | 简单问答、轻量文本生成 |
| 增强档 | 较强能力 | 1.5-2x | 中等任务、专业内容生成 |
| 旗舰档 | 最强能力 | 2.5-3x | 复杂推理、深度分析 |

**模型档位对消耗的影响是"乘数关系"**——同样一个 50 Credits 的标准档任务,用旗舰档可能变成 125-150 Credits。

**怎么选**:
- **日常邮件、周报、文案**:标准档够用
- **专业内容(报告、方案、深度分析)**:增强档
- **关键决策(投资判断、风险评估、复杂推理)**:旗舰档

**一个反直觉的判断**:不是"任务越重要就该用越贵的模型"。如果任务是"基于固定模板生成周报",标准档就够;如果任务是"对一份复杂方案做风险评估",旗舰档才有意义。**匹配任务复杂度,而不是"任务重要性"**——它往往是消耗差异的最主要来源。

### 3.3 上下文长度:被忽视的消耗放大器

第三个变量是**上下文长度**——任务读了多少素材。这个变量往往被新手忽略,但它对消耗的影响最大。

**实测的"读取消耗"系数**:
- 1 份普通 Word/Excel(几千字):消耗 ×1
- 1 份长报告(50 页 PDF):消耗 ×3-5
- 5 份普通文档:消耗 ×3-5
- 5 份长报告:消耗 ×10-20
- 10+ 份混合文件:消耗 ×20-50

**一个粗略公式**:读取消耗 ≈ "素材字数" × "模型档位系数"。一个 50 页 PDF 约 3-5 万字,标准档下读取消耗约 15-30 Credits,旗舰档下约 50-100 Credits——这部分还没算"生成"本身的消耗。

**管理意义**:如果你要做"基于 10 份报告生成季度复盘"这种任务,**先用 WorkBuddy 把每份报告"摘要"一下,再用摘要去生成复盘**——消耗会显著降低。这与"数据预处理"的逻辑一致。

### 3.4 消耗明细的查看

WorkBuddy 在右栏的"工具面板"会显示当前任务和近期任务的 Credits 消耗。具体入口:

- **当前任务**:右栏顶部,实时显示"本次任务已消耗 X Credits"
- **任务历史**:右栏 → "操作日志"或"任务历史",可看到每个任务的消耗明细
- **账户余额**:右栏底部或主界面右上角,显示"剩余 X Credits"和"将于 YYYY-MM-DD 过期"

**一个有效的做法**:每周花 5 分钟,打开任务历史,按任务类型分桶,看"我这周主要消耗在哪"。这一步是"算清个人账"的基础(第七节展开)。

## 五、自购 API Key:另一种成本模型

上一节提到"自购 API Key 适合超重度用户和合规场景",这一节展开讲。

### 5.1 什么是自购 API Key

API Key(应用程序编程接口密钥,Application Programming Interface Key),是你向大模型厂商购买"模型调用额度"时获得的凭证。WorkBuddy 支持接入外部 API Key,接入后,**这部分任务走的是你自购的模型服务,不再消耗平台 Credits**。

这与"用 WorkBuddy 平台模型"的根本区别是:**钱付给大模型厂商,而不是付给 WorkBuddy**。WorkBuddy 只是一个"调用界面"。

**自购的成本计量**:按 Tokens(模型处理的最小文本单位,大致对应 1 个汉字或半个英文单词)计量,输入和输出分别计费。截至 2026 年 6 月,国内市场常见定价:

| 模型 | 输入价格(元/百万 Tokens) | 输出价格(元/百万 Tokens) | 适合场景 |
|---|---|---|---|
| DeepSeek-V3 | 1-2 | 2-4 | 性价比首选 |
| 腾讯混元 Standard | 4 | 8 | 中文任务 |
| 腾讯混元 Pro | 12-20 | 20-30 | 高质量中文 |
| Claude Sonnet 4 | 20-30 | 100-150 | 复杂推理 |
| GPT-4o | 18-30 | 60-90 | 多语言任务 |

注:具体价格以厂商官方为准,可能因促销活动而变。

### 5.2 自购的成本测算示例

粗略换算:1 Credits ≈ 500 Tokens。假设输入:输出 = 1:1,使用 DeepSeek-V3(输入 1.5 元/百万 Tokens,输出 3 元/百万 Tokens)。

**示例 1:中度用户(月消耗 200,000 Credits 等效)**——折合 1 亿 Tokens,自购成本约 **225 元**;对比"标准版(99 元年付 / 70 元月付)+ 150,000 Credits 等效自购(约 170 元) = 269 元",自购省 16%。但自购要自己管理 API Key、监控用量、对接厂商,**标准版的"管理简单"价值 > 自购的"省 16%"价值**。

**示例 2:重度用户(月消耗 1,000,000 Credits 等效)**——折合 5 亿 Tokens,纯自购约 **1,125 元**;Pro+纯自购 = 99 + 1,125 = 1,224 元;Ultra 299 + 自购 800,000 等效 ≈ 1,199 元(自购 800,000 Credits ≈ 900 元),比 Pro+纯自购省约 2%。**重度用户的成本天花板在自购 API Key 本身,套餐只是降低自购数量。Ultra 的真正价值是减少自购管理负担,不是直接省钱**。

### 5.3 哪些场景适合自购

**适合自购的场景**:

- **高频使用**:月消耗 300,000+ Credits,旗舰版 50,000 Credits 不够
- **合规要求**:数据不能经过 WorkBuddy 平台,必须私有通道(金融、医疗、政府场景)
- **多模型混用**:简单任务用便宜模型(DeepSeek),复杂任务用旗舰模型(Claude)

**不适合自购的场景**:月消耗 < 50,000 Credits(自购的"管理成本"大于省钱)、对"管理简单"要求高、不熟悉 API Key 管理。

### 5.4 自购的"管理负担"

自购 API Key 听起来"省钱",但有几项隐性成本要算:**监控用量**(自己记录 Tokens 消耗,避免超额被厂商限流)、**API Key 安全**(泄露会导致"别人用你的钱")、**续费管理**(不同厂商续费方式不同)、**对账复杂**(多模型混用时,每月对账可能涉及 3-4 个厂商)。

**结论**:对**大多数个人用户**,不建议自购。固定套餐的"管理简单"价值 > 自购的"省 15-20%"价值。自购是**重度用户、合规场景、多模型需求**的选项,不是"省钱妙招"。

### 5.5 自购与 WorkBuddy 平台的"二选一"

有些用户会问:"我能不能完全不用 WorkBuddy 平台,只用 API Key 接入?"

可以,但意义不大。WorkBuddy 平台提供的价值,不只是 Credits 体系,还有:
- **Skill 市场**:现成的 Skill 可以直接用,自购需要自己开发
- **操作日志**:WorkBuddy 的本地审计能力,自购没有
- **工作目录集成**:WorkBuddy 的"读本地文件"能力,自购要自己集成
- **跨平台支持**:Mac/Win 一致体验,自购要自己处理

**自购 + WorkBuddy 平台**是组合,不是替代。WorkBuddy 是"界面",API Key 是"算力来源",**两者各司其职**。

### 6.1 Credits 消耗 = AI 投入的客观度量

传统软件的成本是"按月收一笔钱",无论你用多用少——好处是简单,坏处是**"用了多少"不可见**,你不知道团队某个员工"用得值不值"。

WorkBuddy 的 Credits 模型,让"用了多少"变成**可量化的客观数据**:团队周消耗、各任务分布、各员工分布、各 Skill 消耗——这些数据可以在**企业版后台**统一查看。这是**团队级 AI 支出的首次可见化**——你第一次能精确知道"AI 在团队里到底花了多少、做了什么"。

**对比传统软件 ROI**:传统软件只能看"日活"、"功能使用率";WorkBuddy 可以精确知道"每个任务多少 Credits",算"每个任务的 AI 成本"——传统软件算"省了多少时间",WorkBuddy 可以算"省了多少时间 × 每个时间值多少钱 = 多少钱",再除以"Credits 月成本",得到**精确的 AI ROI**。这是传统软件算不出来的。

### 6.2 用 Credits 数据评估"哪些任务用 AI 值"

管理者可以每周花 30 分钟,做一次"AI 投入产出复盘":**第一步拉数据**(团队周消耗、各任务分布、各员工分布);**第二步分价值**(高价值:方案撰写/报告分析/客户回信;中价值:周报/纪要/邮件;低价值:信息检索/知识问答);**第三步算性价比**(高价值 × 高消耗重点保障,高价值 × 低消耗可能没做对,低价值 × 高消耗减少,低价值 × 低消耗正常)。

**一个真实的复盘案例**:

[案例来源:某 SaaS 公司运营总监访谈,2026-05,脱敏处理]

某运营总监每周做一次 AI 投入产出复盘,发现:**30% 的消耗在"低价值任务"(简单问答、信息检索)上,只产生 10% 的业务价值**。决策:减少"低价值任务"的旗舰模型使用,改用标准模型,把释放的 Credits 转向"高价值任务"。一周后同样的总消耗(12,500 Credits),业务价值提升 25%。

这个案例说明:**Credits 数据的真正价值不是"省了多少",而是"花在刀刃上"**。

### 6.3 与传统软件 ROI 的对比

传统软件 ROI 算的是"软件成本 vs 节省的时间 × 时薪"。这个公式有三个问题:**时间难量化**(用了 Word 写报告,节省 2 小时怎么证明?)、**价值难量化**(这 2 小时写出的报告值多少?)、**增量难量化**(不用 Word 我会花多少时间?)。

WorkBuddy 的 Credits 数据让这三个问题**部分可量化**:**时间可量化**(右栏显示任务时长)、**价值可量化**(把"任务"和"业务结果"挂钩)、**增量可量化**(用"类似任务的人工耗时"估算)。

**粗略的 AI ROI 公式**:

```
AI ROI = (节省的时间 × 时薪) / (Credits 消耗 × 单价)
```

例:用 WorkBuddy 写一份周报消耗 30 Credits(0.06 元),节省 30 分钟(30 元按 60 元/小时),AI ROI = 30 元 / 0.06 元 = 500,即"投入 1 元 AI 成本,产出 500 元时间价值"。

这个公式不完美,但**给管理者一个量化的起点**。AI ROI 在 10 以上就值得投入,在 100 以上就是"非常划算"。

### 6.4 Credits 数据驱动的"AI 治理"

当你能精确知道"每个任务多少 Credits",就可以做更精细的"AI 治理":**按角色分配 Credits**(管理者多、员工少)、**按任务设置阈值**(对"低价值任务"设单次消耗上限)、**按时间分批**(月初/月末不同强度建议)、**异常消耗告警**(某员工某天消耗 5 倍于平均,自动告警)。

这些是**企业版/团队版**的能力,个人版看不到。但即使你是个人用户,**建立"用 Credits 算账"的习惯**,对将来推给团队是直接有用的——你能用数据说话,而不是"我觉得 AI 挺好的"。

### 6.5 一个被忽视的视角:AI 成本的"机会成本"

**所有 AI 投入,都有机会成本**——你把 99 元花在标准版,这 99 元就不能花在别的地方(培训、工具、其他 SaaS)。

但反过来:**不花这 99 元,你的时间成本在涨**。一个管理者每天省 1 小时,一年 250 小时,按 60 元/小时算,价值 1.5 万元。99 元的标准版年化约 840-1,188 元(年付 99×12=1,188 元,月付 70×12=840 元),ROI 是 1.5 万 / 1,188 = **12.6 倍**。**大多数场景下,答案都是后者——用 99 元买回 1.5 万的时间**。

**这就是 WorkBuddy 给管理者的核心价值**:**花钱买时间,时间的价值远大于 Credits 的成本**。不是"省 99 元",而是"用 99 元买回 1.5 万的时间"。

这个视角会改变你做"AI 投入决策"的方式——你不再问"AI 这件事值不值 99 元",你会问"AI 这件事值不值 1.5 万"。**答案永远是后者**。

### 7.1 个人使用 1 个月的成本测算

**使用画像**:一位中层管理者,工作 22 天,每天 5-10 个任务(60% 中等、30% 简单、10% 复杂),80% 标准档 + 20% 增强档。

**日均消耗估算**:6 个中等 × 30 + 3 个简单 × 3 + 1 个复杂 × 80 ≈ 270 Credits/天,**月消耗 270 × 22 = 5,940 Credits/月**。

**方案选择**:5,940 < 50,000(Pro 99 元/年付的月均额度),**推荐 Pro(99 元/年付,70 元/月付)**,实际可用约 8 个月(50,000 ÷ 5,940 ≈ 8.4),平均月成本约 12 元(99 ÷ 8.4)。**对照其他方案**:免费 8,000 Credits 只够 1.3 个月(超出后"零可用");Ultra 200,000 Credits 用 33+ 个月——**严重浪费**。

**结论**:个人中度用户,标准版 99 元是"性价比最高的方案"。

### 7.2 团队 10 人 1 个月的成本测算

**团队画像**:
- 10 人团队,5 位管理者 + 5 位员工
- 管理者日均 8-12 个任务,员工日均 5-8 个任务
- 全员 60% 中等任务,30% 简单任务,10% 复杂任务
- 模型使用:70% 标准档,25% 增强档,5% 旗舰档

**人均日消耗估算**:
- 管理者:270 Credits/天(同 7.1)
- 员工:170 Credits/天(任务量比管理者少 30%)

**月消耗**:
- 管理者 5 人 × 270 × 22 = 29,700 Credits
- 员工 5 人 × 170 × 22 = 18,700 Credits
- 合计:**48,400 Credits/月**

**方案选择(团队订阅)**:
- 假设团队订阅与个人同价(以官方为准)
- 5 个标准版 + 5 个标准版 = 10 × 99 = **990 元/月**(理论值,实际可能有团队折扣)
- 实际积分额度以官网为准,通常远超 48,400 需求
- 单月成本 990 元,折合每人 99 元/人/月

**对照"团队折扣"**:10 人各自订阅标准版,月成本 990 元——团队订阅通常有折扣(打 8 折 792 元/月,或打 9 折 891 元/月)。

**对照"混合方案"**:5 个管理者用标准版(495 元),5 个员工用免费 + 签到(签到 11,000 Credits,缺口 7,700 要么"忍痛不补"要么"额外买标准版")。最终 5 × 99 = 495 元/月,加员工"可能需要额外标准版"500 元 ≈ 1000 元/月——**与"全员标准版"差异不大,但管理更复杂**。

**结论**:对 10 人团队,**全员标准版订阅是最简单、成本可预测的方案**,月成本约 990 元(含团队折扣可能 800-900 元)。

### 7.3 团队 50 人 1 个月的成本测算(预告)

**简算**:50 人全员标准版,50 × 99 = 4,950 元/月,全年约 6 万元。这是"中等规模"团队的标准成本。如果团队规模 50+ 或 100+,会有专门的企业版定价,通常按账号数阶梯报价,人均成本可能下降到 70-80 元/月。

**这一节的"50 人测算"是预告**,详细讨论放在第二卷第 8 章《成本与权限:团队 Credits 怎么分》。那一章会展开:团队预算怎么设、Credits 怎么分(按人/按团队/按项目)、怎么审计(防止盗用/误用/过度使用)、怎么报销(对接财务、发票管理)。

**如果你现在就要管 10-30 人团队**,可以先用 7.2 的"全员标准版"方案;**等团队扩展到 30+ 或需要精细化分账**,再读第二卷第 8 章。

### 7.4 个人账到团队账的"放大规律"

观察 7.1 → 7.2 → 7.3 的数字变化,可以总结出"放大规律":

| 规模 | 月消耗 | 月成本(全员标准版) | 人均月成本 | 同比个人 |
|---|---|---|---|---|
| 个人 | 5,940 | 99 | 99 | 1.0x |
| 10 人团队 | 48,400 | 990 | 99 | 1.0x |
| 50 人团队 | 240,000 | 4,950(折扣后约 4,000) | 80-99 | 0.8-1.0x |

**规律**:**人均消耗与个人相似**(管理者消耗多,员工消耗少,平均后接近"个人中度用户"水平);**总成本线性放大**(10 人 = 10 倍,50 人 = 50 倍,扣除团队折扣前);**人均成本随规模下降**(折扣 + 规模效应让"团队人均成本"略低于个人)。

**反直觉判断**:**团队用 AI 比个人自己用更划算**。原因不是单 Credits 成本更低,而是**团队订阅的折扣 + 集中管理减少了"重复消耗"**(个人买标准版用不完,团队可以"集中池化")。

### 7.5 跨卷预告:第二卷第 8 章《成本与权限:团队 Credits 怎么分》

个人账算清了,团队账是简单乘法。但"谁出钱、怎么分摊、怎么审计"是组织问题,不是技术问题:

- **预算模型**:整体预算怎么定、按什么维度分(人头 / 团队 / 项目)
- **分摊规则**:管理者 vs 员工的不同分配、核心项目 vs 边缘项目的不同分配
- **审计机制**:防止 AI 被滥用(刷量、跑无关任务、给非授权人员用)
- **报销流程**:对接财务、发票管理、季度复盘
- **跨部门协调**:多个部门共用一个 WorkBuddy 团队,Credits 怎么结算

这些话题第一卷不展开。**第二卷第 8 章会系统讲清楚**,并提供"团队 Credits 分账模板"。

读到这里若准备把 WorkBuddy 推给团队,**强烈建议接着读第二卷第 8 章**——个人与团队算账逻辑完全不同,跳过这一章直接推团队,容易在"成本失控"上踩坑。

## 小结

这一章我们把 WorkBuddy 的"经济系统"完整算了一遍。

**第一,Credits 是按任务复杂度付费的"通用积分"**——三个核心特征:有有效期、不可提现、使用顺序有规则。免费 Credits 不会"永远躺在账户里",你必须主动用。

**第二,6 种 Credits 来源可以组合使用**:注册赠送 5000、每日签到 100、连续 7 天奖励 1000、平台任务、付费套餐(标准版/旗舰版)、自购 API Key。前 4 种零成本,后 2 种稳定大量。

**第三,消耗按"简单(1-5)/ 中等(20-50)/ 复杂(50-200)/ 超复杂(300+)"分四档**,模型档位再乘 1-3x 系数,上下文长度是"放大器"。5000 Credits 在"轻度使用"下够 3-8 个月,在"重度使用"下只够 5-17 天。

**第四,付费方案选择不是"哪个更贵"的问题**,而是"我这个月的实际消耗落在哪一档"。免费适合试用,标准版(99 元/年付,70 元/月付)适合大多数中度用户,旗舰版(999 元/年付,700 元/月付)适合重度用户。**先试一周,再选方案**。

**第五,自购 API Key 是"绕过平台积分"的另一种成本模型**,适合超重度用户和合规场景。但自购有管理负担,对大多数个人用户**不划算**。**自购 + 平台订阅**是组合,不是替代。

**第六,Credits 消耗 = AI 投入的客观度量**——这是传统软件算不出来的。10 人团队月成本约 990 元,50 人约 5,000 元,**人均成本随规模略降**,但管理复杂度上升。**第二卷第 8 章会系统讲团队账**。

**如果只记一段**:Credits 不是神秘数字,它是你"AI 投入"的可量化度量。**算清自己的账,再决定付不付费、付多少**。99 元(标准版) / 999 元(旗舰版) / 0 元不是"哪个更贵"的问题,是"哪个匹配我的用量"的问题。

## 实践练习

1. **记录一周 Credits 消耗**:用一周时间,每天在右栏查看"今日消耗",按"简单 / 中等 / 复杂"分桶记录。一周后算总消耗,推算月消耗,对照第四节决策表选合适的付费方案。**这是"算清个人账"的第一步**。

2. **测算你的团队月消耗**:如果你有一个 3-10 人的小团队(或"潜在团队"),用 7.2 的方法估算团队月消耗。算完后问自己:(1)全员标准版划算吗?(2)管理者标准版 + 员工免费的混合方案可行吗?(3)有没有自购 API Key 的场景?带着这三个问题进入第 8 章,会更容易理解"团队分账"。

3. **试一次"AI 投入产出"复盘**:选一个你最近用 WorkBuddy 完成的任务,记录"消耗 Credits、节省时间、任务价值",用 6.3 的粗略公式算"AI ROI"。即使数字不精确,这个练习会改变你"看 AI 成本"的方式——**从"花了多少钱"变成"产出了多少价值"**。

4. **写下你的"AI 成本边界"**:每月愿意为 WorkBuddy 花多少钱?50 元?100 元?300 元?1000 元?**把它写下来**,会让你在面对"团队预算"时有一个清晰的锚点——个人愿意花 100 元/月,可能愿意为团队花 1 万元/年。
