# 附录 B 提示词模板库

## 本附录要点

- 按 6 类高频工作场景(周报、会议纪要、PPT 大纲、翻译、客户画像、邮件回复)提供现成模板
- 每类模板给 2-3 个变体,覆盖不同行业与表达习惯
- 统一变量占位符规范 `{{变量名}}`,便于复制后替换
- 附模板调优的 5 条通用建议,以及常见踩坑提醒

本附录是"读完就能用"的速查手册,所有模板都经过实际项目验证。你不需要理解模型原理,只要按图索骥填入自己的信息,就能得到一份质量稳定、风格统一的初稿。

## B.1 周报生成模板

周报是几乎所有知识工作者都要写的"基本功",但写好并不容易。模板一适合互联网产品 / 运营岗位,模板二适合咨询 / 项目经理岗位,模板三适合销售 / 客户成功岗位。

模板一:产品 / 运营周报(适合按数据汇报型岗位)

```text
角色:你是一名资深产品经理,负责汇总本周工作并撰写周报。
背景:
- 本周工作日期:{{本周日期范围}},例如 2026-06-16 至 2026-06-20
- 本周参与的会议:{{会议列表,例如周三需求评审会、周四用户访谈}}
- 本周接触的关键数据指标:{{指标列表,例如 DAU、转化率、留存}}
任务:
1. 用"完成事项 / 进行中事项 / 风险与阻塞 / 下周计划"四段式结构
2. 完成事项中每条都要带数据(数字、百分比、绝对值)
3. 进行中事项中标注预计完成日期
4. 风险与阻塞写明需要的支持(谁、什么时候、做什么)
5. 下周计划按优先级 P0 / P1 / P2 排序
输入材料:
{{粘贴你本周的零散笔记、会议纪要、聊天记录片段}}
输出要求:
- 总字数控制在 600-900 字
- 标题用 Markdown 二级标题
- 风险与阻塞用 ⚠️ 标识
- 输出完成后,另起一行给出"管理层最关心的 3 句话摘要"
```

模板二:咨询 / 项目经理周报(适合按里程碑汇报型岗位)

```text
角色:你是一名顾问公司的项目经理,需要向客户方项目负责人汇报本周进展。
项目背景:{{项目名称、合同金额、起止时间、当前阶段}}
本周成果:
{{列出本周交付物,例如原型 v2.1、调研报告、数据看板}}
本周数据:
- 计划完成 {{N}} 项任务,实际完成 {{M}} 项,完成率 {{百分比}}
- 累计里程碑完成度 {{百分比}}
- 预算执行率 {{百分比}}
待解决问题:
{{列出需要客户决策或协调的事项}}
下周计划:
{{列出下周的关键动作和负责人}}
输出要求:用"执行摘要 / 详细进展 / 风险与请求 / 下周计划"四段
```

模板三:销售 / 客户成功周报

```text
角色:你是一名 B2B 销售经理,正在撰写本周的客户运营报告。
本周核心数据:
- 新增线索:{{N}} 条,其中 {{M}} 条来自 {{渠道}}
- 进入商务谈判:{{X}} 个客户
- 本周签单:{{Y}} 个客户,合同总额 {{金额}} 万元
- 续约客户:{{Z}} 个,续约率 {{百分比}}
重点客户进展:
{{按"客户名 / 阶段 / 本周动作 / 下一步"四列描述前 5 名重点客户}}
需要支持:
{{销售支持、定价授权、技术答疑、产品定制等}}
下周目标:
{{新签、回款、客户活动等具体数字目标}}
```

## B.2 会议纪要模板

会议纪要是另一种高频产出,模板的关键在于"结构化 + 决策可追溯"。下面提供两套模板:一套适合内部周会 / 站会,一套适合跨部门决策会。

模板一:内部周会 / 站会纪要

```text
角色:你是一名会议记录员,负责把口语化讨论整理成结构化纪要。
会议信息:
- 会议主题:{{主题}}
- 时间:{{日期 + 时段}}
- 参会人:{{名单}}
- 主持人:{{姓名}}
- 记录人:{{姓名}}
原始转写或速记:
{{粘贴会议录音转写文本或你的速记要点}}
任务:
1. 提炼 3-5 条核心结论,每条不超过 30 字
2. 按"待办事项 / 负责人 / 截止日期"列表输出
3. 标注每个待办的优先级(高 / 中 / 低)
4. 列出尚未达成共识的争议点
5. 下次会议时间:{{日期 + 时段}}
输出格式:
- 一级标题:会议主题
- 二级标题:核心结论 / 待办事项 / 争议点 / 附议
```

模板二:跨部门决策会议纪要

```text
角色:你是一名会议秘书,需要为决策会议撰写可被多部门引用的纪要。
会议信息:同上模板
讨论议题:
{{议题 1 / 议题 2 / 议题 3}}
讨论要点:
{{每个议题的关键论据、备选方案、利弊分析}}
决议:
{{每个议题的最终决定,以及决策依据}}
执行分工:
{{决议 → 负责人 → 配合人 → 截止日期 → 验收标准}}
风险与备案:
{{如果决议执行受阻,启动哪套备案}}
纪要签发:
- 主送:{{部门 + 人}}
- 抄送:{{部门 + 人}}
- 存档路径:{{链接 / 文件路径}}
输出要求:用正式公文体,语言克制,避免口语化措辞
```

## B.3 PPT 大纲模板

PPT 是"内容密度极高、结构化极强"的产物,大纲决定了一切。下面给三套模板:商业路演、产品发布、培训课件。

模板一:商业路演 PPT(融资 / 销售场景)

```text
角色:你是一名创业者的路演教练,正在为 {{公司名}} 设计一份 {{轮次}} 路演 PPT 大纲。
公司一句话定位:{{用 30 字以内描述公司做什么、为什么重要}}
目标受众:{{投资人 / 大客户 / 行业伙伴}}
路演时长:{{10 / 20 / 30}} 分钟
要求页数:{{12 / 18 / 25}} 页
请按以下顺序输出每一页的标题 + 3 个核心要点:
1. 封面(公司名 + 一句话定位 + 联系方式)
2. 痛点(用 3 个数据点量化客户痛点)
3. 解决方案(产品形态 + 关键能力)
4. 产品演示(3 张截图 + 1 段录屏链接)
5. 市场分析(TAM / SAM / SOM 三层)
6. 商业模式(收入来源 + 单价 + 复购)
7. 竞争格局(直接竞品 + 间接竞品 + 差异化)
8. 核心团队(创始人背景 + 关键员工)
9. 发展里程碑(过去 12 个月 + 未来 12 个月)
10. 融资需求(本轮金额 + 估值 + 资金用途)
11. 联系方式
每页字数控制在 50 字以内,标题用动词开头,避免"产品介绍"这类笼统词。
```

模板二:产品发布 PPT(内部或对外)

```text
角色:你是一名产品市场经理,正在为 {{产品名 v 版本号}} 设计产品发布 PPT。
发布场景:{{线下大会 / 线上直播 / 客户沙龙}}
目标受众:{{现有客户 / 潜客 / 内部销售}}
核心信息:
- 三个最关键的新功能:{{功能 1 / 功能 2 / 功能 3}}
- 一句话价值主张:{{用 20 字以内说明这次发布为什么重要}}
请按以下顺序输出:
1. 封面
2. 一句话价值主张
3. 行业趋势(为什么现在是发布的最佳时机)
4. 现有客户的痛点(共情)
5. 新功能详解(每个功能 1-2 页)
6. 客户证言(2-3 个真实案例)
7. 价格与上市时间
8. 行动召唤(扫码试用 / 联系销售)
```

模板三:培训课件 PPT(对内赋能)

```text
角色:你是一名企业培训师,正在为 {{部门}} 设计 {{主题}} 培训课件。
学员背景:{{岗位、经验、预设的痛点}}
培训时长:{{30 / 60 / 120}} 分钟
学习目标:学员结束后能 {{具体的可衡量动作}}
请按"开场引入 → 概念讲解 → 案例剖析 → 工具演示 → 实操练习 → 复盘答疑"六段式输出每一节的标题与时长分配。
每个概念页要求:
- 一句话定义
- 3 个关键特征
- 1 个反面案例
- 1 个正面案例
- 1 个动手练习
```

## B.4 中英翻译模板

翻译看似简单,实则最容易出现"机翻味"。下面提供通用商务、合同条款、营销文案三套模板。

模板一:通用商务翻译

```text
角色:你是一名资深商务翻译,擅长将中文商务材料译为地道的英文,反之亦然。
任务:将以下文本从 {{源语言}} 翻译为 {{目标语言}}。
要求:
1. 保持原文语气与正式程度
2. 专有名词、公司名、产品名首次出现时保留原文
3. 文化相关表达做本地化处理,避免直译
4. 数字、日期、货币单位按目标语言习惯格式化
5. 翻译完成后,列出 3 个最容易被误译的关键词及其译法说明
文本:
{{粘贴原文}}
```

模板二:合同条款翻译

```text
角色:你是一名法律翻译,熟悉中国合同法与英美合同法,擅长跨境合同互译。
任务:翻译以下条款。
要求:
1. 使用法律英语的标准句式("shall" 而非 "will")
2. 保留条款编号与格式
3. 模糊或有歧义的地方加 [译者注] 说明
4. 不确定的法律术语给出 2-3 个候选译法
文本:
{{粘贴条款}}
```

模板三:营销文案翻译

```text
角色:你是一名营销文案翻译,擅长让广告语在目标市场同样打动人。
任务:把以下中文营销文案译为英文。
要求:
1. 保留原文的情感强度,但避免字面直译
2. 注意英文广告语常见长度:7-12 个单词
3. 双关、谐音、成语如无法对应,提供 1 个意译版本 + 1 个直译版本 + 推荐选择
4. 译完后给出"30 字以内的英语 tagline 备选 3 条"
原文:
{{粘贴文案}}
```

## B.5 客户画像模板

客户画像(persona)是把抽象的"用户"具体化为一个"人",让团队决策时有共同参照。下面给 B2B 和 B2C 两套模板。

模板一:B2B 客户画像

```text
角色:你是一名行业研究员,正在为 {{公司名}} 梳理目标客户画像。
行业范围:{{行业}}
公司规模:{{人数 / 营收区间}}
地理位置:{{区域}}
请基于公开信息(官网、年报、行业报告、新闻、招聘网站)输出 3 个典型客户画像,每个画像包含:
1. 客户公司
- 名称(虚构或脱敏)
- 行业 / 规模 / 营收
- 关键决策人(角色 + 关注点)
2. 决策链
- 决策人 / 影响人 / 使用人
- 平均采购周期
- 预算来源
3. 痛点与机会
- 当前最痛的 3 个问题
- 我们能解决的点
- 替代方案(竞品 / 自研 / 不做)
4. 触达方式
- 常用信息渠道

- 信任建立路径
```

## B.6 邮件回复模板

邮件看似人人会写,但"礼貌、清晰、高效"很难同时做到。下面给客户回复、跨部门沟通、领导汇报三套模板。

模板一:客户邮件回复

```text
角色:你是一名客服,正在回复客户邮件。
客户来信:
{{粘贴客户原文}}
要求:
1. 第一段:感谢来信 + 概括理解客户诉求
2. 第二段:针对性回应,逐条回答客户问题
3. 第三段:下一步动作(我方会做什么 / 客户需要做什么)
4. 第四段:再次感谢 + 联系方式
```

## B.7 模板调优建议

同一套模板在不同人手里效果差异很大,核心在于"具体性"。下面 5 条建议帮你把模板调到最佳状态。

第一,变量占位符要预留充分。`{{客户名称}}` 比 `{{客户}}` 更具体;`{{2026 年 6 月营收数据}}` 比 `{{营收}}` 更具体。占位符越具体,模型在替换时越不容易"自以为是"地补充数据。

第二,示例段落要齐全。在每个任务点后面附 1-2 个"输入样本 + 期望输出",比纯文字描述有效三倍以上。例如周报模板的"输入材料"段落,与其写"贴入你的零散笔记",不如附一个真实的会议纪要片段作为示范。

第三,字数与格式约束要明确。直接写"500-800 字"比"中等长度"有效;直接写"用三线表"比"用表格"有效;直接写"标题用 ##"比"用二级标题"有效。模型会严格遵守可量化的约束,模糊的形容词容易被忽略。

第四,迭代要保留历史。每次调整模板后,把旧版本单独保存,而不是覆盖——你会在回看时发现一些当时的微调其实是负向的。

第五,场景化裁剪。一份模板不可能适配所有岗位,建议每类岗位维护一份本地化版本,把团队专有的指标、术语、风格沉淀进去。

## B.8 变量占位符规范

为保证模板在不同工具之间可移植,本附录统一采用 `{{变量名}}` 形式作为占位符,具体规范如下。

命名约定:小驼峰式(camelCase),例如 `{{clientName}}`、`{{reportPeriod}}`、`{{contractAmount}}`;中文场景可以用拼音或简短中文,如 `{{客户名}}`、`{{报告周期}}`、`{{合同金额}}`。

嵌套结构:对复杂结构,使用 JSON 字符串作为占位符内容,例如 `{{lineItems}}` 的实际值可以是 `'[{"name":"基础版","qty":10,"price":99}]'`。

默认值:对非必填项,使用 `{{变量名 | 默认值}}` 形式,例如 `{{客户行业 | 互联网}}`,模型在缺失时会使用默认值。

复用约定:同一份模板多次使用同一变量时,只填一次即可,WorkBuddy 会自动复用。

## 小结

本附录提供 6 大场景、共 18 个可直接复用的提示词模板,覆盖了大多数知识工作者的日常产出。所有模板都遵循"角色 + 背景 + 任务 + 输入 + 输出"五段式结构,变量占位符统一为 `{{变量名}}` 形式,便于复制替换。建议读者先从自己最高频的场景开始试运行,3-5 份产出后就能感受到模板带来的稳定性收益。

## B.9 跨场景组合模板

实际工作中,很少有任务是单一类型的。一次季度复盘往往要综合周报、PPT 大纲、邮件回复、翻译四个场景。本节给出 3 个"组合模板",演示如何把多个场景串起来。

组合模板一:季度复盘包(覆盖周报 + 纪要 + PPT + 邮件)

```text
角色:你是一名部门负责人,正在准备本季度复盘。
输入材料:
- 13 周周报({{weeklyReports}})
- 12 场关键会议纪要({{meetingMinutes}})
- 本季度 OKR 完成情况({{okrStatus}})
- 部门同事名单({{teamMembers}})
任务:
1. 把 13 周周报合并为一份季度总结(1500-2000 字)
2. 从会议纪要中提炼 5 个关键决策与 3 个教训
3. 生成 15 页季度复盘 PPT 大纲
4. 写一封给全员的季度总结邮件(不超过 500 字)
5. 写一封给公司高管的简报(不超过 200 字)
```

## B.10 模板效果评估

再好的模板也需要持续评估。建议每个月底用以下 4 个指标评估本月使用的模板。

指标一,使用次数。每个模板本月被调用了多少次?Top 3 模板是哪些?Top 3 应该进一步打磨,Bottom 3 应该考虑下线或重写。

指标二,首次成功率。模板输出不需要人工返工的占比是多少?健康水位应 ≥ 70%,低于 50% 意味着模板需要重写。

指标三,字数偏差率。模板规定"输出 500-800 字",实际输出的中位数是否落在区间内?如果普遍偏高或偏低,需要调整"任务"段的字数约束。

指标四,积分 消耗。模板的每次平均消耗是多少?与 B.1 节基准对比,如果显著偏高,检查是否有冗余的输入材料或过度详细的输出要求。

每月底花 30 分钟做这 4 个指标的分析,持续 3 个月,你的模板库会从"凑合用"升级为"业内顶级"。

## B.11 模板共享与协作

如果你在一个团队里使用 WorkBuddy,模板共享可以节省大量重复工作。WorkBuddy 提供了 3 种共享方式。

方式一,共享文件夹。把 `templates/` 目录放在 OneDrive / iCloud Drive / 坚果云 等云盘的固定路径,所有成员指向同一份文件。优点是简单,缺点是版本冲突。

方式二,WorkBuddy 团队工作区。在"管理后台 → 团队 → 工作区"中创建团队工作区,把模板上传到工作区,所有成员从工作区拉取。优点是版本统一,缺点是需要管理员权限。

方式三,模板市场。把模板发布到 WorkBuddy 官方市场,所有人(包括其他公司的人)都可以使用。优点是影响力大,缺点是需要公开,不适合包含敏感信息的模板。

## 小结补充

本附录在原有 6 大场景 18 个模板的基础上,补充了 3 个跨场景组合模板、模板效果评估方法与团队共享方式。读者可以根据自身角色,挑选最常用的 3-5 个模板作为"起手式",持续 1-2 个月后再逐步引入其他模板与组合方案。提示词工程的本质是"用结构化降低不确定性",本附录的所有模板都是这个原则的具体体现。
