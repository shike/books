## 3.1 为什么需要多模型策略——单一绑定的风险

先讲一个真实场景。

2025 年,某中型电商公司把所有 AI 工作流绑在海外某通用大模型上(海外云端 API)。年底,海外厂商调整了价格策略——核心模型价格上涨 3 倍,且对长上下文任务加了额外费用。这家公司一年 AI 预算 80 万元,调整后变成 240 万元,直接击穿预算上限,只能砍掉一半 AI 应用。

**这是单一绑定的经典风险**——你的业务跑在别人的定价权上,任凭对方调整,你只能被动接受。

到了 2026 年,这种风险在中国市场更突出:

1. **价格波动**:国产模型竞争激烈,各厂商每年调整 1-2 次价格,单一绑定会被动承担波动
2. **能力差异**:不同模型擅长不同任务(详见 3.2 节),单一绑定意味着"用错模型"
3. **政策风险**:国内外监管政策都在快速变化,厂商服务可能随时调整
4. **可用性风险**:厂商服务故障、限流、停服,都会直接影响你的业务

**多模型策略**正是为了应对这些风险——你的工作流**不依赖**任何单一模型,而是**按任务、按成本、按可用性**动态选择最合适的模型。

WorkBuddy 的"多模型路由"是这一策略的天然载体——它内置 6-8 款国产模型,按"成本/质量/速度/隐私"四维度自动选模型(第一卷第 5 章讲过),但**对于企业级应用,这种"自动路由"还不够**——你还需要:

1. **自购 API Key**——直接跟模型厂商签合同,绕过 WorkBuddy 内置的 积分
2. **私有化部署**——在企业内网部署开源模型,数据完全不出域
3. **多模型治理**——建立团队级别的模型使用规范、成本分摊、容灾策略

本章围绕这三点展开。

## 3.3 API Key 的三种使用方式

WorkBuddy 中,调用 AI 模型有三种"通道"——

### 方式 1:WorkBuddy 内置 积分(默认)

WorkBuddy 默认用自己的 积分 体系调用模型,用户在 WorkBuddy 内置的模型池里被自动路由。优点是简单,缺点是"被绑定"——你不知道具体用了哪款模型,也不掌握成本细节。

适合:**个人用户、试点阶段、团队初步铺开阶段**。

### 方式 2:自购 API Key(团队推荐)

用户在 WorkBuddy 设置里填入自己从模型厂商购买的 API Key,WorkBuddy 直接调用该厂商的接口,不走内置 积分。

**适合:中大型团队、对成本敏感、对模型选型有明确要求的组织**。

这是本章的重点,后面 3.4 节详细讲流程。

### 方式 3:私有化部署(高级选项)

用户在企业内网部署开源模型(如 DeepSeek 开源版、Qwen 开源版、智谱 GLM 开源版等),WorkBuddy 通过本地网络调用这些模型,数据完全不出域。

**适合:对数据安全有极端要求的组织(金融、医疗、政务等)**。

后面 3.7 节详细讲边界条件。

## 3.4 自购 API Key 的标准流程

以下流程基于"团队级 API Key 采购与接入"的标准做法。**具体厂商的入驻流程、计费规则、API 配额以各模型厂商官方文档为准**——以下给你的是通用骨架。

### Step 1:注册企业账号

到模型厂商官网(如 DeepSeek 开放平台、Kimi 开放平台等),注册**企业账号**(不是个人账号),需要:

- 营业执照
- 法人身份证
- 对公账户信息(用于结算)
- 企业联系人

审核周期通常 1-3 个工作日。

### Step 2:申请 API Key

登录企业控制台,创建 API Key。每个 Key 对应一个调用入口,可设置:

- 名称(便于识别,如"市场部专用")
- 权限范围(允许调用哪些模型)
- 配额上限(每月调用上限,防止误用超额)
- IP 白名单(只允许特定 IP 调用,提升安全)

**建议**:不同部门、不同项目用不同 Key,便于成本核算和权限管理。

### Step 3:在 WorkBuddy 配置 API Key

打开 WorkBuddy → 设置 → 模型与 API Key → 添加 API Key:

- 选择厂商(如"DeepSeek")
- 填入 API Key
- 测试连通性
- 保存

这一步完成后,WorkBuddy 就可以直接调用该厂商的模型,**不再消耗 WorkBuddy 内置 积分**。

### Step 4:配置多 Key 路由

如果团队用了多个厂商的 API Key,WorkBuddy 支持配置"多 Key 路由规则":

- 按任务类型路由(长文档 → Kimi,数据分析 → DeepSeek)
- 按成本路由(优先用便宜的)
- 按可用性路由(某 Key 故障时自动切换备选 Key)
- 按权限路由(财务部用某个 Key,研发部用另一个)

### Step 5:成本监控

WorkBuddy 提供"API Key 使用明细"页面,显示:

- 每个 Key 的调用次数
- 每次调用的 token 数
- 每次调用的成本
- 每月累计成本

**建议**:每周 review 一次,识别"异常高消耗"的任务,及时调整。

## 3.5 成本计算与优化

### 3.5.1 成本结构

AI 模型的成本由两部分组成:

- **输入 token**:你发给模型的文本量
- **输出 token**:模型生成返回的文本量

两个方向都计费,**通常输出 token 比输入 token 贵 2-4 倍**。

成本公式:

```
任务成本 = 输入 token 数 × 输入单价 + 输出 token 数 × 输出单价
```

(具体单价以各模型厂商最新报价为准。)

### 3.5.2 实战:一份周报生成任务的成本

我用第一卷"周报生成"场景做估算:

| 步骤 | 输入 token | 输出 token |
|---|---|---|
| 读取本周邮件 | 50,000 | 0 |
| 读取本周聊天 | 30,000 | 0 |
| 读取本周文档 | 20,000 | 0 |
| Step 1 事件归纳 | 100,000 | 5,000 |
| Step 2 事件分类 | 5,000 | 1,000 |
| Step 3 措辞润色 | 1,000 | 2,000 |
| Step 4 输出 | 2,000 | 1,500 |
| **合计** | **208,000** | **9,500** |

以 DeepSeek 为例(输入 0.14 元/百万 token,输出 2 元/百万 token,2026 年 8 月报价):

- 输入成本:208,000 / 1,000,000 × 0.14 = 0.029 元
- 输出成本:9,500 / 1,000,000 × 2 = 0.019 元
- **单次周报总成本:0.048 元**

**一年 52 周**:52 × 0.048 = 2.5 元(纯模型成本)

这个数字看起来不可思议地低——但这是真实的,2026 年的国产模型价格已经做到"几乎免费"。

但这只是"纯模型成本",完整成本还包括:

- **WorkBuddy 订阅费**(具体档位以 WorkBuddy 官方为准)
- **人工 review 时间**(每次 15-30 分钟)
- **Skill 维护时间**(每月 1-2 小时)
- **审计日志存储成本**(可忽略,本机存储)

**完整年成本估算**(以中型团队 20 人计算,具体数字以你团队实际数据为准):

| 项 | 成本 |
|---|---|
| 20 个 WorkBuddy 订阅 | 以 WorkBuddy 官方为准 |
| 模型 API 调用 | 约 200-1000 元/年(团队总计) |
| 人工 review 时间 | 主要"时间成本",通常算 ROI 的主要贡献 |
| Skill 维护 | 主要是开发者时间成本 |

### 3.5.3 成本优化技巧

我给五条经过验证的优化技巧。

**技巧 1:用"小模型"做"小任务"**

不是所有任务都需要最强大的模型。改个错别字、做格式调整——这些用最小的模型就够了,成本能压到 1/10。

WorkBuddy 的多模型路由支持"小任务自动降级",你不用手动选。

**技巧 2:减少输入 token**

输入 token 是成本大头。优化方法:

- 用"摘要后送 AI"代替"原文送 AI"
- 用"分块处理"代替"一次性送"
- 用"文件引用"代替"文件内容复制"(WorkBuddy 支持)

**技巧 3:缓存重复请求**

同一个团队,经常问相似的问题(比如"我们的周报模板是什么")。用缓存机制,第二次问直接返回缓存,不计 token。

WorkBuddy 企业版支持"组织级缓存"。

**技巧 4:批量任务打包**

"给 50 个客户发跟进邮件"——不要让 WorkBuddy 跑 50 次,而是**让它一次生成 50 封邮件草稿**,然后批量发送,可以省 30-50% token。

**技巧 5:设置月度预算**

给每个 API Key 设月度预算上限,避免误用超额。WorkBuddy 在接近预算时会提前告警。

## 3.6 稳定性与容灾

### 3.6.1 单一模型的可用性风险

2025-2026 年,国产 AI 模型服务出现多次大规模故障——

- 某模型厂商在 2025 年 Q3 出现 6 小时全局故障,数万家依赖该模型的业务中断
- 某厂商 2026 年 Q1 因算力紧张,对部分客户限流,长上下文任务排队 30 分钟+
- 某厂商 2026 年 Q2 调整安全策略,某些敏感词触发更严格的内容审核,误杀率上升

**多模型容灾**,就是为应对这些场景。

### 3.6.2 容灾策略

| 策略 | 实施方式 | 适用 |
|---|---|---|
| **主备切换** | 关键任务配 2-3 个模型的 API Key,主 Key 故障自动切备 | 关键业务 |
| **降级服务** | 某模型不可用时,自动用次优模型替代 | 大多数任务 |
| **本地兜底** | 关键场景配私有化模型作为最终兜底 | 极端重要场景 |

WorkBuddy 的多模型路由默认支持"主备切换"和"降级服务"。配置方法:

```
设置 → 模型路由 → 容灾策略:
- 主要模型:DeepSeek-V3
- 备用模型 1:Kimi
- 备用模型 2:通义千问
- 切换条件:主模型连续 3 次失败 / 响应时间 > 30 秒 / 限流错误
```

### 3.6.3 SLA 视角

对企业级用户,要关注模型厂商的 SLA(服务等级协议):

- **可用性承诺**:通常 99.5% - 99.9%(年停机时间 4-44 小时)
- **响应时间承诺**:不同模型承诺不同
- **赔付条款**:未达 SLA 的赔付

**不要只看价格,要看 SLA**。一个 SLA 99.9% 的贵模型,可能比 SLA 99.5% 的便宜模型更划算——因为业务中断的代价远大于模型差价。

## 3.7 私有化部署的边界条件

### 3.7.1 什么是私有化部署

私有化部署 = 在企业自己的服务器(或私有云)上跑开源大模型,数据完全不出域,模型调用走内网。

常用开源模型:

- DeepSeek 开源版(7B / 67B 等规格)
- Qwen 开源版(7B / 14B / 72B 等)
- GLM 开源版
- Yi(零一万物)
- Baichuan(百川)
- Llama 开源版(海外)

(以上为常用选项,具体版本与能力以各开源社区最新发布为准。)

### 3.7.2 私有化部署的成本

私有化部署的真实成本,大多数组织低估了。我列全成本项:

| 成本项 | 量级(参考) | 备注 |
|---|---|---|
| GPU 服务器采购 | 几十万元到几百万元 | 取决于模型规格 |
| 机房 / 云租赁 | 几万-几十万/年 | 取决于规模 |
| 电费 | 几万-几十万/年 | GPU 耗电 |
| 运维人员 | 1-3 人,年薪 30-80 万 | 模型微调、监控、故障处理 |
| 模型微调 | 几万-几十万/次 | 适配企业数据 |
| 升级维护 | 持续投入 | 新版本更新 |

对一个 50 人团队,完整私有化部署的年成本通常在 **150-500 万元**(以一线城市硬件与人力的市场价计算,具体以你团队实际部署数据为准)。

这个数字,远超订阅云端服务的年成本。

### 3.7.3 什么场景值得做

**值得做的场景**:

1. **强监管行业**:金融、医疗、政务,法律强制要求数据不出域
2. **核心商业机密**:战略规划、客户数据、研发代码
3. **超大规模使用**:月调用 token 超过 1 亿,自建比订阅更便宜
4. **定制化需求**:需要基于企业数据微调模型

**不必做的场景**:

1. **普通企业内部使用**:周报、邮件、纪要、文档,WorkBuddy 内置 + 自购 API Key 已足够
2. **小团队(5-20 人)**:用不起,也用不满
3. **没有运维能力**:私有机房/服务器需要专人维护,小团队养不起

### 3.7.4 折中方案:混合托管

对大多数组织,折中方案是"**混合托管**"——

- 核心数据(客户名单、合同、源代码)走私有化或本地
- 非核心数据(周报、邮件、公开文档)走自购 API Key(国产云)
- 极敏感的(战略规划)走本地+人工审核

WorkBuddy 支持这种"分层数据策略"——在权限配置里,不同文件夹走不同通道。

## 3.9 企业级多模型治理

### 3.9.1 模型使用规范

建议团队制定《AI 模型使用规范》,至少包含:

1. **允许使用的模型清单**:基于合规、成本、能力评估
2. **禁止使用的模型清单**:对某些厂商有合规或合作限制
3. **不同任务类型的默认模型**:减少个人随意选择
4. **数据分级**:哪些数据可以用云端模型,哪些只能用本地
5. **审批流程**:采购新 API Key、引入新模型要走什么流程

### 3.9.2 成本分摊

大团队的成本分摊,通常有三种模式:

| 模式 | 适合 | 优缺点 |
|---|---|---|
| **部门预算制** | 部门独立核算 | 公平,但跨部门协作难 |
| **项目预算制** | 项目制组织 | 精准,但管理成本高 |
| **中心预算制** | 集中管理 | 简单,但吃大锅饭 |

我推荐:**"中心预算 + 项目标记"**——模型 API Key 由公司统一采购、统一结算,但每次调用都标记"所属项目",月底按项目做成本归集。

WorkBuddy 支持"项目标记"功能,具体以官方文档为准。

### 3.9.3 模型迭代跟踪

国产模型迭代很快(平均 2-3 个月一次大版本)。团队要建立"模型跟踪机制":

- 每月:看厂商更新日志,识别新版本
- 每季度:用业务真实数据做 A/B 测试,看新模型是否更优
- 每半年:重新评估模型选型,可能调整默认配置

我建议团队设一个"AI 工具委员会"(2-3 人),专门负责这件事。

### 3.9.4 异常使用监控

监控三类异常:

1. **Token 暴涨**:某员工某天突然消耗 10 倍 token,可能误用或滥用
2. **敏感内容**:调用日志里出现敏感关键词,可能涉及合规风险
3. **异常时段**:凌晨 3 点突然有大量调用,可能账号被盗用

WorkBuddy 企业版的审计日志支持这些监控(具体功能以官方文档为准)。

## 3.10 真实案例:一家 50 人咨询公司的多模型策略

最后给一个完整案例。

**公司背景**:某管理咨询公司,50 人,主要为大型企业提供战略咨询。痛点是研究员每周花大量时间做"行业资料搜集 + 整理",效率低。

**AI 落地过程**:

**阶段 1(2025 Q4)**:试点。3 个研究员用 WorkBuddy 内置 积分,主用 Kimi(读行业报告 PDF)+ DeepSeek(分析数据)。每月 积分 消耗 200-300 元(具体以 WorkBuddy 官方为准)。

**阶段 2(2026 Q1)**:扩展。15 个研究员加入。采购了 DeepSeek 和 Kimi 的企业 API Key,自己控制成本。每月模型成本 800-1500 元(具体以厂商报价为准)。

**阶段 3(2026 Q2)**:优化。建立模型使用规范:
- 长文档阅读 → Kimi
- 数据分析 → DeepSeek
- 中文写作 → 智谱清言
- 行业调研 → 文心一言

每月模型成本稳定在 1000-1800 元(具体以实际数据为准)。

**阶段 4(2026 Q3)**:集成。WorkBuddy 与公司知识库系统集成,研究员可以一键调用行业资料。

**ROI 评估**(具体以该公司实际数据为准):
- 试点前:每份行业报告平均 5 个工作日
- 试点后:每份行业报告平均 2.5 个工作日
- **效率提升 50%**
- 模型成本:约 1500 元/月,折合每人每天 5 元

公司 CFO 评价:"AI 模型成本可以忽略不计,但研究员时间节省是巨大的。"

## 3.11 小结

本章讲了五个核心判断:

1. **多模型策略是企业级 AI 的标配**——单一绑定带来价格、能力、政策、可用性四重风险。
2. **国产 6 款主流模型各有所长**——WorkBuddy 的多模型路由帮你自动选,但企业级用户要更深一层:自购 API Key、私有化部署、混合托管。
3. **自购 API Key 的核心是"成本控制 + 选型自主"**——一旦掌握,就从"被定价"变成"主动选择"。
4. **私有化部署有明确的边界条件**——大多数组织不需要,只在"强监管 + 核心机密 + 超大规模 + 定制需求"四类场景下值得。
5. **企业级多模型治理是组织工作**——使用规范、成本分摊、迭代跟踪、异常监控,缺一不可。

下一章,我们从"模型层"进入"系统层"——讲 WorkBuddy 怎么跟企业现有的 OA、CRM、知识库、BI、工单系统对接,以及对接的常见架构模式。
