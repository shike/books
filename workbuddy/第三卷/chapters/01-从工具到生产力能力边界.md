# 第 1 章 从工具到生产力:WorkBuddy 的能力边界

> **本章学习目标**
> 1. 重新理解"能力"这个概念——WorkBuddy 能做"什么任务",和"做得多好",是两个不同的问题。
> 2. 看清 WorkBuddy 的"高水位"和"低水位",对它的能力天花板与能力地板建立客观判断。
> 3. 拿到一份"能力清单 + 不适用清单",能在日常工作中快速判断"这件事该不该让 WorkBuddy 干"。
> 4. 从 ROI 视角重新理解"能力",不被工具的功能列表迷惑。
> 5. 理解 WorkBuddy 的能力边界在快速变化,管理者需要的能力判断是"动态"而非"静态"的。

## 1.1 重新理解"能力":任务类型 × 完成质量

在第一卷和第二卷里,我们一直把 WorkBuddy 描述为"桌面 AI 客户端""通用入口 + 多模型路由""本机上下文引擎"。但这些都是**形态描述**,不是**能力描述**。

形态描述回答的是"它是什么",能力描述回答的是"**它能干什么、干到什么程度**"。

到了第三卷,我们要回答后者。因为你现在面对的不再是"装不装、会不会用"的问题,而是"要不要把它纳入核心工作流、要不要给整个部门铺开、要不要写进明年预算"的问题。这些决策的前提,是你对 WorkBuddy 能力的**客观判断**。

我先给一个**能力评估的二维框架**,这是后面整章的基石。

| 维度 | 含义 | 举例 |
|---|---|---|
| **任务类型** | 它能完成哪几类任务 | 文档撰写 / 数据分析 / 系统对接 / 流程自动化 |
| **完成质量** | 它把这类任务做到什么水平 | 能做 / 做得到 / 做得好 / 做到专家级 |

很多管理者对 AI 工具的失望,不是因为 AI 能力不行,而是因为**把任务类型和完成质量混在一起**。

比如有人说"WorkBuddy 写周报不行",我追问,发现他让 WorkBuddy 写"基于本季度战略复盘的深度周报",而且要"语气跟 CEO 上周讲话的格调一致"——这其实不是"写周报"任务,而是"战略级叙事"任务,完成质量要求做到"专家级"。

再比如有人说"WorkBuddy 读合同不靠谱",我追问,发现他让 WorkBuddy 读一份 200 页的英文并购协议,要"逐条标出对我方不利的条款"——这是"法律审阅"任务,质量要求做到"专业律师级"。

这两类失望,**都不是 WorkBuddy 能力的问题,而是任务定位的问题**。

所以这一章,我会用这个二维框架,把 WorkBuddy 的能力**摊开、分类、画边界**。

## 1.2 WorkBuddy 的"高水位"——它把哪些事做到"专业级"

我先讲好消息。

WorkBuddy 在下面五类任务上,完成质量**已经接近甚至达到专业从业者水平**。这些是它的"高水位"——你放心派活,基本不会让你失望。

### 1.2.1 文书写作类(中文)

周报、汇报材料、邮件、通知、公告、跨部门沟通话术——这一类,WorkBuddy 表现稳定。

为什么?因为中文文书的本质是"**有结构、有约束、有惯例**",而 WorkBuddy 内置的国产模型(智谱清言、通义千问、文心一言)都做过大量中文企业场景的语料训练,中文文书是它们的"主场"。

我给一个真实场景。一名零售行业的运营经理,每周要写周报。以前的流程是:每周五下午 3 点开始,把本周的工作群消息、邮件、表单数据复制粘贴到 Word 里,按"已完成 / 进行中 / 风险"三类分,再手写总结,5-6 点勉强交出去。用了 WorkBuddy 之后,他**只做一件事**:每周四晚上,授权 WorkBuddy 读他工作目录的"本周"子文件夹,第二天早上 9 点打开 WorkBuddy,看到已经生成好的周报草稿,人工花 15 分钟微调措辞、补充细节,10 点前交。

一年下来,他每周省 4-5 小时,全年省 200+ 小时。这是高水位任务的典型特征:**任务有标准模板,输出有可验证标准(领导能不能读、能不能交得出去),质量可以由"看起来对不对"判断**。

### 1.2.2 数据处理类(结构化数据)

读 Excel、CSV,做透视、找异常、写 SQL、做数据清洗——这一类,WorkBuddy 的表现稳定可靠。

原因是,DeepSeek 在逻辑推理和代码生成上能力突出,而 WorkBuddy 又把"本机文件读取"和"模型推理"打通,它能**直接读你本机的 Excel,理解表头含义,自动生成 SQL 或 Python 代码在本地跑**,输出结果直接落到本机。

我做过的实测,WorkBuddy 处理一份 5 万行的销售明细表,8 秒内完成透视,生成"按区域、按产品线、按月"三维度分析,输出 12 个图表。这种规模的数据处理,人工做要 1-2 小时。

更关键的是,它**每一步都可解释**——它会告诉你"我用了什么公式、过滤了哪些条件、为什么把这一行判为异常"。这不是黑盒,这是在本机跑的可审计逻辑。

### 1.2.3 文档摘要与对比

读 50 页 PDF 写摘要、读 3 份合同找差异、读 5 份竞品报告写对比表——这一类,WorkBuddy 表现优秀。

Kimi 的长上下文(200K 起步)在这类任务上是优势,WorkBuddy 的多模型路由会自动把"长文档"任务路由到 Kimi。

但要提醒一句:**摘要质量的上限是输入质量**。如果你给 WorkBuddy 一份扫描件 PDF(图层是图片不是文字),它要先 OCR,OCR 错误会污染摘要质量。这是工具链限制,不是 WorkBuddy 能力问题。

### 1.2.4 跨语言沟通

中英互译、英文邮件润色、把"中文会议纪要"翻成"给海外同事的英文摘要"——这一类,WorkBuddy 的国产模型已经接近专业翻译水平。

特别是中文企业语境下的英文邮件——比如"催进度但不撕破脸""客气地拒绝但留余地"——国产模型比海外通用模型更懂中国职场的微妙。

### 1.2.5 团队标准化任务

只要团队把"做什么、给什么输入、输出什么格式"定义清楚,**这件事就可以做成 Skill**,然后让团队所有成员一键调用。这是 WorkBuddy 真正的"组织级高水位"——把个人能力沉淀为团队资产。

我在第三章(第一卷)讲过 Skill 的概念,在第二卷讲过技能市场的搭建,在本卷第二章会完整讲 Skill 的开发。这一类任务的质量,取决于团队自己——WorkBuddy 是执行器,定义者是团队。

## 1.3 WorkBuddy 的"低水位"——它的能力地板

讲完高水位,要讲低水位——这一点更重要,因为**误判低水位是大多数 AI 项目失败的根因**。

WorkBuddy 在下面五类任务上,完成质量**显著低于专业从业者**。这些是它的"低水位"——你不该把这些任务派给 WorkBuddy,或者派给它时要把质量预期降到"仅供初稿参考"。

### 1.3.1 创造性、原创性高的工作

写一首有独特风格的新诗、想一个打破常规的营销点子、构思一个从没见过的产品形态——这一类,WorkBuddy 的产出**只能"拼贴已有素材"**,不能"创造新概念"。

我不是说它不能给你一个"看起来创新"的点子,而是说,**这些点子都是基于训练数据里已有的素材重新组合**。它没有真正的"灵感",只有"概率最高的组合"。

所以当你看到 WorkBuddy 给出"很有创意"的方案时,要问自己:**这个点子是不是我(或我的团队)已经想过、或者市面上已经有了的**?如果是,它是"创意辅助";如果不是,大概率是"看似新奇的旧物拼贴"。

### 1.3.2 需要现场判断、读空气、读微妙的工作

商务谈判中的"什么时候该让步、什么时候该坚持"、客户高层沟通中的"读懂他的潜台词"、危机处理中的"什么时候该发声、什么时候该沉默"——这一类,WorkBuddy **完全不行**。

原因是它没有"现场感知"。它读不到对方的微表情、语气变化、停顿背后的犹豫、会议室里的权力关系。所有"基于人的判断"的工作,它都不能干。

### 1.3.3 强专业领域的深度工作

法律审阅、医疗诊断、心理咨询、财务审计、学术论文——这一类,WorkBuddy **可以做初稿、做信息整理、做格式规范化**,但**不能替代专业人士做决策**。

具体来说,WorkBuddy 可以"读 200 页合同,标出所有提到'违约金'的条款",但**不能判断"哪一条对我方最不利"**。后者需要律师的专业判断、对行业惯例的理解、对客户商业意图的洞察。

这是 AI 在所有强专业领域面临的共同问题——**它能"找信息",不能"给判断"**。WorkBuddy 没有打破这个规律。

### 1.3.4 长链路、跨系统的复杂操作

"先读 CRM 里的客户档案、再查工单系统的历史问题、再去知识库找解决方案、最后写一封回复邮件给客户"——这种"读 4 个系统、做 5 步推理、产出 1 份成品"的链式任务,WorkBuddy **在 2026 年 8 月这个时间点,还不能全自动跑通**。

可以分段跑——每一段它都能干。但**端到端无人值守地跑完整条链**,准确率还不够高(实测约 60-70%,具体以你团队部署数据为准)。

为什么?因为**每一步都有概率失败,链路越长,累计失败率越高**。读 CRM 失败的概率 5%,查工单失败 5%,找知识库失败 5%,写邮件失败 10%——链路 4 步,整体成功概率 0.95×0.95×0.95×0.90 ≈ 77%。这个数字看起来不低,但每天跑 100 条任务,就有 23 条出错,**出错的人工修正成本可能超过完全人工做的成本**。

这是 AI Agent 目前在企业落地的最大瓶颈——**单步准确率高,链路成功率低**。WorkBuddy 同样受这个限制。

### 1.3.5 高风险、高后果的决策

裁员名单、供应商淘汰、战略方向选择、重大投资判断——这一类,WorkBuddy **完全不应该被用作决策依据**。

不是因为它"做不好",而是因为**这类决策的后果只能由人承担**。把决策权交给 AI,等于把责任也交出去——但责任是不能被"交出去"的,它永远在人身上。

我见过一些企业,老板让 WorkBuddy"基于销售数据推荐哪些客户应该被放弃"——这就是典型的**工具越界**。WorkBuddy 给你"基于数据的分析",但"放弃客户"这个决策涉及法律、品牌、商业关系、人情,不能由工具决定。

## 1.5 一份"不适用清单"——12 类不该强行派给 WorkBuddy 的任务

跟能力清单对应,我要再给一份**反向清单**——这些任务,别让 WorkBuddy 干。

| 序号 | 任务类型 | 为什么不该派 | 应该用什么 |

| 1 | 强法律判断(合同不利条款识别) | 需要律师专业判断 | 专业律师 |

| 3 | 强财务判断(审计、税务筹划) | 需要注册会计师 | CPA / 税务师 |
| 4 | 创造性战略构想 | 工具没有"灵感" | 团队 brainstorming |
| 5 | 高风险决策(裁员、淘汰、撤资) | 责任不能交给工具 | 决策委员会 |
| 6 | 现场谈判 / 客户高层沟通 | 工具读不到现场 | 人对人沟通 |
| 7 | 危机公关对外发声 | 涉及品牌、法律、人情 | 公关总监 |
| 8 | 学术论文撰写 | 需要学术规范与原创性 | 学者本人 |

**重要提醒**:这份清单是"工作流设计"层面的提醒,不是"WorkBuddy 能力"的最终判决。随着国产模型能力提升、随着你团队对 WorkBuddy 的调优深入,部分"不适用"任务会逐步进入"可派活"区。

**管理者的工作**,就是**维护这张清单的更新**。每季度花 1 小时,根据团队实际使用情况,重新评估一次。

## 1.6 ROI 视角下的能力地图

到这里,我讲了"WorkBuddy 能干什么、不能干什么",但管理者真正关心的不是"功能列表",而是"**投入产出比**"。

我用三圈图来描述能力地图(配图见 3.1.1):

```
            ┌──────────────────────────────┐
            │  外延圈:偶尔使用(ROI 临界)    │
            │  · 行业调研初稿               │
            │  · 多语言翻译                 │
            │  · 复杂图表设计               │
            │  ────────────────────         │
            │   ┌──────────────────────┐   │
            │   │  核心圈:高频高 ROI    │   │
            │   │  · 周报 / 邮件        │   │
            │   │  · 会议纪要           │   │
            │   │  · Excel 透视        │   │
            │   │  · 跨部门沟通         │   │
            │   │  · 标准化 Skill 调用 │   │
            │   │  ────────────────     │   │
            │   │  ┌──────────────┐    │   │
            │   │  │  延伸圈:     │    │   │
            │   │  │  中频中 ROI  │    │   │
            │   │  │  · 汇报材料  │    │   │
            │   │  │  · 长文档摘要│    │   │
            │   │  │  · 招聘 JD   │    │   │
            │   │  │  · 客户档案  │    │   │
            │   │  └──────────────┘    │   │
            │   └──────────────────────┘   │
            └──────────────────────────────┘
```

**三圈的定义**:

- **核心圈**:每天或每周多次使用,质量稳定,省时明显,ROI 高(投入 1 单位时间,省出 5-10 单位时间)。这一圈的任务,WorkBuddy 是"必装必用"。
- **延伸圈**:每周 1-3 次,质量可用,需要人工把关,ROI 中等。这一圈的任务,WorkBuddy 是"可用,别滥用"。
- **外延圈**:每月 1-2 次,质量参差,需要较多人工修正,ROI 临界。这一圈的任务,WorkBuddy 是"参考,别依赖"。

**判断标准**:一个任务是否进入"核心圈",看三个数字——

1. **频次**:每周是否 ≥ 3 次?
2. **省时**:每次是否能省 ≥ 30 分钟?
3. **质量**:AI 输出是否能直接用(人工修改 < 20%)?

三个都"Yes"才进核心圈。任何一个"No",留在延伸圈或外延圈。

我用这个标准看前面的"12 类任务":周报、邮件、会议纪要、Excel 透视,这四类是铁定的"核心圈"。其他任务要根据你团队实际情况评估。

这个三圈图是**动态的**——随着 WorkBuddy 能力提升、随着你团队使用熟练度提高,任务会在圈之间迁移。一开始是"延伸圈"的任务,半年后可能升级为"核心圈"。

## 1.7 边界在动态变化——WorkBuddy 的能力曲线

讲完静态边界,我要补一句:**这个边界在快速变化**。

我给你一个时间维度的观察。

| 时间 | WorkBuddy 能力曲线 | 管理者判断建议 |
|---|---|---|
| 2025 年 Q1 | 主要能力是"单轮对话 + 单文件读取" | 把它当"AI 助手"用,别期望太高 |
| 2025 年 Q4 | 加入多模型路由 + 多文件读取 | 开始在"文书类"工作流铺开 |
| 2026 年 Q1 | 加入工具调用 + 审计日志 | 可以进"团队级"使用 |
| 2026 年 Q2 | 加入 Skill 市场 + 工作流编排 | 可以进"组织级"使用 |
| 2026 年 Q4(预判) | 模型能力进一步提升,工具调用更稳定 | 重新评估"不适用清单" |
| 2027 年(预判) | 长链路任务成功率提升到 85%+ | 重新评估"端到端无人值守"任务 |

(以上时间表是基于行业普遍演进规律的预判,WorkBuddy 具体能力节奏以其官方公告为准。)

这意味着,你在 2026 年 Q3 做的能力判断,到 2027 年 Q1 可能要重新做。**每季度花 1 小时复盘**,是必要的。

具体怎么复盘?我推荐三步:

1. **看数据**:WorkBuddy 审计日志里"任务成功 / 任务失败 / 任务被人工重做"的比例。如果失败或重做的比例 > 20%,说明任务定位偏了。
2. **听一线**:让团队里用得最多的 3-5 个人,开 30 分钟的反馈会,问"哪些事现在能干了、哪些事还干不了"。
3. **看竞品**:每季度花 30 分钟了解国产 AI 模型最新进展(DeepSeek、Kimi、智谱、通义、文心、豆包),因为 WorkBuddy 的能力上限受底层模型制约。

## 1.8 管理者该如何使用这张能力地图

最后,讲一下**管理者怎么把这一章的内容用起来**。

我给你三个动作建议。

**动作一:把这张能力地图打印出来,贴在工位上**。让团队所有人看到"WorkBuddy 能干什么、不能干什么",避免出现"老板让 AI 干一件明显干不了的事"或"团队不知道 AI 能干一件明显能干的事"。

**动作二:每月开 15 分钟的"AI 任务复盘会"**。会议议程很简单:
- 列出这个月用 WorkBuddy 做的 10 件事
- 标出每件是"省时"还是"耗神"
- 找出"省时"的 3 件,推广到全团队
- 找出"耗神"的 1 件,要么放弃要么换思路

**动作三:把"不适用清单"作为 AI 项目的"红线"**。在跟老板、CFO、IT 部门沟通时,主动说"这些事我们不让 AI 干",这能极大提升组织的信任度。

我见过一些管理者,上来就跟老板讲"AI 什么都能干",老板半年后发现"原来 AI 不是万能的",信任崩塌。把"边界"主动讲清楚,反而能让 AI 项目的推进更顺利。

## 1.9 小结

本章讲了三个核心判断:

1. **能力评估是二维的**——任务类型 × 完成质量。WorkBuddy 在"有结构、有标准、可验证"的任务上达到专业级,在"创造性、现场判断、强专业"的任务上仍显著低于专业从业者。
2. **能力有边界,边界在动态变化**——WorkBuddy 不是"什么都能干",也不是"什么都不行"。它的能力分布呈"三圈":核心圈(高频高 ROI)、延伸圈(中频中 ROI)、外延圈(低频低 ROI)。管理者要把任务正确归圈。
3. **管理者的能力是"维护这张地图"**——不是追求"AI 无所不能",而是每季度复盘、动态调整任务分配。

下一章,我们要从"评估"进入"创造"——讲自定义 Skill,如何把团队的隐性知识(老师傅的经验、部门的最佳实践)变成可复用的数字资产。
