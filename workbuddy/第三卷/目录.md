# 第三卷 目录

## 当桌面 AI 走向团队

第一卷回答"为什么用"、第二卷回答"怎么用",第三卷回答:**当 WorkBuddy 不再只属于你一个人,而是走进团队、走进部门、走进整个公司,你会遇到哪些新问题?**

个人生产力只是起点。真正决定桌面 AI 价值的,是它能否在一个组织里稳定运行、被人愿意使用、产生可衡量的业务回报。本卷面向三类读者:把 AI 推荐给团队的部门负责人、为采购决策提供意见的 IT 与信息安全负责人,以及需要评估投资回报的业务负责人。

本卷与前两卷术语统一,关键名词见附录 B,提示词模板见附录 C。

## 一 从工具到生产力:WorkBuddy 的能力边界

**定位**:个人用 WorkBuddy 是"提效",组织用 WorkBuddy 是"重新分配工作"——难度不在一个量级。

本章为你建立一把"能力尺":哪些场景能稳定产出,哪些需要人工兜底,哪些目前还做不到。读完你会拿到能力象限图、六种典型失败模式清单,以及一条决策线——任务同时涉及"对外承诺"和"不可逆操作"时,WorkBuddy 应当处于哪个位置。

**主要小节**

- 能力象限:把任务按频率和风险分类
- 六个常见失败模式与应对方式
- 个人提效 ≠ 组织提效:对照表
- 给团队负责人的三条边界建议

---

## 二 自定义 Skill:把隐性知识变成可复用资产

**定位**:团队里最贵的不是 AI 订阅费,而是"只有张三会做"的那部分经验。

本章带你把"专家脑子里的那点东西"沉淀成可被所有人调用的 Skill。你会学到 Skill 的三段式结构(触发条件 + 操作步骤 + 验收标准)、用 5 次访谈提炼隐性方法,以及避免"Skill 写出来没人用"的陷阱。读完你能独立完成一个最小可用 Skill 的设计、撰写、测试和上线。

**主要小节**

- Skill 三段式:触发条件、操作步骤、验收标准
- 用 5 次访谈提炼隐性方法
- Skill 的最小可用版本(MVP)
- Skill 库治理:命名、版本、权限
- 把 Skill 接到日常流程里

## 三 API Key 与多模型策略

**定位**:不是所有任务都值得用最贵的模型,关键是把对的模型用在对的环节。

本章拆解 API Key(模型提供方颁发的访问凭证,用于按量计费调用大模型)背后的成本结构、限流规则和风险。你会看到"任务—模型匹配表":写作用便宜模型足够,代码审查必须用强推理模型,敏感数据处理要走私有部署。还会介绍多模型路由(Multi-Model Routing)的三种实现方式。

**主要小节**

- API Key 的工作机制与计费方式
- 任务—模型匹配表
- 多模型路由:三种实现路径
- 预算与限流的工程化做法
- 模型升级时的平滑切换

## 四 与企业系统对接

**定位**:WorkBuddy 的真正威力在于它能读你电脑里的东西——但"读什么"和"写什么"必须由你来定。

本章聚焦 WorkBuddy 如何与企业现有系统打通。你会学到本地连接器(Connector)的部署方式、如何通过 MCP(Model Context Protocol,让 AI 客户端与外部工具安全通信的开放协议)接入 CRM 和 ERP,以及"读得到但传不出"的隔离配置。案例覆盖飞书多维表(Bitable)、Salesforce、Notion 三种典型环境。

**主要小节**

- 本地连接器与权限边界
- MCP 协议入门
- 连接飞书、Salesforce、Notion 的实战
- 双向同步与冲突处理
- 上线前的接口测试清单

## 五 组织级 ROI 怎么算怎么讲

**定位**:"每周省 5 小时"在 CFO 眼里一文不值——除非你把它换算成钱、风险和战略对齐度。

本章给你"三段式 ROI(投资回报率)表达法":从时间节省(投入)→ 业务结果(产出)→ 风险与机会成本(对照),讲清楚怎么用一份四页 PPT 说服高管。你会拿到可直接填写的 ROI 计算表、三个脱敏案例,以及"省钱型 ROI"和"增收型 ROI"的区别。

**主要小节**

- 为什么"省时间"打动不了 CFO
- 三段式 ROI 表达法
- 四页 ROI PPT 的结构
- 案例:三家企业的改造前后数据
- 避坑:常见 ROI 造假与识破

## 六 变革管理:会用不等于愿用

**定位**:技术解决"会不会",但解决不了"愿不愿"——后者是组织行为问题。

本章借鉴 ADKAR 模型(个人变革五阶段:Awareness 认知、Desire 意愿、Knowledge 知识、Ability 能力、Reinforcement 巩固),拆解推广 WorkBuddy 在不同阶段会遇到的阻力。你会看到"早期采用者画像",学到用"种子用户—示范项目—制度化"三步走把使用率从 10% 推到 60%。

**主要小节**

- 为什么 80% 的 AI 推广项目死在第 6 个月
- 早期采用者画像与招募策略
- 示范项目设计:小而美的样板间
- 推过临界点:从 10% 到 60%
- 当团队说"不":三类抗拒的拆解

## 七 数据安全与合规

**定位**:客户名单、合同金额、未公开财报——这些东西能喂给 WorkBuddy 吗?这一章给你答案。

本章基于截至 2026 年 8 月可执行的中国《个人信息保护法》《数据安全法》和欧盟 GDPR(通用数据保护条例)要求,梳理企业部署 WorkBuddy 必须做满的"五件套":数据分级、传输加密、本地化部署、审计日志、员工培训。你会拿到一份可直接给法务的合规清单,以及三种高危场景的处置建议。

**主要小节**

- 企业数据的五个等级与对应处理方式
- 传输加密与本地化部署选项
- 审计日志:记录什么、保留多久
- 跨境数据:WorkBuddy 走哪条线路
- 合规清单与员工培训要点

## 八 未来 12 到 24 个月

**定位**:桌面 AI 还在以季度为单位迭代——这一章帮你把"半年后的事"提前想清楚。

本章基于已有公开信息(WorkBuddy 官方 2026 年 7 月路线图、主流模型厂商发布节奏、行业数据)做有节制的预测,不夸大、不神话。你会看到三个确定性方向(Agent 化、本地化、流程化)、两个不确定方向(多模态成熟度、监管节奏),以及一份准备清单。

**主要小节**

- 三个确定性方向:Agent、本地、流程
- 两个不确定方向:多模态与监管
- 企业现在该做的三件准备
- 个人能力栈的迁移路径
- 写给 2028 年的你:一封短信
