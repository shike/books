## 一、为什么政企是 WorkBuddy 战略级市场

政企客户不是 WorkBuddy 三大目标行业(咨询/教育/政企)里体量最大的,但是**单笔最重、周期最长、复购最高**的一类。本节从四个维度,说明为什么政企应当被列为战略级市场。

**第一,等保合规强需求,催生"本机部署 + 国产化"的硬约束。** 政企机构普遍处于国内主流信息安全合规框架 三级及以上的监管环境,关键信息基础设施单位还叠加《关键信息基础设施安全保护条例》与《数据安全法》《个人信息保护法》的多重义务。云端通用大模型在政企客户眼里"开箱即用"恰恰是最大风险:数据出境、训练样本回灌、第三方日志无法审计——每一项都可能触发等保测评中的"高风险"项。WorkBuddy 桌面端的"本地读取 + 系统工具 + 可审计"三特性(出自第一卷 ch01-模块卡 02 行)刚好对症,后续章节六的私有化部署清单(第三卷 ch07 模块卡)进一步给出技术评估表。

**第二,数字化转型是"一把手工程",但落地经常卡在最后一公里。** 过去十年,政企客户普遍完成了 OA、协同办公、政务专网、电子公文交换系统等基础设施的建设;真正没解决的是"机关干部日常用不上、不愿用"的最后一公里。WorkBuddy 三部曲把数字化转型拆成"个人会用 → 团队用得起来 → 组织用得对"三个台阶(分别对应第一卷、第二卷、第三卷),刚好对应"处长先飞、处室复用、机关嵌入"的三步推进路径。

**第三,公务员 AI 素养培训是组织部门、党校、机关工委的硬性议题。** 截至 2026 年 6 月,多地组织部门已将"人工智能应用能力"列入公务员年度培训学分体系,部分省份要求处级以上干部每年完成不少于 8 学时的 AI 专题培训。WorkBuddy 三部曲的 24 个模块恰好可以裁剪为"处长班 / 科员班 / 信息中心班"三套培训方案,模块化交付,直接对接党校与机关大讲堂。

**第四,跨部门协同是政企客户长期未解的痛点。** 政企机构普遍存在"委办局之间数据共享难、处室之间口径不一致、上下级之间报告口径反复改"的问题。WorkBuddy 的"团队工作目录 + 公共 / 个人 / 项目三层 + 权限矩阵"(出自第二卷 ch03-模块卡)与"企业微信 / 钉钉 / 政务微信集成"(出自第二卷 ch02-模块卡),提供了一套不依赖单一厂商、能在政务专网环境下运行的协同方案。

综合四点,政企市场的战略价值不在"卖多少账号",而在"沉淀多少可复用的政务 Skill 与合规模板"。一旦在某省厅、某市局做成样板,即可在同系统、同省份内做"母版复用",边际成本接近于零。这是把 WorkBuddy 从"工具"升级为"政务知识资产"的根本路径。

## 二、政企行业的 4 类典型场景

政企客户的高频文字工作高度集中在以下四类场景。每类场景,都给出"WorkBuddy 怎么用、用到什么程度、谁来用、产出是什么"四要素。案例均经过脱敏,具体数字与机构名称已做处理。

### 场景 1:公文与材料

公文写作是政企机构最典型的"高频 + 模板固定 + 审阅严"的工作。一份综合性报告、年度工作总结、领导讲话稿、调研报告,平均要经历"初稿 → 部门征求意见 → 办公室汇总 → 领导审改"四轮,周期 7-15 个工作日。WorkBuddy 在这个场景下的定位是"起草助手 + 校对助手",不替代任何人完成最终定稿。

具体用法:把已有素材(会议纪要、上级文件、本单位年度数据)放入工作目录,用第一卷 ch04 模块卡中"会议纪要模板"或"汇报材料模板"派活,生成带"[事实/推测]"标签的初稿,作者在 1-2 小时内完成"事实校验 + 语气调校 + 关键表述替换",把初稿到送审稿的周期从 5-7 天压缩到 2-3 天。配套的 6 段白名单话术(第三卷 ch07-模块卡)能直接套用,形成《AI 公文起草与审校规范》,供本单位办公室备案。

风险点:必须设"事实终审环节",不允许 WorkBuddy 直接出具"对外发布"的公文。所有 AI 生成内容必须明确标注"AI 起草 + 人审改",并保留操作日志,这是后续"5 节点决策树"(第三卷 ch01-模块卡)中"高风险任务"的标准动作。

### 场景 2:跨部门数据共享

跨部门数据共享是政企数字化转型的硬骨头。典型场景:应急部门需要从公安、卫健、交通、市场监管四个部门汇总当月数据,过去要发 4 份函、走 4 套签批、收 4 份 Excel、手工合并 2 天。WorkBuddy 的解法是"标准化目录 + 自动汇总 + 一键归档"(第二卷 ch06-模块卡的"四要素工作流"模板)。

具体用法:信息中心牵头建立 `D:\Gov_Shared\` 公共目录,下设 `应急 / 公安 / 卫健 / 交通 / 市场监管` 五个子目录,每个部门按"统一字段名 + 统一时间口径"每周五下班前更新 Excel,WorkBuddy 在每周六凌晨自动触发"汇总 + 异常值标记 + 一句话洞察"三件套,生成《跨部门周度数据简报》发到分管秘书长邮箱。审核流程:业务处室 30 分钟内校对 → 办公室排版 → 秘书长阅示。整体周期从过去的 5 天压到 1 天。

风险点:跨部门数据共享涉及"数据出境、敏感字段、个人信息"三大合规线,必须先用第三卷 ch07-模块卡的"数据安全与合规审计清单"做一次全面体检,再决定哪些字段可自动汇总、哪些字段必须脱敏、哪些字段根本不能进 AI 工作目录。

### 场景 3:政策研究

政策研究是政企机关"含金量最高、占用时间最长"的工作。一份专题调研报告,例如"本市数字经济产业发展现状与对策",通常要 1 位处长 + 2 位主任科员花 4-6 周完成,涉及上级文件解读、本地数据汇总、兄弟城市经验对比、专家访谈整理、最终报告写作五个环节。

WorkBuddy 的定位是"研究员助手",把"文件检索 + 数据汇总 + 访谈整理 + 参考文献格式化"四类体力活接走,让研究员专注"判断与建议"。具体操作:把上级文件、本地统计年鉴、4-6 份兄弟城市报告、10-15 份访谈记录放入 `D:\Research\2026Q3_数字经济\` 子目录,用第一卷 ch05-模块卡的"三件套提示词 + 7 项自检"派活,WorkBuddy 先出"文件脉络 + 数据对比 + 访谈主题"三段,再由研究员基于这三段写"对策建议"。整体周期从 4-6 周压到 2-3 周,研究员可把省下的时间用于实地调研与专家座谈。

风险点:政策研究的产出最终会以"单位名义"对外发布,所有事实性表述必须人工核实,所有数据必须回到统计部门原文校核。WorkBuddy 在此场景只能承担"草稿层",不允许直接出"对外发布稿"。同时,所有引用必须可追溯到原始素材(第一卷 ch03-模块卡中"可审计"三特性之一)。

### 场景 4:民生服务

民生服务(12345 热线回复、信访件办理、政策咨询答复)是政企机关面向群众的一线窗口,也是 AI 最早能"看见价值"的场景。一份标准的 12345 工单,办理周期 3-7 个工作日,涉及工单分类、相关政策检索、答复口径拟定、领导审批、群众回访五个环节。

WorkBuddy 在此场景的解法是"工单分类 + 答复草稿 + 政策匹配"三件套(对应第二卷 ch01-模块卡的"用户反馈分类"案例)。具体操作:把工单导出文本放入工作目录,WorkBuddy 自动分类(咨询/投诉/求助/建议),从本单位《常见政策问答库》匹配相关条款,生成 200-400 字答复草稿,办理人员 15-30 分钟内审改提交,极大压缩重复劳动。某 80 人客服团队案例(第三卷 ch05-模块卡行)显示,这一套做法把平均处理时间从 18 分钟压到 8 分钟,采纳率从 38% 提到 78%,前提是"AI 草稿必须配人工事实校验"。

风险点:民生服务直接面对群众,任何口径错误都可能引发二次投诉或行政复议。WorkBuddy 输出的所有答复必须由"业务骨干 + 政策法规处"双签,涉及裁量基准、补助金额、时限承诺的,不得使用 AI 草稿。配套制度(《AI 辅助工单办理管理办法》)应在本单位印发。

## 三、30 天路线图(政企行业定制版)

政企客户与一般企业最大的不同,是**决策链长、合规环节多、容错率低**。第二卷 ch07-模块卡的"30 天培训手册"给出了 L1(装得上)/ L2(写得动)/ L3(用得对)/ L4(用得久)四阶递进目标,本节按政企实际做"四步裁剪",每一步标出"决策点 + 产出物 + 验收标准"。

### 第 1 周:合规评估 + 高层访谈

**目标**:把"能不能用、用到什么程度"这两件事说清楚,作为后续推广的法理基础。

**动作清单**:
1. **合规初评**(Day 1-2):信息中心牵头,联合办公室(保密)、法规处(合规)、审计处(留痕),对照第三卷 ch07-模块卡的"数据安全与合规审计清单",完成首轮自查。识别 5-8 项不通过项,排出 30 天整改计划。
2. **高层访谈**(Day 3-4):分别访谈分管副职、办公室主任、3-5 位处长,核心三问——"你每周最想省下 1 小时的文字工作是哪一类""哪些事绝对不能交给 AI""试点你最担心什么"。访谈结果汇总成《需求清单 v1.0》。
3. **试点处室确定**(Day 5):根据"高频 + 合规可控 + 处室领导主动"三标准,选定 1 个试点处室(优先选办公室、政策法规处、信息中心),不选"硬骨头处室"。

**产出物**:《WorkBuddy 政企试点合规初评报告》《需求清单 v1.0》《试点处室选定说明》。
**验收标准**:分管副职签字 + 法规处无重大反对意见 + 试点处室领导书面同意。

### 第 2 周:1 个处室试点

**目标**:在 1 个处室跑通"装得上 + 写得动",产出 3-5 个真实场景的 AI 辅助成果。

**动作清单**:
1. **环境部署**(Day 6-7):统一部署 WorkBuddy 桌面端 v1.x,建立 `D:\GovAI_workspace\` 工作目录,按"最小授权原则"仅授权该子目录(第一卷 ch02-模块卡"工作目录 7 子目录结构"模板);不在云同步盘根目录建工作目录,避免跨设备漂移。
2. **种子用户训练**(Day 8-9):处长 + 2-3 位业务骨干参加"4 学时实操培训",内容覆盖"提示词三件套 + 三栏操作 + 5 个高频场景"第一卷 ch04 / ch05 模块内容。培训讲师最好由本机关已熟练的主任科员担任,而不是外部讲师。
3. **真实任务试跑**(Day 10-12):每个种子用户在 3 个真实任务上完成 1 次"AI 起草 + 人审改",任务从"周报 / 纪要 / 邮件回复 / 政策摘要"中选。
4. **周复盘**(Day 13-14):处长 + 信息中心 + 培训讲师共评"3 件事跑通 + 3 件事没跑通",确定下周是否继续在该处室深入,还是需要换人换场景。

**产出物**:《试点周报 1》《3 份 AI 辅助成果样本(含人审改记录)》《第二周复盘会议纪要》。
**验收标准**:L1(装得上)达成率 100%,L2(写得动)达成率 ≥ 60%。

### 第 3 周:跨处室复用

**目标**:把试点经验扩到 3-5 个处室,验证"组织一致性"。

**动作清单**:
1. **Skill 沉淀**(Day 15-16):把试点处室跑通的 3-5 个高频任务封装为可复用 Skill(第一卷 ch06-模块卡"5 步转化流程"),命名采用"机关统一前缀"(`gov-` 或 `机关代码-`),避免和外部 Skill 混淆。
2. **跨处室推广**(Day 17-19):按"业务相近 + 处室领导主动"原则,扩到 3-5 个处室。每处室派 1 位"标杆员工"(第一卷 ch08-模块卡 4 要素之首),先做 1 对 1 上手辅导,再做小范围演示,**不要直接开全处室启动会**。
3. **监督机制上线**(Day 20-21):信息中心统一接管 WorkBuddy 团队版的"消耗数据"看板(第二卷 ch08-模块卡),但**不看内容日志**——这是合规底线。每月形成《AI 使用月报》报分管领导。

**产出物**:《3-5 份可复用 Skill 清单》《跨处室推广周报 2》《AI 使用月报雏形》。
**验收标准**:L2(写得动)达成率 ≥ 70%,L3(用得对)达成率 ≥ 30%(初始正常水平)。

### 第 4 周:阶段性汇报 + 推广方案

**目标**:向分管副职汇报,形成下一阶段推广方案。

**动作清单**:
1. **数据汇总**(Day 22-24):信息中心汇总 4 周数据,包括"参与人数 / 日活率 / 任务类型分布 / 积分 消耗 / 节省工时估算",按第三卷 ch05-模块卡的"五维公式 + 四张表"组织材料。
2. **汇报准备**(Day 25-26):形成《30 天试点工作报告》(建议 15 页以内),关键页包括"试点结论、3 件事跑通、3 件事没跑通、下一阶段建议、预算申请"。汇报口径用"工时节省 × 0.3-0.5"实诚系数(第二卷 ch08-模块卡),不夸大。
3. **正式汇报**(Day 27-28):分管副职主持,办公室 / 法规处 / 审计处 / 信息中心参加,形成《会议纪要 + 下一阶段推广方案》。
4. **下一阶段动员**(Day 29-30):按会议决议印发《WorkBuddy 推广实施方案(第二阶段)》,明确 90 天目标(覆盖至 50% 处室、200+ 用户)与 180 天目标(覆盖至 90% 处室、500+ 用户)。

**产出物**:《30 天试点工作报告》《会议纪要》《WorkBuddy 推广实施方案(第二阶段)》。
**验收标准**:分管副职同意下一阶段推广;法规处 / 审计处 / 办公室三方会签。

**关键提示**:30 天路线**不是"启动 50 个账号"**,而是"30 天跑通 1 个闭环"。政企客户最大的失败模式,就是"采购 50 个账号 + 一次启动会"——三个月后日活 5%(第一卷 ch08-模块卡案例 1)。本路线图把"启动会"放在 Day 30,前 29 天只做"小范围试点 + 制度铺垫",恰恰是反"启动会文化"的设计。

## 四、关键 Skill 库(政企行业推荐)

WorkBuddy 的"Skill"(出自第一卷 ch06-模块卡)是"把派活沉淀为团队工具"的核心机制。本节按政企客户实际需求,推荐 6 类核心 Skill,每类说明适用场景、关键参数、典型产出。机构在落地时,可按本节清单建立"机关 Skill 库 v1.0",后续按月迭代。

### Skill 1:公文写作(`gov-official-doc`)

适用场景:综合性报告、年度工作总结、领导讲话稿、专题汇报、调研报告。关键参数:文件类型、字数、风格(庄重 / 简洁 / 口语化)、读者层级(机关内部 / 上级单位 / 公开对外)。典型产出:3000-8000 字带"[事实/推测]"标签的初稿 + 1 段摘要 + 1 份"事实校验清单"。配套必装:政策法规处口径库、年度统计基础数据、上级文件库(最近 2 年)。

### Skill 2:政策解读(`gov-policy-brief`)

适用场景:上级文件学习、专项政策传达、新出台法规解读。关键参数:文件原文、解读层级(全文 / 摘要 / 问答)、目标读者(处级 / 科级 / 一般干部)。典型产出:1 份 1500-3000 字解读稿 + 1 张"重点条款图解" + 1 份"本单位落实建议清单(6-10 项)"。配套必装:上级文件原文库、本单位职责清单、年度重点任务台账。

### Skill 3:数据汇总(`gov-data-summary`)

适用场景:周报 / 月报 / 季报 / 年报中的数据汇总、跨处室数据合并、专项数据统计。关键参数:数据来源(Excel / 数据库 / 系统导出)、汇总口径、对比基准。典型产出:1 张汇总表 + 1 段"关键变化说明" + 1 张"异常值标记图"。配套必装:统一字段名规范、时间口径规范、单位换算表(万元 / 亿元 / 万人次等)。

### Skill 4:民意分析(`gov-public-sentiment`)

适用场景:12345 热线工单分类、信访件主题提取、网络舆情摘要、群众留言分析。关键参数:文本来源、分类标签(咨询 / 投诉 / 求助 / 建议 / 举报)、时间窗口、敏感度阈值。典型产出:1 份分类清单 + 1 张"主题热度图" + 1 段"潜在风险预警"。**风险提示**:此 Skill 必须配置"敏感词白名单 + 个人信息脱敏",并经过法规处审核方可上线。

### Skill 5:调研报告(`gov-research-report`)

适用场景:专题调研、经验总结、典型案例编写。关键参数:调研主题、调研对象(企业 / 群众 / 基层)、数据来源、报告结构。典型产出:1 份 5000-10000 字报告 + 1 份"调研提纲与访谈记录模板" + 1 张"调研路线图"。配套必装:兄弟城市报告库、本地基础数据库、专家访谈录音转写流程。

### Skill 6:工作汇报(`gov-work-report`)

适用场景:年度工作汇报、季度工作汇报、专项工作汇报、述职报告。关键参数:汇报对象(上级 / 本级 / 下级)、汇报时长(15 分钟 / 30 分钟 / 1 小时)、汇报层级(全局 / 分管领域 / 单项工作)。典型产出:1 份主报告(3000-6000 字)+ 1 份 PPT 大纲(第一卷 ch04-模块卡"汇报材料模板")+ 1 份"问答准备清单(15-20 题)"。

**Skill 库建设三原则**:第一,**不贪多**——30 人以下处室建议先建 3-5 个,跑通再加码;100 人以上机关可分两批,先建 6 个核心,季度评估后再扩。第二,**必有维护人**——每个 Skill 指定 1 位"业务骨干 + 1 位 IT 支持",防止变成"知识坟场"(第二卷 ch05-模块卡"保鲜三件套")。第三,**版本号管理**——Skill 升级必须走"v1 → v1.1 → v2"显式版本号,所有调用日志可追溯(第三卷 ch02-模块卡)。

## 五、案例(脱敏)

为方便阅读,以下两个案例对客户名称、具体数字、内部组织架构做脱敏处理,保留实施逻辑与可复用经验。案例 A 为"500 人市级机关半年落地",案例 B 为"2000 人省厅年度落地"。

### 案例 1:某市直机关(500 人,落地 6 个月)

**客户背景**:某地级市直属机关,编制 500 人,内设 25 个处室,日常工作以公文、政策研究、跨处室协同为主。2025 年 12 月由分管副市长主持启动 WorkBuddy 试点,信息中心牵头,法规处、办公室、审计处配合。

**实施节奏**:
- **第 1-30 天(试点期)**:选择办公室、政策法规处、信息中心 3 个处室做试点,部署 12 个账号。法规处先行做合规初评,信息中心完成工作目录与权限矩阵配置。
- **第 31-90 天(扩展期)**:扩到 12 个处室、80 个账号。建立 6 个核心 Skill(`gov-official-doc` / `gov-policy-brief` / `gov-data-summary` / `gov-public-sentiment` / `gov-research-report` / `gov-work-report`),从 2 名培训讲师扩展到 5 名。
- **第 91-180 天(固化期)**:覆盖 22 个处室、380 个账号。设立"机关 AI 应用月度分享会"机制(每月最后一周五下午,机关大讲堂),信息中心每月出《AI 使用月报》报分管副市长。

**关键数据(6 个月累计)**:
- 参与处室:22 / 25(88%)
- 日活率(DAU/MAU):从 12% 提升到 71%
- 任务类型覆盖:从 3 类扩展到 11 类
- 平均节省工时:每位活跃用户 4.2 小时 / 周
- 关键节点节省:综合性报告周期 7-10 天 → 3-4 天;会议纪要 60 分钟会 → 15 分钟出稿

**经验教训**:
- 试点期选"愿意 + 能配合 + 文字密集"三特征处室,不要选"硬骨头"处室;
- 法规处早期介入,形成《AI 辅助公文起草与审校规范》作为后续推广的法理基础;
- 月度分享会比启动会更重要,前者形成"自下而上"的文化,后者容易引发抵触;
- 法规处、审计处的合规介入,反而让其他处室更放心,而不是更抗拒。

**风险点**:
- 第 60 天一度出现"工单内容被自动分享到企微群"事故,源于一个 Skill 配置错误,经 30 分钟响应小组处理后修复;
- 1 次"AI 起草 + 未人审改 + 直接对外"事件,事后追责到具体责任人,作为反面教材在月度分享会通报。

### 案例 2:某省厅(2000 人,落地 12 个月)

**客户背景**:某省直厅局,编制 2000 人,内设 32 个处室 + 8 个直属事业单位,日常以行业政策制定、跨地市指导、专项工作推进为主。2025 年 6 月由厅长主持启动,信息中心 + 办公室双牵头。

**实施节奏**(更细分):
- **第 1-30 天**:合规初评 + 选定办公室、政策法规处、规划处、信息中心 4 个处室为试点,部署 20 个账号,确定 8 个核心 Skill 雏形。
- **第 31-90 天**:扩到 10 个处室、120 个账号,启动"机关 AI 应用布道师"计划(第二卷 ch07-模块卡),选拔 8 位布道师,工作量减免 + 培训津贴 + 晋升背书。
- **第 91-180 天**:扩到 25 个处室、800 个账号,建立"行业政策研究中心"作为 Skill 沉淀主体,每月产出 1-2 个新 Skill,季度清理低频 Skill。
- **第 181-365 天**:覆盖全部 32 个处室 + 6 个直属事业单位、1850 个账号,完成"行业知识库"+"政策法规库"+"案例库"三库对接,形成 24 个标准 Skill 库。

**关键数据(12 个月累计)**:
- 覆盖:32 / 32 处室 + 6 / 8 直属单位(75% 直属单位,2 个为涉密单位暂不部署)
- 日活率:从 8% 提升到 78%
- 任务类型覆盖:从 4 类扩展到 18 类
- 节省工时:累计 32 万小时(经"工时 × 0.4"实诚系数折算)
- 政策研究周期:典型调研报告 4-6 周 → 2-3 周;政策解读文件下发后 24 小时内出"本单位落实清单"
- 跨地市指导文件:格式统一率从 60% 提升到 95%,地市反馈"格式反复改"投诉下降 80%

**经验教训**:
- 2000 人规模的机构必须设"布道师"机制,5-8 人专职或半专职,工作量减免 + 培训津贴 + 晋升背书三件套缺一不可;
- 涉密单位、保密等级高的处室不部署,避免"为效率牺牲合规";
- "行业知识库"由业务处室主导建设,信息中心提供技术支持,反之效果差;
- 直属事业单位落地难度高于机关处室,因人员编制多元、考核口径不同,需要单独设计"事业单位版"推广方案。

**风险点**:
- 第 120 天出现"某处长私用 WorkBuddy 起草涉密文件草稿"事件,经紧急排查未造成实际泄露,但促使全厅"涉密目录与工作目录物理隔离"强制要求落地;
- 第 240 天 API Key 误传内部群,经 10 分钟内回收并轮换,未造成经济损失;此后设"API Key 季度强制轮换 + Keychain 管理"硬要求。

**两个案例的共同启示**:第一,**法理基础先行**(合规初评 + 三方会签)远比"启动会"重要;第二,**小步快跑 + 月度分享**比"一次性大铺"有效;第三,**布道师机制是 200 人以上机构的必选项**,不是加分项;第四,**涉密、敏感岗位物理隔离**是硬底线,任何"为效率"开的后门都会成为泄露入口(第三卷 ch04-模块卡案例 3)。

### 6.4 培训交付常见问题

**Q1:培训是集中脱产,还是分散在职?**
政企客户普遍接受"集中脱产(2-3 天)+ 分散在职(30 天内配套 3 次答疑会)"模式。完全分散在职效果差(第二卷 ch07-模块卡案例 2 经验:负责人前 30 天每周 8-10 小时投入是底线)。

**Q2:培训讲师是外聘,还是本机关?**
推荐"本机关主任科员任讲师 + 外聘专家做顾问"组合。本机关讲师懂本机关口径,外聘专家懂行业方法论,两者缺一不可。

**Q3:培训要不要考核?**
要考核,且考核结果与"AI 应用月度分享会"准入挂钩。考核不通过者,30 天后补考。

**Q4:涉密人员能不能参加?**
涉密人员**不参加** AI 工具培训,涉密岗位**不部署** WorkBuddy 桌面端。这是硬底线。

## 七、ROI 估算模板

政企客户算 ROI 与一般企业有三个不同:**第一,不只看钱,还要看"行政效率 + 公共服务水平"**;**第二,接受"工时节省 × 0.3-0.5"实诚系数**(第二卷 ch08-模块卡);**第三,要给"非经济收益"(干部能力提升、知识沉淀、协同改善)留位置**。本节给出一份政企版 ROI 估算模板,供信息中中心与财务处共同测算。

### 7.1 五维公式(政企版)

政企版 ROI 建议用"五维公式",而非"工时节省 × 时薪 ÷ 成本"单一维度:

| 维度 | 权重建议 | 量化方法 |
|---|---|---|
| 工时节省 | 40% | 月节省工时 × 单位工时成本(以本单位人均年支出 ÷ 12 ÷ 174 小时测算) |
| 质量改善 | 20% | 错字率、事实错误率、格式统一率的前后对比 |
| 合规改善 | 15% | 等保测评问题项数量、信访件处理时效、群众满意度 |
| 干部能力 | 15% | 培训完成率、AI 应用能力考核通过率、年轻干部成长速度 |
| 创新储备 | 10% | 新 Skill 数量、行业知识库规模、跨部门协同案例 |

**示例**:某 500 人机关半年 ROI 计算——
- 工时节省:每位活跃用户 4.2 小时/周 × 380 人 × 26 周 × 0.4 实诚系数 = 16,601 小时,折合约 95 万元(以 60 元/小时单位工时成本)
- 质量改善:综合性报告平均返工次数从 2.3 次压到 1.1 次,折合约 18 万元
- 合规改善:等保测评问题项 8 项 → 4 项,折合约 8 万元
- 干部能力:60 位年轻干部完成 AI 应用能力认证,折合非货币收益
- 创新储备:6 个核心 Skill、1 套机关知识库,折合非货币收益
- **总收益约 121 万元(货币化部分)**,对比 WorkBuddy 投入(账号 + 培训 + 陪跑)约 65 万元,**净收益 56 万元,回收期 5.5 个月**。

### 7.2 四张表对齐

为保证 ROI 可审计,本节建议每月做"四张表"对齐(第三卷 ch05-模块卡):

1. **使用日志表**:WorkBuddy 团队版自动导出,字段包括"用户、处室、任务类型、消耗 积分、节省工时估算"。
2. **业务工单表**:从 OA / 协同办公系统导出,字段包括"工单类型、办理时长、办理人、满意度"。
3. **财务支出表**:WorkBuddy 账号费、培训费、陪跑费、硬件费。
4. **问卷调查表**:每季度 1 次,5 题核心问卷(满意度、问题、建议、推荐意愿、最有用 Skill)。

四张表每月对齐,形成《月度 ROI 跟踪表》,季度向分管副职汇报。

### 7.3 给 CFO / 分管领导的 3 句话

向分管副职或上级财务部门汇报,建议用 3 句话模板(第三卷 ch05-模块卡):
- **第 1 句话:规模**——"本机关覆盖 X 个处室 / Y 个账号,日活率 Z%,覆盖 W 类任务。"
- **第 2 句话:净收益**——"半年累计节省工时 N 小时,折合 M 万元;对比投入 P 万元,净收益 Q 万元,回收期 R 个月。"
- **第 3 句话:风险**——"已识别 3 类风险(X、Y、Z),目前均已设防,未发生实际损失。"

不报"理论最大值",只报"实诚折算值";不报"AI 能做什么",只报"AI 已经在做什么 + 已经省了什么"。

### 7.4 政企客户常见追问与应答

| 追问 | 应答要点 |
|---|---|
| "为什么不是用免费的 云端 AI?" | 三特性:本地读取 / 系统工具 / 可审计(第一卷 ch01),数据不出本机,日志可向纪检出示。 |
| "投入 65 万值不值?" | 看净收益 56 万 + 非货币收益,且 2000 人机构可摊薄到 30 元/人/年,极低。 |
| "会不会有下岗风险?" | AI 替代"信息搬运",人做"判断决策"(第三卷 ch08-模块卡),不替代岗位,提升能力。 |
| "如果出现涉密泄露怎么办?" | 已设三道防线:合规初评、Skill 白名单、5 节点决策树 + 应急响应小组。 |
| "为什么不用国产化大模型?" | 私有化部署支持对接国产化大模型(如 DeepSeek、Qwen、GLM),客户可按名单自选。 |

## 八、风险与对策

政企客户的风险结构与一般企业不同,本节按"国内主流信息安全合规框架、国产化要求、招投标流程、公务员培训纪律"四类,给出风险清单与对策。

### 8.1 风险 1:国内主流信息安全合规框架

**风险描述**:国内主流信息安全合规框架 三级要求"重要数据不出域、操作可审计、人员权限可控"。WorkBuddy 默认部署若未做合规改造,可能在测评中被判"高风险项"。

**对策清单**:
- 工作目录仅授权本机指定子目录,严禁"桌面 / 文档 / 下载"全盘授权(第一卷 ch02-模块卡"最小授权原则");
- API Key 走系统 Keychain,严禁明文存储(第三卷 ch03-模块卡);
- 审计日志包含"人 / 时 / 处 / 动 / 数据指纹"五要素(第三卷 ch07-模块卡);
- 制定《WorkBuddy 合规使用规范》,经法规处 + 保密办 + 审计处三方会签;
- 重要操作(对外发布、写入业务系统、跨境数据)设"专家终审环节",AI 草稿不得直接出"对外发布稿";
- 每季度做一次合规自查,形成《合规自查报告》报分管副职。

### 8.2 风险 2:国产化要求

**风险描述**:部分央国企客户处于"国产化替代"监管范围,要求"芯片 + 操作系统 + 数据库 + 中间件 + 应用"全栈国产化。WorkBuddy 默认对接海外大模型 API,需做"国产化模型对接 + 私有化部署"改造。

**对策清单**:
- 国产化模型对接:支持 DeepSeek、Qwen、GLM、Kimi 等国产大模型,客户可按名单自选主力 + 兜底双模型;
- 私有化部署:支持"本地模型 + 本地存储 + 离线更新"形态(第三卷 ch07-模块卡),牺牲部分云端能力换合规;
- 部署形态三选一:本地优先 / 云端辅助 / 混合托管,按本机关合规要求确定;
- 国产化硬件清单(参考):鲲鹏 + 麒麟 / 海光 + UOS / 龙芯 + 统信,均提供适配方案;
- 与"信创目录"对标,所有产品组件具备相应的信创认证证书。

### 8.3 风险 3:招投标流程

**风险描述**:政企客户采购普遍走"政府采购 + 招投标"流程,周期长(60-180 天)、合规要求高、评标委员会对"非主流产品"天然谨慎。

**对策清单**:
- **预先入围**:与本地代理 / 集成商合作,提前进入"政府采购目录 / 信息化项目协议供货名单";
- **典型案例包装**:在投标文件中提供 2-3 个同系统 / 同省份的"脱敏案例 + 实施报告 + 验收文件",证明可交付;
- **评分项对标**:针对评标标准中的"产品功能、案例、安全资质、服务能力、价格"五维,逐一提供证明材料;
- **小步快跑**:对暂时无法直接中标的大型项目,可先以"小金额培训服务 + 1 个处室试点"切入,跑出案例再扩展;
- **陪跑报价透明**:账号费、培训费、陪跑费分项报价,便于甲方在多个供应商间对比。

### 8.4 风险 4:公务员培训纪律

**风险描述**:公务员培训受《干部教育培训工作条例》《公务员培训规定》等规范约束,部分敏感议题(政治表述、口径、保密)不能交给 AI 处理。

**对策清单**:
- 制定《AI 辅助培训纪律十条》,内容覆盖"涉密内容不上 AI、领导讲话稿必须人审改、政策口径以法规处为准、不允许用 AI 替代组织生活、不允许用 AI 起草处分决定";
- 涉密人员 / 涉密岗位**不部署** WorkBuddy 桌面端,作为硬纪律;
- 培训讲师定期(每季度)接受"政治表述 + 政策口径"专项培训,确保不被 AI 输出误导;
- AI 输出在对外发布前必须经过"业务骨干 + 法规处 + 办公室"三审,审改记录归档;
- 一旦发现"AI 起草未经人审改直接对外"事件,按"公文办理责任追究"机制处理,绝不姑息。

### 8.5 其他常见风险(简要)

- **数据出境风险**:禁止用境外大模型处理敏感数据,跨境业务走"本地化 + 数据脱敏"流程;
- **账号滥用风险**:信息中心统一接管消耗数据看板,但**不看内容日志**——这是合规底线;
- **依赖性风险**:逐步建立"人 + AI"双轨制,关键岗位保留"人"路径,防止"AI 故障 = 业务停摆";
- **舆情风险**:民生服务类 AI 输出必须经政策法规处审核,严防口径错误引发二次投诉。

## 九、报价
