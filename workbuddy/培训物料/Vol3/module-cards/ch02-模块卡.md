# 模块卡 02 — 自定义 Skill:把隐性知识变成可复用资产

> 卷:第三卷 | 适用对象:技术骨干/部门专家 | 时长:60-90 min | 难度:进阶
> 配套 PPT:ch02-PPT.md | 配套附录:附录 C 模板 1、2

## 一、本模块回答的核心问题(1 句)
资深员工的"凭感觉"如何被编码成一段任何人都能调用的指令,让团队少一个能干的人也不掉链子。

## 二、学习目标(完成后能...)
1. 按"指令 + 参数 + 模板"三件套结构,搭出一个能稳定复用的 Skill。
2. 走通需求→原型→测试→文档→发布 5 步流程,每步都拿出可验证的产物。
3. 用调用日志、A/B 评估、版本号,让上线后的 Skill 持续迭代不退化。

## 三、关键案例(3 个)

### 案例 1:合同审阅 Skill
- 场景:法务团队每日审 20-50 份合同,资深同事的"高风险条款"检查清单散落在脑子里(章节行 129-148)。
- 冲突/问题:通用对话只能给"看上去合理"的建议,缺少 50 万元损失阈值、四列结构化输出这类硬约束,新员工审一份要 40 分钟。
- 启示:把"角色+流程+判定标准+输出格式"四段式写进指令,比加更多形容词更管用。

### 案例 2:客户画像 Skill
- 场景:销售见客户前要拼齐工商、舆情、沟通记录三类信息(章节行 188-216)。
- 冲突/问题:事实与推测混在一起,新人照着画像去谈,常把猜测当承诺讲,丢单后才发现。
- 启示:用"[推测]"标签硬性区分客观与推断,模板钉死边界,比反复培训"说话严谨"更稳。

### 案例 3:周报生成 Skill 升级到 L3
- 场景:某运营总监的"周报生成 Skill"用 4 个月从私有走到公司市场(章节行 462-464)。
- 冲突/问题:第一版指令 800 字,差评率 12%;没人愿意重读、没人愿意填,迭代卡在"个人工具"阶段。
- 启示:从 800 字精简到 400 字、加入"周报风格"枚举参数、跑通 200+ 次调用后再申请发布——发布是验证的结果,不是终点。

## 四、互动题(讲师在课堂上抛出的问题)
1. 你团队里谁的"经验"如果被抽走,会让业绩立刻下滑?那个经验能不能用今天的三件套结构写出来?(开放,无标准答案)
2. 举手投票:在座谁过去 3 个月写过至少 1 个 Skill?谁上线后坚持做了版本号管理?(快速收集现状)

## 五、可直接用的工具/模板
- 附录 C 模板 1:客服对话质检 Skill(章节行 9-30),可作为"指令写四段式"的最小完整范例。
- 附录 C 模板 2:周报自动汇总 Skill(章节行 32-54),演示"参数+模板"如何把重复输入固化下来。
- 章节案例 1-4 的指令全文,可直接复制到 WorkBuddy 5.3.12 的「Skill 市场 → 我的 Skill → 新建」编辑器跑通。

## 六、本周可做的 1 件事
挑一个你这周已经做过 3 次以上的判断(审合同、写周报、复盘数据),用指令四段式(角色→输入→流程→输出)写出第一版,跑 5 个真实样本,看命中率。
