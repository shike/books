# 模块卡 03 — APIKey 与多模型策略(本模块回答的核心问题)

> 卷:第三卷 | 适用对象:技术骨干/IT/采购负责人 | 时长:60-90 min | 难度:进阶
> 配套 PPT:ch03-PPT.md | 配套附录:附录B(B.3 模型路由与多模型策略、B.5 ROI 与成本度量)

## 一、本模块回答的核心问题(1 句)
什么时候自购 API 比订阅更划算,如何用"任务分级 + 多模型路由"把月度账单压下来,又不被任何一家厂商绑死。

## 二、学习目标(完成后能...)
1. 用三句话讲清 API Key 的本质:不是省钱钥匙,而是模型选择权、成本可观测、数据流向控制权。
2. 套用"轻/中/重"任务分级表,为本周高频任务匹配对应模型档位,识别"其他主流闭源模型 做翻译"这类浪费。
3. 走通四步配置流程(设置→加 Key→设主备→对话级切换),完成至少两家供应商的接入与切换演练。

## 三、关键案例(2-3 个)
### 案例 1:GitHub 公开仓库泄露 Key,几小时被刷数千美元
- 场景:开发者把含 API Key 的代码推上公共仓库,未启用 Keychain。
- 冲突/问题:扫描机器人秒级捕获,几小时内把账户余额打空。
- 启示:API Key 是"钱"的等价物——必须走系统 Keychain,明文存配置=裸奔。来源:第三卷 §3.1,L42-44。

### 案例 2:用 其他主流闭源模型 写会议邀请邮件,月浪费 3000 元
- 场景:某团队"质量优先",所有对话默认走 其他主流闭源模型。
- 冲突/问题:轻量任务用重量模型,单次成本差 100-1000 倍,月底账单翻 3 倍。
- 启示:**轻量优先、重型慎用、长期看账单**——多数场景 其他主流闭源模型-mini 已够。来源:第三卷 §3.3,L92-94。

### 案例 3:零售企业单供应商 API 故障 2 小时,损失百万元
- 场景:某零售公司电商客服 100% 依赖单一国产模型。
- 冲突/问题:厂商 API 中断 2 小时,客服瘫痪,客诉与订单流失超百万。
- 启示:至少两家供应商,主备自动切换——切换是"消防演习"。来源:第三卷 §3.5,L170-174。

## 四、互动题(讲师在课堂上抛出的问题)
1. 开放题:你团队过去一个月在 WorkBuddy 上的实际花费是多少?如果全部走自购 API,同样的用量该花多少?(现场用用量面板+自购成本公式估算)
2. 投票题:以下 5 类任务,你目前默认走哪个模型?举手统计——翻译/摘要/代码/数学/创意,看有多少人"重型模型做轻量活"。
3. 分组题:给定一个真实业务场景(讲师准备),用"轻/中/重"三档分级,设计主备模型路由方案。
