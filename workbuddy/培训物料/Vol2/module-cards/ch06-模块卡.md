# 模块卡 06 — 自动化让 WorkBuddy 自己跑流程

> 卷:第二卷 | 适用对象:技术骨干 / 团队 leader | 时长:60-90 min | 难度:进阶
> 配套 PPT:ch06-PPT.md | 配套附录:附录 C

## 一、本模块回答的核心问题(1 句)

专家中心里已经沉淀的 Skill,怎么从"等人来调"变成"自己会跑"?

## 二、学习目标(完成后能...)

1. 在白板画出"四要素工作流"(触发器 / 执行动作 / 输出位置 / 失败处理),并对 4 类触发器按场景选型
2. 用五位 cron 表达式声明一个定时任务,5 种写法覆盖 90% 管理场景
3. 套用"三档失败处理"为已有自动化补齐安全带,并做一次"故意失败"自测

## 三、关键案例(3 个,均来自章节)

### 案例 1:8 人产品团队 — 周报自动生成

- 场景:每周五 4-6 小时收周报、汇总、催交(§3.1,第 310 行)
- 冲突:用 Skill 还要人启动,日活调用量 6 月比上线首周下降 40%
- 启示:定时 + 文件双触发,提交及时率 75%→95%,主管汇总时间 90min→35min

### 案例 2:15 人运营团队 — 月度数据汇总

- 场景:每月 2-3 天手算用户增长 / 收入 / 漏斗(§3.2,第 343 行)
- 冲突:纯人工汇总无洞见,异常波动要等汇报才被发现
- 启示:定时 + 预检查(数据库连通才跑),机械汇总 60-80h/月 → 8-10h/月

### 案例 3:12 人 ToB 销售 — 客户回访提醒

- 场景:签约后 30/90/180 天回访,2026 Q2 续约率仅 58%(§3.3,第 377 行)
- 冲突:销售凭记忆回访,签了就忘,流失才发现
- 启示:CRM 触发 + 自动生成"回访准备包",30 天回访完成率 35%→82%

## 四、互动题(讲师在课堂抛出)

1. 你团队目前"等人来调"的 Skill 有几个?挑 1 个最痛的设计自动化(开放题,白板画四要素)
2. 这条自动化该走文件 / 邮件 / 日历 / 定时哪一类触发?为什么?(举手投票)
3. 给 1 个"全自动发送客户邮件"的冲动,小组共评 2 个边界(出错代价 / 合规风险)
4. 已有自动化"失败处理"是否显式配置?3 道自检题逐条对照(举手统计未配齐项)
