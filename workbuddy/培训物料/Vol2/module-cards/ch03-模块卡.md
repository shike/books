# 模块卡 03 — 团队工作目录与文件规范(让团队文件夹"自己会说话")

> 卷:第二卷 | 适用对象:全员(尤其团队负责人 / IT) | 时长:45-60 min | 难度:入门
> 配套 PPT:ch03-PPT.md | 配套附录:附录D 清单 3(团队工作目录建立检查表)

## 一、本模块回答的核心问题(1 句)

团队从 1 人扩到 10 人,如何用"公共 / 个人 / 项目"三层 + 四段式命名 + 最小可见权限,把"找文件"从每天 30 分钟压到几乎为零?

## 二、学习目标(完成后能...)

1. 画出"公共 / 个人 / 项目"三层目录结构,并为现有团队文件夹做一次 30 分钟整改
2. 套用四段式命名(`<项目编号>_<类型>_<日期>_<负责人>_<状态>`),杜绝"最终版.docx"这一类失败命名
3. 区分 R/W/S 三种权限粒度,给 WorkBuddy 配一个不挂载 `_private` 的最小工作目录
4. 说出版本控制的 3-2-1 备份原则,并能给一个项目区配出 Git + 网盘历史版本 + 异地备份三件套

## 三、关键案例

### 案例 1:实习生的"无意识越权"事故
- 场景:20 人团队,新来的实习生用全员可写的共享盘,误删了财务的预算表
- 冲突:公共区被当"便签墙",权限没按 R/W/S 分开(章节第 36-43 行)
- 启示:"一个人能看到的,不应多于他完成工作所需要的"(章节第 300 行)

### 案例 2:`~/Downloads/` 被设为工作目录
- 场景:产品经理图省事,把 Downloads 直接挂载成 WorkBuddy 工作目录
- 冲突:WorkBuddy 索引到了工资单、合同、微信截图——不是 AI 偷看,是用户亲手"把门打开"(章节第 329-346 行)
- 启示:工作目录 = WorkBuddy 能看到的整个世界;`_private` 下划线前缀 = 团队命名级的"默认不可见"

### 案例 3:"最终版(真的).docx"
- 场景:市场部一份对外方案,文件名依次是 `最终版.docx`、`最终版(2).docx`、`最终版(真的).docx`
- 冲突:6 个月后没人知道哪个是定稿,新员工照错版给客户报价(章节第 200-204 行)
- 启示:四段式命名让名字自己说话;规则要一页纸讲完,执行成本才压得下来

## 四、互动题(讲师在课堂上抛出的问题)

1. **开放题**:打开你当前团队的共享盘,数一数"最终版 / 副本 / 新建文件夹"这一类文件占了多少?如果把它们全删了,会误删定稿吗?
2. **举手投票**:你认为团队文件夹最常见的崩溃模式是?选项:A 散落(每人桌面 / Downloads) / B 单一超大共享盘 / C 过度细分到 7-8 层目录
