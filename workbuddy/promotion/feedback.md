# 反馈入口 / Feedback(三卷共享)

> 电子书与印刷书最大的不同:**作者能在几天内收到反馈并修正**。
> 本文档是 WorkBuddy 三部曲**唯一权威反馈入口说明**,所有渠道在此集中登记,避免读者到处找。

---

## 首选:GitHub Issues(最推荐)

**仓库**:`https://github.com/shike/books`(顶层仓库,`workbuddy/` 子目录)

**适合**:
- 🐛 错字、引用失效、场景描述不准等具体问题
- 💡 章节补充建议、新增场景、新增工作模板
- 🤔 对方法论结论的质疑或反对(欢迎,我可能在错)
- 📦 配套培训物料(`培训物料/`)中的资源缺失 / 失效
- 🎓 培训认证体系的问题

**为什么首选**:
- 公开透明,所有读者都能看到问题与修复
- 自动追踪进度(Open / Closed),不会丢
- 修复后会自动出现在 PR 中,易于追溯
- GitHub Issues 关闭时会触发邮件通知

**Issue 模板**(5 种,提交时会自动选择):
1. **🐛 Bug Report** — 错字 / 引用失效 / 事实错误
2. **💡 Feature Request** — 章节补充 / 新场景 / 新工作模板
3. **🤔 Question / Discussion** — 方法论讨论 / 不同意结论 / 企业落地经验分享
4. **📖 Doc Improvement** — 文档 / 注释 / 配套资源
5. **🎓 Training Material** — 培训物料改进 / 讲师手册反馈 / 学员手册反馈

**Issue 标签约定**(提交后可补充):
- `vol1` / `vol2` / `vol3`:对应卷
- `training`:培训物料相关
- `cert`:认证体系相关

## 反馈处理流程

```
读者提交反馈
  ↓
作者分类(PATCH / MINOR / MAJOR / 卷号)
  ↓
记录到 promotion/corrections.md(可公开的错误与未决项)
  ↓
PATCH:72 小时内修复 → 立即推 GitHub + 24 小时内推 KDP / 微信 / 豆瓣
MINOR:本月内修复 → 进入下个 MINOR 版本(按卷更新)
MAJOR:进入 backlog → 在下个 MAJOR 版本讨论
  ↓
CHANGELOG.md 记录本次更新(含卷号)
  ↓
通知订阅者(Watch 仓库 / 公众号"电子书架"栏目)
```

## 培训物料共建(特别征集)

WorkBuddy 三部曲的培训物料(`培训物料/`)是面向**企业内训**的标准化交付件,目前 11 子目录。

如果你在内训中实际使用过本书,欢迎提 Issue 标注 `training-contribution`,分享你的:

**可以贡献的内容**:
- 📝 **讲师手册补充**:你讲某个模块时的实战经验、补充讲解点
- 📝 **学员手册改进**:学员常卡住的环节、需要的额外练习
- 📝 **工作坊迭代**:你跑工作坊时的反馈、新玩法
- 📝 **题库更新**:实际考试中遇到的学员问题(脱敏)
- 📝 **行业方案扩展**:SaaS / 制造 / 金融 / 医疗 / 教育 / 政务 等行业的特定场景(脱敏)

**回报**:
- 在对应物料中署你笔名(或匿名)
- 获赠 WorkBuddy 培训认证 1 次
- 受邀加入 WorkBuddy 培训讲师闭门群

## WorkBuddy 产品问题 vs 本书内容问题

请区分两类问题:

| 类型 | 渠道 | 说明 |
|---|---|---|
| **WorkBuddy 产品问题**(客户端 Bug / 功能建议) | WorkBuddy 官方支持 | 本书不处理产品问题 |
| **本书内容问题**(错字 / 案例 / 方法论) | 本文档列出的反馈入口 | 作者处理 |

如果你反馈的"问题"其实是 WorkBuddy 产品本身的,请先到 WorkBuddy 官方支持,我不会处理这类反馈(避免误判)。

## 不要做这些事

❌ **不要在豆瓣 / 微信读书评论区反馈技术问题** — 平台侧通知链路太慢
❌ **不要在 Twitter / X 私信反馈** — 我不一定看得到,且容易丢
❌ **不要在豆瓣短评写勘误** — 短评不是反馈渠道
❌ **不要在公众号文章留言** — 留言 48 小时后无法回复
❌ **不要把 WorkBuddy 产品问题反馈到本书** — 我处理不了,会误导你
