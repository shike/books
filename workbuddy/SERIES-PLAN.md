# WorkBuddy 三部曲 · 方案文档

> 本文档是三卷书的**全局蓝图**。三卷呈"个人 → 团队 → 组织"三级递进,管理者视角贯穿始终。

---

## 0. 系列元信息

| 项 | 值 |
|---|---|
| 系列名 | WorkBuddy 三部曲 |
| 主副标题候选 | "从个人到组织——管理者用好 WorkBuddy 的三步进阶" / "把 AI 助理装进团队——管理者视角的 WorkBuddy 实战" |
| 总字数 | 28-34 万字 |
| 总章数 | 24 章(每卷 8 章) |
| 目标读者 | 资深职场人 / 团队管理者(要带团队用) |
| 写作目的 | 出版/正式发行,对标市面 AI 教程书 |
| 目标交付 | 与出版社签约或自出版,提供 Markdown/PDF/ePub |

## 1. 三卷递进逻辑

```
        ┌─────────────────────────────┐
        │   第一卷 · 上手(个人)        │
        │   "我先自己用明白"            │
        └──────────────┬──────────────┘
                       ▼
        ┌─────────────────────────────┐
        │   第二卷 · 协作(团队)        │
        │   "从一个人到一个团队"        │
        └──────────────┬──────────────┘
                       ▼
        ┌─────────────────────────────┐
        │   第三卷 · 重塑(组织)        │
        │   "从团队到重塑工作方式"      │
        └─────────────────────────────┘
```

**核心叙事**:不是"AI 从入门到精通",而是"我→我们→组织"三级跃迁,管理者视角贯穿始终。

---

## 2. 第一卷 ·《上手:管理者自己的第一把刀》

> **命题**:"先成为使用者,才有资格引入团队"。
> **读者状态**:装上 WorkBuddy,准备开干。
> **关键能力**:主操作 + 高频 5 场景 + 积分。
> **预估字数**:8-10 万。

| 章 | 标题 | 核心内容 |
|---|---|---|
| 1 | 管理者为什么需要桌面 AI | 决策密度 × 信息过载 × 可审计,讲清与 ChatGPT 的差异 |
| 2 | 装上 WorkBuddy | 安装、登录、文件夹授权、安全边界 |
| 3 | 主界面与三栏结构 | 导航、对话区、工具面板、积分 余额查看 |
| 4 | 5 个管理者高频场景 | 改造自已有素材:周报/汇报材料/邮件/纪要/PPT |
| 5 | 提示词:从"问问题"到"派活" | 管理者视角的提示词工程(目标-约束-输出三件套) |
| 6 | Skill 是什么 | 概念铺垫,详细开发留给第三卷 |
| 7 | 积分 与成本 | 积分机制、Pro/Ultra 对比、自购 API Key 的成本边界 |
| 8 | 从个人到团队:你要做的准备 | 引出第二卷,提供自检清单 |

**核心交付**:读者装好软件,自己用熟 5 个高频场景,会写"派活型"提示词,清楚自己的使用成本。

## 3. 第二卷 ·《协作:让团队用起来》

> **命题**:"我用 ≠ 我们用",跨越从个人到团队的关键一步。
> **读者状态**:团队 3-10 人开始用。
> **关键能力**:企业微信/远程协作 + 自动化 + 培训。
> **预估字数**:10-12 万。

| 章 | 标题 | 核心内容 |
|---|---|---|
| 1 | 团队落地的三阶段:试点 / 推广 / 沉淀 | 方法论框架 + 时间表 |
| 2 | 企业微信集成与远程协作 | 团队授权、出差/移动端派任务、企业微信/飞书/钉钉集成;**不提 Claw,改中性"远程协作"** |
| 3 | 团队工作目录与文件规范 | 公共/个人素材区、命名规范、权限分级 |
| 4 | 技能市场:选现成的 Skill | 评估标准、Top 10 推荐场景;**不提 SkillHub/OpenClaw,改"WorkBuddy 技能市场 + 国产 Skill 社区"** |
| 5 | 专家中心:沉淀团队最佳实践 | 把"老师傅经验"结构化为可复用 Skill 模板;持续运营 |
| 6 | 自动化:让 WorkBuddy 自己跑流程 | 触发器、定时任务、与日程集成;不提 Claw/MCP 专有协议 |
| 7 | 30 天培训手册:从 0 到全员 | 教程模板、内部布道、答疑机制、考核题库 |
| 8 | 成本与权限:团队 积分 怎么分 | 预算模型、积分 池设计、按角色/部门/项目分配、审计 |

**核心交付**:管理者具备把 WorkBuddy 推给 5-30 人团队的全套方法。

## 4. 第三卷 ·《重塑:WorkBuddy 与组织融合》

> **命题**:"工具 → 流程 → 文化",WorkBuddy 价值的真正高地。
> **读者状态**:团队 50+,要谈 ROI/合规。
> **关键能力**:自定义 Skill + 多模型 + 战略。
> **预估字数**:10-12 万。

| 章 | 标题 | 核心内容 |
|---|---|---|
| 1 | 从工具到生产力:WorkBuddy 的能力边界 | 客观评估能做什么、不能做什么;不提 codebuddy 专有功能对比 |
| 2 | 自定义 Skill:把隐性知识变成可复用资产 | 完整开发教程;**不提 codebuddy/SkillHub/OpenClaw,改"WorkBuddy 技能市场 + 内部 Skill 库"** |
| 3 | API Key 与多模型策略 | 不被单一厂商绑定的架构选择;**不提"v3.4 / v5.x"具体版本号** |
| 4 | 与企业系统对接 | OA/CRM/知识库的常见集成模式;用 Webhook/REST/GraphSQL/SQL/IM 通用协议 |
| 5 | 组织级 ROI:怎么算、怎么讲 | 工时统计、决策质量、案例举证;**所有数字中性化** |
| 6 | 变革管理:会用 ≠ 愿用 | 抵触、隐私焦虑、岗位焦虑的应对 |
| 7 | 数据安全与合规 | 本地部署的边界、审计日志、敏感场景;**不提"等保 2.0"等具体认证编号,改"国内主流合规框架"** |
| 8 | 未来 12-24 个月 | 桌面 AI 趋势预判 + 管理者该提前布局什么;**不假设 WorkBuddy 具体路线图** |

**核心交付**:读者能从战略层面对 WorkBuddy 落地做长期规划。

## 5. 跨卷一致性

### 5.1 重复度控制

- **第 1 卷第 2 章"装上 WorkBuddy"** 与 **第 2 卷第 3 章"团队工作目录"**:前者讲个人安装,后者讲团队规范,不重复
- **第 1 卷第 6 章"Skill 是什么"** 与 **第 3 卷第 2 章"自定义 Skill 开发"**:前者概念铺垫(3000 字),后者实战(12000 字),后者可引用前者
- **积分 内容**:第 1 卷讲个人计费,第 2 卷讲团队分摊,第 3 卷讲 API Key 成本优化

### 5.2 章节衔接钩子

每卷最后一章末尾的"下一卷预告"必须明确指向下一卷的开篇:

- 第 1 卷第 8 章 → 引出第 2 卷第 1 章"团队落地的三阶段"
- 第 2 卷第 8 章 → 引出第 3 卷第 1 章"WorkBuddy 的能力边界"
- 第 3 卷第 8 章 → 给出全书总结与读者后续行动建议

### 5.3 命名与编号统一

- 章号:每卷从 01 重新计数
- 图号:每卷从 1.1 重新计数
- 引用:跨卷引用用"第 N 卷第 M 章第 K 节"

## 6. 配套体系

### 6.1 系列级配套

- **总序**(放在第一卷卷首):为什么要写这套书、目标读者、三本怎么选
- **读者指南**(放在第一卷附录):不同角色怎么跳读
- **术语表**:三卷共用,放在第一卷附录
- **配套网站**(在 shike.github.io):提示词模板下载、案例补充、版本勘误

### 6.2 每卷附录

- 提示词模板集(本卷 10-20 个常用提示词)
- 检查清单(checklist)(本卷核心动作)
- 案例库(2-3 个真实团队案例)
- 进一步阅读(本卷涉及的工具、论文、社区)

## 8. 风险与备选

### 8.1 内容风险

| 风险 | 应对 |
|---|---|
| WorkBuddy 产品快速迭代,功能描述过期 | 每章末附"截至日期"+ 季度勘误表 |
| 提到具体价格/版本可能不准 | 用"截至 2026 年 6 月"统一标注 |
| 部分功能存在区域差异 | 注明"以国内版/国际版区分" |
| 隐私/合规敏感话题 | 保持中立,给双方观点,不出强建议 |

### 8.2 出版备选

- **首选**:与国内科技/经管类出版社签约(机械工业、图灵、电子工业等)
- **备选 1**:电子版先在 shike.github.io 试水,积累读者后转纸版
- **备选 2**:与 WorkBuddy 官方合作,作为半官方教程(需明确利益声明)

### 8.3 进度风险

- 团队访谈与组织案例可能延期 → 第二卷第 7 章先以"虚拟团队"形式写,后续替换
- 配图赶不上写作进度 → 暂用文字描述占位,出版前统一补图
- 三卷统稿工作量超出预期 → 优先保证第一卷出版,二三卷分批交付
