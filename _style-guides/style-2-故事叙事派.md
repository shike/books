# 风格手册 2:故事叙事派(fde 用)

> **目标读者**:被派去客户的"前线工程师"(FDE、AI 工程师、解决方案架构师)
> **核心承诺**:从真实故事里提炼可复用的判断框架
> **章节范式**:`# 第 N 章｜主题` → `## 一个故事` → 故事叙事 → 章末金句
> **典型章节长度**:300-500 行,密度中等,情感强烈
> **代表章节**:fde/01-FDE 不是部署工程师.md(陈柏宇 2019 秋天) / 02-PoC 地狱.md

---

## 风格特征(6 条)

1. **故事开场** — 每章必须以"## 一个故事"开头,时间 + 地点 + 人物 + 任务四要素齐全
2. **真实感优先** — 具体到月份(2019 年秋)、公司类型(中型零售企业)、对话("老周把一台 Surface 推到他面前")
3. **短句节奏** — 段落简短,频繁换行;用一句话独立成段
4. **金句收束** — 章末必有 1-3 句"可被引用"的金句(单加粗、双下划线)
5. **时间线推进** — 故事按"第一周/第一个月/第二个月..."推进,不按主题分节
6. **抽象在故事后** — 故事讲完才出现"这个项目里没有人是骗子"等元判断

## 关键句式(7 个)

- "**XX 年,X 月,X 地,X 决定做 Y。**" — 开场
- "**X 看了 Y 一眼,没说话。**" — 人物特写
- "**第一个月 / 第一周 / 第 N 个月,X 发现 Y。**" — 时间线推进
- "**这件事没有人是 X。Y 没有 Z,W 没有 P。**" — 复盘归因
- "**每个人都在自己的职责范围内做了正确的事。**" — 戏剧张力
- "**但 X 从一开始就被设计成会失败的。**" — 反转
- "**这是 A 个问题。全世界都把它们当成一个。**" — 章末金句

## 禁忌(7 条)

- ❌ 不用"## 1.1 / ## 1.2"式编号分节(用 `## 一个故事` / `## 第二个故事` / `## 三个结论`)
- ❌ 不写抽象定义(用故事替代)
- ❌ 不出现"方法论"等学术词
- ❌ 不用"应该""必须"等命令式(用"X 没这么做"叙事替代)
- ❌ 不在章首列"学习目标"
- ❌ 不引用具体产品名(如 Kimi/Claude) — 用"某厂商"模糊化
- ❌ 不写"模型 Token 价格 X 元/M"等数字(用"贵但稳"等质性描述)

## 例子(选自 fde/02-PoC 地狱.md)

> 2022 年,一家医疗影像公司决定用 AI 帮放射科医生做肺结节筛查。
>
> PoC 做得非常漂亮。算法团队在三家合作医院的历史数据上训了一个检测模型,敏感度 96%,假阳性率控制在可接受范围。
>
> 第一个月:模型在县医院的数据上表现退化。敏感度从 96% 掉到 81%,假阳性率从 6% 飙升到 22%。
>
> 第六个月:项目叫停。
>
> 花掉的预算是 PoC 阶段的 14 倍。
>
> ---
>
> 每个人都在自己的职责范围内做了正确的事。
>
> 但这个项目从一开始就被设计成会失败的。
>
> **因为 PoC 的问题不是"技术做得好不好"。是 PoC 验证的东西和上线需要的东西,不是同一件事。**

## 风格检查项(7 条)

- [ ] 章首是否有"## 一个故事"或同义开场
- [ ] 故事是否包含"时间 + 地点 + 人物 + 任务"四要素
- [ ] 故事是否按时间线推进(第一周/第一个月/...)
- [ ] 是否有 1-3 句章末金句(加粗 + 短句)
- [ ] 段落中位数 ≤ 80 字(短句节奏)
- [ ] 全文是否只有 1 个"## 一个故事"或"## 第二个故事"分节
- [ ] 抽象方法论是否放在"故事讲完之后"才出现
