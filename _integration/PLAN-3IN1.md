## 方案 A · 图片方案

### A1. 目标

让 3 本书都"图文并茂":每章 2-4 张图,无冗余,质量统一,出版可用。

### A2. 图源 3 类

| 图源 | 工具 | 适用 | 占比预估 |
|---|---|---|---|
| **A 类:概念图 / 流程图 / 架构图 / 表格图** | `image_synthesize` 批生成 | 90% 章节配图 | 80% |
| **B 类:真实软件截图** | 用户提供 + 我用 image_synthesize 出"占位示意" | 5-10 张/本(关键操作演示) | 15% |
| **C 类:历史/案例现场** | 文字描述代替,或 image_synthesize 出"信息图" | 1-3 张/本 | 5% |

### A3. 质量标准(3 本书统一)

| 维度 | 标准 |
|---|---|
| 格式 | **统一 png**(出版社首选,不用 svg) |
| 分辨率 | **1400-2800 px 长边**(印刷标准) |
| 文件大小 | **200-500 KB/张**(GitHub + PDF 友好) |
| 命名 | `X.Y.Z-name.png`(与章节号对齐,如 `1.1.1-manager-time-allocation.png`) |
| 风格 | 同本书内部风格统一(色调 / 字体 / 留白),跨书可独立 |
| 信息密度 | 1 张图讲 1 件事(避免"图大字多") |
| 文字 | 中文(AI 生成时 prompt 明确) |

## 方案 B · 写作风格体系

### B1. 目标

**3 套可复用风格**,每本书选一套,**整本统一执行**,不再混搭。

### B2. 3 套风格(现成可用)

#### **风格 1:行业战略派**(ai-coding 当前风格)
- **适合**:行业分析、战略决策书、研究专著
- **特征**:
  - 章首"本章导读"段(讲清楚这章讲什么、不讲什么、目标读者、关键词)
  - 学术脚注风格(`[^1^][^7^]`)
  - 三级章节号(`# 第 N 章` / `## N.M` / `### N.M.K`)
  - 强调"分析框架"而非"操作步骤"
  - 引用权威报告(Gartner / McKinsey / IDC)
  - 章末"本章小结 + 思考题"(可加)
- **示例**:
  > **本章导读**:2026 年的 AI 编程产品市场,海外两家与国产三家已形成"模型 + 软件 + 套餐"三层绑定的销售结构。**本章关键词**:垂直闭环、模型档位、套餐机制。

#### **风格 2:故事叙事派**(fde 当前风格)
- **适合**:案例分析、人物访谈集、行业启示录
- **特征**:
  - 章首"## 一个故事"或"## 场景"
  - 人物对话驱动("陈柏宇说...老周说...")
  - 场景化描写(时间、地点、人物动作、心理)
  - 章节无编号(用 `## 小标题`)
  - 故事 → 反思 → 提炼 → 方法论(4 段式)
  - 章末"## 这个故事告诉我们"
- **示例**:
  > ## 一个故事
  > 2019 年秋天,陈柏宇坐在一家中型零售企业的会议室里,对面是 IT 总监老周。
  > 老周把一台 Surface 推到他面前,屏幕上是一份招标文件。"我们要上 AI 客服,"老周说,"预算批了,能做吗?"

#### **风格 3:实用操作派**(workbuddy 当前风格)
- **适合**:操作指南、培训交付件、实用手册
- **特征**:
  - 章首"本章学习目标"(1-5 条 bullet)
  - 表格密度高(步骤表 / 路由表 / 对照表 / 决策矩阵)
  - 即学即用(章末"明天你可以..." + "30 天路线图")
  - 强调"立刻上手"而非"理解原理"
  - 数字场景(具体公司、具体人、具体数字)
  - 三级章节号 + 大量表格
- **示例**:
  > **本章学习目标**
  > 1. 看清中层管理者每天面对的真实工作负荷...
  > 2. 理解云端 AI 工具为什么解决不了核心痛点...
  > 假设你是一名中层管理者——部门负责人、总监、VP……

### B3. 选配 2 套风格(备用,新书可选用)

#### **风格 4:学术综合派**(新书)
- **适合**:教材、研究专著、博士论文
- **特征**:GB/T 7714 引文、参考文献列表、章节末"小结 + 思考题 + 延伸阅读"

#### **风格 5:极简口语派**(短篇/演讲稿)
- **适合**:管理类短篇、实战手册、TED 演讲稿
- **特征**:短句为主(5-20 字)、段落 3-5 行、频繁用"你"、少用脚注

### B4. 3 本书风格选择(已和你确认)

| 书 | 风格 | 状态 |
|---|---|---|
| ai-coding | 风格 1(行业战略派) | ✅ 当前已是,只需做"风格执行手册"明确化 |
| fde | 风格 2(故事叙事派) | ✅ 当前已是 |
| workbuddy | 风格 3(实用操作派) | ✅ 当前已是 |

### B5. 风格执行手册(交付物)

**生成 1 份 `books/_style-guides/写作风格执行手册.md`**,包含:
- 5 套风格完整定义
- 每套的"模板 / 必含 / 禁用 / 推荐示例"
- "风格识别测试"(给一段文字,问它属于哪套)
- "风格混用检测"(检测混搭段落)
- 3 本书各用哪套的明确说明

**新书写作时,先选风格 → 按手册写 → 用风格检测脚本验证一致性**。

### B6. 风格一致性自动检测

写一个 Python 脚本 `books/scripts/style-consistency-checker.py`:
- 扫描一本 .md
- 检测:
  - 章首是否有"导读" / "学习目标" / "一个故事" 模板
  - 是否用了特定脚注风格
  - 是否在章末有"小结" / "明天你可以..." / "这个故事告诉我们"
  - 章节编号格式
- 输出:风格匹配度(%)+ 偏差清单

**总工作量**:**4-6 小时**(写手册 2-3h + 写脚本 2-3h)
